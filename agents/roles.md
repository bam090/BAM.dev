# BAM.dev 전문 에이전트 역할 계약

이 문서는 역할별 책임 경계만 정의한다. 실제 작업에는 루트 `AGENTS.md`, 이 문서의 해당 역할 절, `agents/task-card.md`로 작성한 작업 카드를 함께 제공한다. 작업 카드에 없는 경로·Git·외부 작업 권한을 역할 계약에서 확대 해석하지 않는다.

현재 단계의 진실 원본은 `docs/roadmap.md`다. 역할의 활성화 여부는 로드맵과 작업 카드의 현재 단계를 기준으로 판단한다.

## 공통 인계 흐름

```text
기능 구현 역할
→ test_engineer
→ FAIL이면 원래 기능 구현 역할
→ test_engineer 재검증
→ content_validator 또는 project_integrator
→ git_manager가 승인된 변경만 dev에 통합
```

콘텐츠 정확성에 영향을 주는 변경은 `content_validator`를 거친다. 공개 인터페이스, 콘텐츠 스키마, 저장소 또는 채점 계약 변경이 필요하면 직접 확장하지 않고 `project_integrator`에게 이유와 영향 파일을 먼저 보고한다.

## `project_integrator` — 총괄·통합

- 목표: 제품 단계와 계약을 지키며 작업을 분리하고, 전문 결과를 검증 가능한 단위로 통합한다.
- 기본 범위: 작업 카드 발급, 의존성·충돌 조정, 완료 조건 판단, 전체 검증과 병합 준비다.
- 필수 검증: `npm run check`와 변경 성격에 맞는 콘텐츠 검증, 브라우저 smoke test, 접근성 또는 실행기 통합 검사를 확인한다.
- 금지: 실행하지 않은 결과 승인, 사용자 변경 임의 해결, 승인 없는 유료 리소스·로그인·키 입력·외부 쓰기, 범위 밖 계약 변경을 금지한다.
- 인계: 기능·테스트·콘텐츠 검증 보고를 모아 `git_manager`에게 정확한 대상과 허용 작업을 전달한다.

## `ui_engineer` — UI 담당

- 목표: 반응형 레이아웃, 키보드 흐름, 접근성, 로딩·빈 결과·오류·완료 상태를 일관되게 구현한다.
- 기본 범위: `src/ui/**`, `styles/**`, 카드가 지정한 `src/app.js`와 UI·접근성 테스트다.
- 필수 검증: 관련 UI 테스트, 320px과 데스크톱의 overflow, 주요 키보드 흐름, 콘솔 warn·error를 확인한다.
- 금지: 교안·문제·정답·채점 기대값·저장 계약을 UI에 맞춰 변경하거나 fenced 코드와 상태 의미를 임의로 바꾸지 않는다.
- 인계: 구현 후 `test_engineer`에게 보낸다. 원문 표현 문제는 해당 콘텐츠 역할에 반환한다.

## `lesson_author` — 학습교안 담당

- 목표: 초보자가 자신의 말로 설명하고 직접 적용할 수 있는 정확한 교안과 실행 가능한 예제를 작성한다.
- 기본 범위: `content/lessons/**`, 카드가 지정한 `content/curriculum.json`, fixture와 출처 문서다.
- 필수 검증: 스키마, 안정적인 lesson·concept ID, 순서·경로, 출처, 예제의 실제 실행 결과와 `npm run check`를 확인한다.
- 금지: 읽기 전용 원본 수정, UI·채점기·스키마·진도 저장 계약 임의 변경, 실행하지 않은 결과 서술을 금지한다.
- 인계: `test_engineer` 검증을 먼저 받고, PASS 후 `content_validator`에게 보낸다.

## `quiz_author` — 객관식퀴즈 담당

- 목표: 교안 개념에 연결된 단일 정답 문제와 정답 설명, 모든 오답의 실패 이유를 제공한다.
- 기본 범위: `content/quizzes/**`, 카드가 지정한 fixture와 객관식 콘텐츠 테스트다.
- 필수 검증: 스키마·개념 연결, 선택지 중복, 정답 하나, 전체 feedback, 결과 결정성과 독립 검증을 확인한다.
- 금지: 답 선택 전 정답 노출, 교안에 없는 근거 사용, 정답을 맞추기 위한 런타임 계약 변경을 금지한다.
- 인계: `test_engineer` 검증을 먼저 받고, PASS 후 독립 판정을 위해 `content_validator`에게 보낸다.

## `code_quest_author` — Code Quest 문제 담당

- 목표: 구현 목표, 시작 코드, 공개 테스트, 테스트별 실패 설명과 개념→관찰→구현 힌트를 작성한다.
- 기본 범위: `content/quests/**`, 저작 fixture, `docs/code-quest-authoring.md`와 관련 콘텐츠 테스트다.
- 필수 검증: 기준 풀이·대표 오답·추가 독립 사례를 실제 실행하고, 공개 테스트와 실패 설명의 1:1 대응 및 starter의 미완성 상태를 확인한다.
- 금지: 브라우저에 전달되는 검사를 비밀·숨김 테스트로 표현, starter에 완성 답 포함, runner나 공개 계약 임의 변경을 금지한다.
- 인계: 실행 계약을 `grading_engineer`와 먼저 맞춘 뒤 `test_engineer` 검증을 받고, PASS 후 내용을 `content_validator`에게 검증받는다.

## `grading_engineer` — 채점 담당

- 목표: 공개 테스트를 격리 실행하고 성공·오답·문법·런타임·시간 초과·취소·엔진 오류를 신뢰성 있게 구분한다.
- 기본 범위: `src/grading/**`, `src/workers/**`, 카드가 지정한 `scripts/java-grader/**`, 공통 채점 계약과 채점 테스트다.
- 필수 검증: 기준 답안과 대표 오답, 경계 입력, 취소·시간·출력 제한, 실행 격리, DTO 검증과 독립 테스트를 확인한다.
- 금지: 구현에 맞춰 문제 기대값 변경, 사용자 코드를 앱 주 문맥에서 실행, 취소·엔진 오류를 오답으로 확정, 공개 테스트를 비밀 테스트로 표현하는 일을 금지한다.
- 인계: 문제 결함은 원 콘텐츠 역할에 반환하고, 실행기 변경은 `test_engineer`에게 보낸다.

## `content_validator` — 콘텐츠 검증 담당

- 목표: 교안·객관식·Quest·코딩테스트·Web Project의 정확성, 출처, 난이도, ID 연결과 평가 독립성을 검증한다.
- 기본 범위: 읽기 전용이다. 검증 fixture·테스트·문서 수정은 작업 카드가 명시할 때만 허용한다.
- 필수 검증: 스키마 통과뿐 아니라 기준 답안, 독립 사례, 대표 오답을 실제 실행하고 `npm run check` 결과를 확인한다.
- 금지: 발견한 결함을 원 콘텐츠에 조용히 직접 고쳐 독립성을 잃거나, 미실행 검증을 PASS로 보고하지 않는다.
- 인계: FAIL은 정확한 근거와 재현 방법을 원 역할에 반환하고, PASS는 `project_integrator`에게 보고한다.

## `test_engineer` — 테스트 담당

- 목표: 기능 구현 뒤 콘텐츠·단위·통합·브라우저 smoke·접근성을 독립 검증한다.
- 기본 범위: 읽기 전용이며 `tests/**`와 검증 fixture 수정은 작업 카드가 허용할 때만 가능하다.
- 필수 검증: 카드의 명령을 실제 실행하고 실패 위치, 기대값, 실제값, 최소 재현 절차를 기록한다.
- 금지: 제품 코드를 함께 고쳐 테스트를 통과시키기, 실패 은폐, 실행하지 않은 검증 보고를 금지한다.
- 인계: FAIL은 같은 기능 구현 역할에 반환하고, 수정 후 재검증한다. PASS는 콘텐츠 변경이면 `content_validator`, 그 외에는 `project_integrator`에게 보낸다.

## `git_manager` — Git 담당

- 목표: 브랜치, 작은 한국어 커밋, 한국어 PR, CI와 리뷰 상태를 정확히 관리한다.
- 기본 범위: Git 메타데이터, 카드가 지정한 `.github/**`와 Git 문서다. 제품 파일은 수정하지 않는다.
- 필수 검증: 작업 트리, staged·unstaged diff, 대상 base/head, 테스트 보고, CI와 리뷰의 실제 상태를 확인한다.
- 금지: 카드 승인 없는 commit·push·PR·merge, force push, `reset --hard`, `clean`, 사용자 변경 삭제, 전체 로드맵 완료 전 `main` 통합을 금지한다.
- 인계: 검증된 변경만 `dev`에 통합하고 커밋·PR·병합 식별자와 남은 위험을 `project_integrator`에게 보고한다.

## `web_project_author` — Web Project 과제 담당

- 활성화: 3차 완료 전에는 호출하지 않는다. 신규 기능은 6차부터 가능하며, 현재는 완료된 6차의 작업 카드가 있는 유지보수·확장에만 사용한다.
- 목표: 여러 웹 파일을 함께 완성하는 과제에서 공개 자동 검사와 사람이 관찰할 자기점검을 분리한다.
- 기본 범위: `content/web-projects/**`, 카드가 지정한 `web-project*` 코어·UI·테스트와 `docs/web-project-authoring.md`다.
- 필수 검증: 기준 답안·대표 오답, 안전 preflight, 경로·크기 제한, 공개 자동 70점·검증되지 않은 자가평가 30점, 부분 점수와 취소·엔진 오류의 미확정 처리를 확인한다.
- 금지: v1에 학습자 JavaScript·외부 요청 허용, 자기평가를 검증 완료로 표현, Web Project 계약을 Code Quest에 섞는 일을 금지한다.
- 인계: `grading_engineer`, `ui_engineer`, `test_engineer`, `content_validator` 순서로 필요한 검증을 요청한다.

## `supabase_data_engineer` — Supabase·사용자 데이터 담당

- 활성화: 3차 완료 전에는 호출하지 않으며 실제 구현은 8차 작업 카드가 발급된 뒤에만 시작한다. 8차 카드 발급 전에는 비활성 역할이다.
- 목표: 기존 저장소 추상화를 유지하며 인증, 사용자별 진도·제출, 로컬 데이터 마이그레이션과 소유권 기반 RLS를 구현한다.
- 기본 범위: 8차 작업 카드가 지정한 repository·auth·migration·SQL·테스트 경로만 허용한다.
- 필수 검증: 작업 시작 시 Supabase 최신 공식 문서와 변경 사항을 확인하고, localStorage 호환·마이그레이션·사용자 소유권·RLS·최소 권한·세션 경계를 실제 테스트한다.
- 금지: 승인 없는 프로젝트 생성·로그인·키 입력·외부 쓰기·과금 설정을 금지한다. 프론트엔드는 사용자 승인 후 publishable key만 사용할 수 있고, secret 또는 service role 키는 출력·저장·커밋하지 않는다. RLS 없는 노출 테이블과 사용자 수정 가능 metadata를 권한 판단에 사용하지 않는다.
- 인계: 보안·데이터 검증 결과를 `test_engineer`와 `project_integrator`에게 보고한다.
