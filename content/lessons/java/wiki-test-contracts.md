# 공개 계약에서 테스트 조건 찾기

## 학습 목표

입력·결과·예외·외부 변화에서 정상·경계·실패 조건을 골라 확인할 수 있습니다.

## 한줄 요약

테스트는 선택한 입력에서 호출자가 관찰할 약속을 확인하며 내부 구현이나 모든 경우의 무결함을 증명하지 않습니다.

## 먼저 확인할 개념

[메서드 계약](#/learn/java/wiki-methods) · [예외 처리와 전달](#/learn/java/wiki-exceptions) · [조합·위임과 생성자 주입](#/learn/java/wiki-composition-injection)를 먼저 확인하면 예제의 전제를 이해하기 쉽습니다.

## 한 번 실행해 본 것과 계속 확인하는 것은 다르다

계산기를 한 번 눌러 보고 맞았다고 생각해도 다른 숫자나 경계에서는 틀릴 수 있다.
코드를 고친 뒤 같은 확인을 사람이 매번 반복하면 빠뜨리거나 결과를 잘못 읽기도 한다.

자동화된 테스트는 정해 둔 입력으로 코드를 실행하고 관찰한 결과가 기대와 같은지 반복해서 확인하는 코드다.
좋은 테스트는 `어떤 구현 순서로 계산했는가`보다 `호출한 사람이 볼 수 있는 약속을 지켰는가`를 확인한다.

## 먼저 메서드의 공개된 약속을 적는다

공개된 메서드 계약(method contract)은 호출자가 알아야 하는 입력, 반환값, 발생할 수 있는 예외, 밖에서 관찰되는 변화를 말한다.
테스트 도구를 고르기 전에 이 계약에서 확인할 사실을 찾는다.

할인 계산기의 계약을 다음처럼 정할 수 있다.

- 원래 가격은 `0` 이상이다.
- 할인율은 `0`부터 `100`까지다.
- 유효한 값을 받으면 할인된 가격을 반환한다.
- 범위를 벗어난 값을 받으면 `IllegalArgumentException`을 던진다.

여기서 확인할 조건은 세 종류로 나눌 수 있다.

| 조건 | 확인하는 이유 | 할인 계산기 예 |
| --- | --- | --- |
| 정상 조건 | 평소 입력에서 핵심 계산이 맞는지 본다. | `10,000원`에 `20%`를 적용하면 `8,000원`이다. |
| 경계 조건 | 허용 범위가 바뀌는 가장자리를 본다. | 할인율 `0`과 `100`을 허용한다. |
| 예외 조건 | 거부해야 할 입력과 실패 방식이 맞는지 본다. | 할인율 `101`은 예외를 던진다. |

가능한 모든 숫자를 시험하는 것이 목표는 아니다.
계약의 서로 다른 규칙을 대표하는 값을 고르면 적은 테스트로도 무엇을 확인했는지 분명해진다.

## 준비하고 실행하고 검증한다

테스트 한 개는 준비(Arrange), 실행(Act), 검증(Assert)의 세 부분으로 읽을 수 있다.

```text
준비: 필요한 객체와 입력을 만든다.
실행: 확인할 메서드를 한 번 호출한다.
검증: 반환값·예외·외부 변화가 기대와 같은지 본다.
```

세 부분을 반드시 주석이나 별도 블록으로 나눌 필요는 없다.
짧은 테스트는 위에서 아래로 읽을 때 준비한 값, 실행 결과, 검증할 사실이 바로 보이면 충분하다.

## 계산 예제를 계약으로 읽기

아래 메서드는 클래스 안에 선언하는 Java 25 예제다. 가격은 0 이상, 할인율은 0부터 100까지라는 조건을 직접 검사한다.

```java
final class DiscountCalculator {
    int finalPrice(int price, int discountPercent) {
        if (price < 0 || discountPercent < 0 || discountPercent > 100) {
            throw new IllegalArgumentException("가격과 할인율을 확인해 주세요.");
        }
        int discount = (int) ((long) price * discountPercent / 100);
        return price - discount;
    }
}
```

int끼리 곱한 뒤 long에 담지 않고, 곱하기 전에 long으로 넓혀 중간 오버플로를 피한다.
10,000원에 20%는 8,000원, 0%는 원래 가격, 100%는 0원이 되는지 확인한다.
101%나 음수 가격은 반환값 대신 약속한 예외를 확인한다.
private helper를 나누거나 계산 순서를 정리해도 공개된 값·예외·외부 변화가 같으면 그 계약을 계속 검증한다.


## 입력에서 검증까지 이어서 보기

지금까지 배운 내용은 서로 떨어진 문법 목록이 아니다.
한 기능을 만들고 확인하는 순서에서 각 장의 역할이 이어진다.

| 흐름 | 앞 장에서 사용하는 내용 | 확인할 질문 |
| --- | --- | --- |
| 입력을 받는다. | 타입·변수·배열·문자열 | 어떤 값이 들어오며 허용 범위는 어디까지인가? |
| 판단과 계산을 나눈다. | 조건·반복·메서드 | 어느 계산을 이름 있는 메서드로 분리할 것인가? |
| 상태와 책임을 묶는다. | 클래스·캡슐화·`static`·`final` | 어떤 객체가 값을 지키고 바꾸어야 하는가? |
| 구현을 연결한다. | 상속·인터페이스·제네릭·컬렉션 | 역할과 저장 조건에 맞는 타입은 무엇인가? |
| 실패와 변환을 다룬다. | 예외·자원·람다·Stream·시간 | 실패를 어디까지 전달하고 값을 어떤 단계로 처리할 것인가? |
| 여러 작업을 안전하게 잇는다. | executor·happens-before·공유 상태 | 어떤 값을 공유하며 결과가 보이는 시점은 언제인가? |
| 계약을 다시 확인한다. | 테스트 | 호출자가 관찰할 정상·경계·예외 결과는 무엇인가? |

새 기능을 만났을 때 문법 이름부터 고르기보다 입력, 상태, 판단, 출력과 외부 협력 경계를 먼저 그린다.
그 뒤 필요한 Java 도구를 고르면 문법이 기능의 이유와 연결된다.

## 테스트가 통과해도 확인은 계속된다

작성한 테스트는 선택한 조건에서 관찰한 결과를 확인한다.
모든 입력과 실행 환경을 확인한 것이 아니므로 테스트 통과가 결함이 전혀 없음을 증명하지는 않는다.

경계값을 빠뜨렸는지, 예외가 원래 원인을 숨기지 않는지, 동시 실행에서 별도 위험이 있는지 계속 살핀다.
테스트는 생각을 대신하는 보증서가 아니라 정한 약속이 다시 깨졌는지 빠르게 알려 주는 안전망이다.
