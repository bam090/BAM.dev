# 상속과 실제 객체의 메서드

## 학습 목표

선언 타입의 사용 가능 멤버와 실제 객체의 오버라이딩 메서드를 구분할 수 있습니다.

## 한줄 요약

상속은 타입 관계를 만들며 재정의한 인스턴스 메서드는 실제 객체에 따라 선택됩니다.

## 선언 타입과 실제 객체를 나누어 읽는다

상위 타입 변수는 그 타입으로 사용할 수 있는 멤버를 정하고 재정의 가능한 인스턴스 메서드는 실제 객체에 맞는 구현이 실행된다.
필드와 static 메서드는 이런 인스턴스 메서드의 동적 선택과 같지 않다.
오버라이딩은 물려받은 메서드 구현을 바꾸는 것이고 오버로딩은 받을 수 있는 매개변수 구성을 늘리는 것이다.

```java
class LearningItem {
    String kind() {
        return "기본";
    }
}

class VideoLesson extends LearningItem {
    @Override
    String kind() {
        return "영상";
    }
}
```

`LearningItem item = new VideoLesson();` 뒤 `item.kind()`를 호출하는 흐름을 읽어 보자.
선언 타입이 LearningItem이어도 실제 객체가 구현한 kind가 선택된다.
상위 타입으로 바라본다고 객체가 잘리거나 다른 객체로 변하는 것은 아니다.

## 상속에 포함되지 않는 것

일반 클래스는 직접 상위 클래스를 하나만 지정한다.
상위 클래스의 private 멤버를 하위 코드에서 직접 사용할 수 없고 생성자도 상속되지 않는다.
상위 클래스에 접근 가능한 인수 없는 생성자가 없다면 하위 생성자는 알맞은 super(...)를 호출해야 한다.

오버라이딩에는 매개변수·반환 타입·접근 수준·예외의 호환 규칙이 있다.
상위 메서드보다 접근 범위를 좁히거나 final 메서드를 재정의할 수 없다.
@Override는 재정의를 만드는 마법이 아니라 실제 재정의가 맞는지 컴파일러가 검사하게 하는 표시다.
코드 재사용만 보지 말고 하위 객체가 상위 타입의 약속을 지키는 한 종류인지 판단한다.

## 핵심 질문 답

컴파일 때는 선언 타입의 멤버 계약을 확인하고 재정의한 인스턴스 메서드는 실제 객체의 구현을 실행합니다.
필드와 static 메서드의 선택을 이 동적 메서드 선택과 같게 보지 않습니다.
상속은 의미 있는 타입 관계여야 하며 생성자 초기화와 접근·반환·예외의 호환 규칙도 지켜야 합니다.
