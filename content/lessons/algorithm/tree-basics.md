# 09. 트리

## 학습 목표

- 트리의 노드·간선·루트·부모·자식·리프를 설명할 수 있습니다.
- 노드의 깊이와 트리의 높이를 간선 수 기준으로 구할 수 있습니다.
- 전위 순회와 레벨 순회의 방문 순서를 추적할 수 있습니다.
- 재귀 스택과 큐를 사용한 트리 순회의 차이를 설명할 수 있습니다.

## 왜 필요한가

모든 데이터가 일렬로 이어지지는 않습니다.
폴더 안에 다른 폴더가 있고, 메뉴 아래에 하위 메뉴가 있으며, 하나의 선택에서 여러 다음 선택으로 갈라지기도 합니다.
이런 부모·자식 관계를 표현하고 전체를 빠뜨리지 않고 살펴볼 때 트리를 사용합니다.

트리는 그래프의 한 종류이지만 시작점인 루트를 정하면 위에서 아래로 관계를 읽기 쉽습니다.
구조를 먼저 이해하면 재귀, DFS와 BFS가 왜 트리 순회에 사용되는지도 자연스럽게 연결됩니다.

## 개념 연결

- 선행: `algo.graph-representation`, `algo.bfs`, `algo.dfs`, `algo.stack`, `algo.queue`에서 배운 연결 관계와 탐색 순서를 사용합니다.
- 이 단원: `algo.tree`, `algo.tree-traversal`로 계층 구조와 노드 방문 순서를 익힙니다.
- 후속: `algo.heap`, `algo.priority-queue`, `algo.dynamic-programming-advanced`에서 트리의 순서 규칙과 하위 구조의 답을 재사용하는 방법으로 이어집니다.

## 트리란?

**트리**는 무방향 그래프로 볼 때 모든 노드가 연결되어 있고 순환이 없는 구조입니다.
순환이 없다는 것은 간선을 따라 이동하다가 같은 경로를 빙 돌아 출발점으로 돌아오는 고리가 없다는 뜻입니다.
두 노드 사이에는 하나의 단순 경로만 존재합니다.

트리에서 한 노드를 **루트**로 정하면 관계를 위에서 아래로 설명할 수 있습니다.

- **노드**: 값을 담는 한 지점입니다.
- **간선**: 두 노드의 연결입니다.
- **루트**: 트리의 시작으로 정한 노드이며 부모가 없습니다.
- **부모와 자식**: 루트에서 아래로 내려갈 때 바로 위 노드와 바로 아래 노드의 관계입니다.
- **리프**: 자식이 없는 노드입니다.
- **서브트리**: 어떤 노드와 그 아래의 모든 자손으로 이루어진 작은 트리입니다.

루트를 정하지 않은 트리에는 본래 위와 아래가 없습니다.
루트를 정한 뒤에야 부모, 자식과 깊이를 말할 수 있습니다.

## 깊이와 높이

이 교안에서는 거리를 **간선 수**로 셉니다.

- 노드의 **깊이**는 루트에서 그 노드까지 지나가는 간선 수입니다.
- 트리의 **높이**는 루트에서 가장 깊은 리프까지의 간선 수입니다.

따라서 루트의 깊이는 `0`입니다.
루트만 있는 트리의 높이도 `0`입니다.
자료에 따라 노드 수로 높이를 세는 경우도 있으므로 문제나 문서가 사용하는 기준을 먼저 확인해야 합니다.

## 일반 트리와 이진 트리 구분하기

일반 트리의 노드는 여러 자식을 가질 수 있습니다.
**이진 트리**는 각 노드가 최대 두 자식, 즉 왼쪽 자식과 오른쪽 자식을 갖는 트리입니다.

이진 트리라고 해서 자동으로 이진 탐색 트리이거나 힙인 것은 아닙니다.
이진 탐색 트리는 키의 순서 규칙이 더 필요하고, 힙은 부모와 자식 사이의 우선순위 규칙이 더 필요합니다.

## 트리 순회

**순회**는 정해진 규칙으로 모든 노드를 한 번씩 방문하는 과정입니다.
이 교안에서는 일반 트리에도 적용할 수 있는 두 순서를 비교합니다.

### 전위 순회

전위 순회는 현재 노드를 먼저 방문한 뒤 자식 서브트리를 왼쪽부터 차례대로 방문합니다.
깊은 곳으로 내려갔다가 이전 호출로 돌아오므로 DFS와 같은 깊이 우선 흐름입니다.

### 레벨 순회

레벨 순회는 루트부터 깊이가 같은 노드를 차례대로 방문합니다.
먼저 발견한 노드를 먼저 처리해야 하므로 큐를 사용하는 BFS 흐름입니다.

## 최소 예제

다음 트리는 `A`가 루트이고, `A`의 자식은 `B`, `C`, `B`의 자식은 `D`, `E`입니다.

```javascript
const tree = {
  value: "A",
  children: [
    {
      value: "B",
      children: [
        { value: "D", children: [] },
        { value: "E", children: [] },
      ],
    },
    { value: "C", children: [] },
  ],
};

function preorder(node, result = []) {
  result.push(node.value);

  for (const child of node.children) {
    preorder(child, result);
  }

  return result;
}

function levelOrder(root) {
  const result = [];
  const queue = [root];
  let head = 0;

  while (head < queue.length) {
    const node = queue[head];
    head += 1;
    result.push(node.value);

    for (const child of node.children) {
      queue.push(child);
    }
  }

  return result;
}

console.log(preorder(tree)); // [ 'A', 'B', 'D', 'E', 'C' ]
console.log(levelOrder(tree)); // [ 'A', 'B', 'C', 'D', 'E' ]
```

두 함수 모두 모든 노드를 한 번씩 방문하므로 노드가 `n`개일 때 방문 작업은 `O(n)`입니다.
트리 높이가 `h`일 때 전위 순회의 재귀 호출 추가 공간은 `O(h)`입니다.
JavaScript 실행 환경의 호출 스택 한도를 넘을 만큼 깊은 트리라면 재귀 대신 명시적 스택과 반복문을 사용해야 합니다.
레벨 순회 예제는 처리한 노드를 `queue` 배열에서 제거하지 않으므로 큐 배열의 추가 공간은 `O(n)`입니다.
처리한 앞부분을 회수하는 별도 큐 구현에서는 실제 대기 중인 노드 수, 즉 트리의 최대 너비가 공간 사용량을 결정합니다.

## 단계별 실행 흐름

### 전위 순회

1. 루트 `A`를 결과에 넣습니다.
2. 첫 자식 `B`를 방문합니다.
3. `B`의 첫 자식 `D`를 방문합니다. `D`는 자식이 없어 돌아옵니다.
4. `B`의 다음 자식 `E`를 방문한 뒤 `A`로 돌아옵니다.
5. `A`의 다음 자식 `C`를 방문합니다.
6. 결과는 `A, B, D, E, C`입니다.

### 레벨 순회

| 단계 | 꺼낸 노드 | 뒤에 추가한 자식 | 결과 |
| --- | --- | --- | --- |
| 1 | A | B, C | A |
| 2 | B | D, E | A, B |
| 3 | C | 없음 | A, B, C |
| 4 | D | 없음 | A, B, C, D |
| 5 | E | 없음 | A, B, C, D, E |

큐의 앞에서 발견 순서대로 읽기 때문에 깊이 `0`의 `A`, 깊이 `1`의 `B`, `C`, 깊이 `2`의 `D`, `E` 순서가 됩니다.

## 흔한 실수

### 1. 루트와 리프를 같은 뜻으로 사용하기

루트는 시작으로 정한 노드이고, 리프는 자식이 없는 노드입니다.
루트 하나만 있는 트리에서는 한 노드가 두 역할을 모두 가질 수 있지만 뜻은 다릅니다.

### 2. 깊이와 높이의 기준을 확인하지 않기

이 교안은 간선 수를 사용합니다.
다른 자료가 노드 수를 사용하면 결과가 `1`만큼 달라질 수 있으므로 기준을 먼저 확인합니다.

### 3. 이진 트리를 정렬된 트리라고 생각하기

자식이 최대 두 개라는 조건만으로 값의 크기 순서는 정해지지 않습니다.
이진 탐색 트리나 힙에는 별도의 규칙이 필요합니다.

### 4. 전위 순회에서 자식보다 현재 노드를 늦게 처리하기

전위 순회는 현재 노드를 먼저 처리합니다.
처리 위치를 재귀 호출 뒤로 옮기면 다른 순회가 됩니다.

### 5. 레벨 순회에서 스택을 사용하기

스택은 최근에 넣은 노드를 먼저 꺼내므로 깊이 우선 흐름이 됩니다.
같은 깊이를 발견 순서대로 처리하려면 큐를 사용합니다.

### 6. 부모 방향까지 따라가면서 방문 관리를 생략하기

예제는 자식 방향만 저장해 루트에서 아래로 이동합니다.
부모와 자식을 모두 인접 관계로 저장하면 되돌아가는 간선이 있으므로 이전 노드를 제외하거나 방문 여부를 기록해야 합니다.

## 면접 답변 예시

### 답변 1

부모가 없는 시작 노드는 루트이고, 자식이 없는 노드는 리프입니다. 루트 하나만 있는 트리에서는 그 노드가 루트이면서 리프일 수 있습니다.

### 답변 2

깊이와 높이를 간선 수로 세면 루트까지 이동하는 간선이 없으므로 루트의 깊이는 `0`입니다. 루트만 있는 트리도 가장 깊은 리프까지 간선이 없으므로 높이가 `0`입니다.

### 답변 3

전위 순회는 현재 노드를 처리한 뒤 한 자식의 서브트리를 끝까지 방문하는 깊이 우선 방식입니다. 레벨 순회는 큐에 먼저 들어온 노드를 먼저 꺼내 같은 깊이의 노드를 순서대로 방문하므로 결과가 다릅니다.

### 답변 4

이진 트리는 각 노드가 최대 두 자식을 가진다는 구조만 정합니다. 이진 탐색 트리는 왼쪽과 오른쪽 키의 순서 규칙이 추가되고, 힙은 부모와 자식의 우선순위 규칙이 추가되므로 모든 이진 트리가 두 구조에 해당하지는 않습니다.
