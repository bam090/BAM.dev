# 집합: 유니온 파인드로 그룹 합치기

## 학습 목표

- 부모 배열에서 find로 대표를 찾고 union으로 두 그룹을 합치는 과정을 따라갈 수 있습니다.
- 경로 압축과 크기 기준 합치기가 find를 빠르게 만드는 이유를 설명하고 연결 요소 수 세기와 사이클 판별에 유니온 파인드를 쓸 수 있습니다.

## 한줄 요약

유니온 파인드는 원소마다 부모를 적어 둔 배열로 그룹을 표현하고 대표를 찾는 find와 두 그룹을 잇는 union으로 두 원소가 같은 그룹인지 빠르게 답합니다.

## 분리 집합이란

**분리 집합**은 원소들을 서로 겹치지 않는 여러 그룹으로 나눠 두고 두 원소가 같은 그룹인지 빠르게 확인하는 자료구조입니다.
여기서 **집합**은 원소를 모은 묶음이고 **분리**는 한 원소가 두 묶음에 동시에 들어가지 않는다는 뜻입니다.
해시 문서에서 본 `HashSet`은 값 하나하나를 중복 없이 담는 모음 하나였습니다.
반면 분리 집합은 모음 여러 개를 나란히 두고 필요할 때 두 모음을 하나로 합칩니다.

이런 자료구조가 필요한 이유는 연결이 하나씩 늘어나는 문제가 많기 때문입니다.
친구 관계가 새로 생기거나 컴퓨터를 케이블로 하나 더 이을 때마다 누가 누구와 이어져 있는지 다시 확인해야 합니다.
연결이 생길 때마다 전체를 처음부터 탐색하면 느립니다.
그래서 그룹을 합치는 일과 같은 그룹인지 묻는 일만 빠르게 해내는 구조를 따로 둡니다.

예를 들어 바다에 섬 6개가 있고 섬 사이에 다리를 하나씩 놓는다고 생각해 보세요.
다리로 이어진 섬끼리는 걸어서 오갈 수 있으니 같은 그룹입니다.
직접 다리가 없어도 다른 섬을 거쳐 닿을 수 있으면 역시 같은 그룹입니다.

이 문서는 아래 섬 6개를 처음부터 끝까지 사용합니다.

![섬 0부터 5까지 6개가 있고 0-1 · 1-2 · 3-4에 다리가 놓여 있다. 그래서 섬들이 그룹 {0, 1, 2} · 그룹 {3, 4} · 그룹 {5}의 세 그룹으로 나뉘어 색이 다른 배경으로 묶여 있다.](content/assets/algorithm/uf-islands.png)

섬 `0`과 `2` 사이에는 다리가 없지만 `1`을 거쳐 갈 수 있으므로 같은 그룹입니다.
섬 `5`는 아직 어떤 다리도 없어서 혼자 한 그룹을 이룹니다.
이렇게 어느 섬도 두 그룹에 동시에 속하지 않으니 이 섬들은 분리 집합입니다.

## 유니온 파인드의 두 연산

분리 집합을 다루는 방법 중 코딩테스트에서 가장 많이 쓰는 것이 **유니온 파인드**입니다.
이름 그대로 두 가지 연산만 제공합니다.

| 연산 | 하는 일 | 섬 예제에서 |
| --- | --- | --- |
| `find(x)` | `x`가 속한 그룹의 대표를 찾습니다 | 섬 `2`가 속한 그룹의 대표 섬 찾기 |
| `union(a, b)` | `a`의 그룹과 `b`의 그룹을 하나로 합칩니다 | 섬 `2`와 섬 `4` 사이에 다리 놓기 |

**대표**는 그룹마다 하나씩 정해 둔 원소입니다.
두 섬의 대표가 같으면 같은 그룹이고 다르면 다른 그룹입니다.
그래서 "두 섬이 이어져 있나요?"라는 질문은 `find(a) == find(b)` 한 줄로 바뀝니다.

그렇다면 대표는 어떻게 기억해 둘까요?
유니온 파인드는 트리를 이용합니다.

## 부모 배열로 표현

유니온 파인드는 그룹 하나를 트리 하나로 보고 각 원소의 부모를 배열 `parent`에 적어 둡니다.
트리 문서에서는 부모가 자식을 가리켰지만 여기서는 반대로 자식이 부모를 가리킵니다.
위로만 올라가면 되기 때문에 부모 번호 하나만 알면 충분합니다.

트리의 루트가 곧 그룹의 대표입니다.
루트는 더 올라갈 곳이 없으므로 자기 자신을 부모로 적습니다.

![섬 1과 2는 화살표로 0을 가리키고 섬 4는 3을 가리키며 섬 5는 자기 자신을 가리킨다. 0 · 3 · 5가 초록색 대표로 표시되어 있다. 아래에 번호 0부터 5까지의 parent 배열 0 · 0 · 0 · 3 · 3 · 5가 있고 대표 칸이 초록색이다.](content/assets/algorithm/uf-parent-array.png)

그림 아래의 배열을 읽어 보면 `parent[2]`는 `0`이고 `parent[4]`는 `3`입니다.
`parent[0]`·`parent[3]`·`parent[5]`는 자기 번호와 같으니 세 섬이 각 그룹의 대표입니다.

### find: 대표 찾기

`find(x)`는 `parent`를 따라 위로 올라가다가 자기 자신을 가리키는 칸에서 멈춥니다.

```java
static int find(int x) {
    if (parent[x] == x) return x;
    return find(parent[x]);
}
```

`parent[x] == x`이면 `x`가 루트이므로 바로 돌려줍니다.
아니면 부모에게 같은 질문을 넘깁니다.
`find(2)`는 `parent[2]`인 `0`으로 올라가고 `0`은 자기 자신을 가리키니 `0`을 돌려줍니다.

### union: 두 그룹 합치기

`union(a, b)`는 두 원소의 대표를 먼저 찾고 한쪽 대표를 다른 쪽 대표 아래에 붙입니다.

```java
static void union(int a, int b) {
    int rootA = find(a);
    int rootB = find(b);
    if (rootA != rootB) parent[rootB] = rootA;
}
```

여기서 `a`와 `b` 자체가 아니라 두 대표를 잇는다는 점이 중요합니다.
`parent[b] = a`처럼 원소를 바로 이으면 `b`가 원래 부모와의 연결을 잃고 `b` 위에 있던 대표와 나머지 원소들은 원래 그룹에 그대로 남기 때문입니다.
예를 들어 곧 볼 `union(2, 4)`에서 `parent[4] = 2`로 적으면 섬 `4`만 옮겨 가고 대표 `3`은 따로 떨어져 남습니다.
대표끼리 이어야 그룹 전체가 한꺼번에 합쳐집니다.

이제 섬 `2`와 섬 `4` 사이에 다리를 놓아 보겠습니다.

![왼쪽은 union(2, 4) 전으로 find(2)는 0이고 find(4)는 3이라 대표가 다르다. 오른쪽은 union(2, 4) 뒤로 대표 3이 대표 0 아래로 들어가 0 아래에 1 · 2 · 3이 있고 3 아래에 4가 있다. parent 배열은 0 · 0 · 0 · 3 · 3 · 5에서 0 · 0 · 0 · 0 · 3 · 5로 바뀐다.](content/assets/algorithm/uf-union.png)

`find(2)`는 `0`이고 `find(4)`는 `3`이라 대표가 다릅니다.
그래서 `parent[3] = 0`으로 대표 `3`을 대표 `0` 아래에 붙입니다.
`parent[4]`는 여전히 `3`이지만 `3`을 거쳐 `0`까지 올라가므로 섬 `4`도 이제 `0`의 그룹입니다.

다리를 놓기 전과 뒤에 두 섬이 같은 그룹인지 코드로 확인해 보겠습니다.
실행하기 전에 각 줄에 무엇이 찍힐지 먼저 예상해 보세요.

```java
union(0, 1);
union(1, 2);
union(3, 4);
System.out.println("다리 3개 뒤: " + Arrays.toString(parent));
System.out.println("0과 2: " + (find(0) == find(2)));
System.out.println("2와 4: " + (find(2) == find(4)));

union(2, 4);
System.out.println("2-4 다리 뒤: " + Arrays.toString(parent));
System.out.println("2와 4: " + (find(2) == find(4)));
```

```text
다리 3개 뒤: [0, 0, 0, 3, 3, 5]
0과 2: true
2와 4: false
2-4 다리 뒤: [0, 0, 0, 0, 3, 5]
2와 4: true
```

섬 `0`과 `2`는 직접 다리가 없어도 대표가 `0`으로 같아서 `true`입니다.
섬 `2`와 `4`는 처음에는 대표가 달라 `false`였다가 다리를 놓은 뒤 `true`가 됩니다.
배열에서 바뀐 칸은 대표 `3`의 부모를 적은 `parent[3]` 하나뿐입니다.

## 경로 압축과 크기 기준 합치기

그런데 다리를 놓는 순서에 따라 트리가 한 줄로 길게 늘어질 수 있습니다.
예를 들어 `union(4, 5)`·`union(3, 4)`·`union(2, 3)`·`union(1, 2)`·`union(0, 1)` 순서로 다리를 놓으면 `5 → 4 → 3 → 2 → 1 → 0`처럼 사슬이 생깁니다.
그러면 `find(5)`는 대표에 닿을 때까지 칸을 여섯 개나 지나야 합니다.
섬이 10만 개라면 `find` 한 번에 10만 칸을 올라갈 수도 있습니다.

이 문제를 푸는 방법이 두 가지 있습니다.

### 경로 압축

**경로 압축**은 `find`가 올라가며 지나간 칸이 모두 대표를 바로 가리키도록 부모를 고쳐 두는 방법입니다.
한 번 긴 길을 올라갔다면 다음에는 그 길을 다시 걷지 않게 지름길을 만들어 두는 것입니다.

![왼쪽은 5가 4를 · 4가 3을 가리키는 식으로 0까지 이어진 긴 사슬이고 find(5)는 6칸을 지나 대표 0에 닿는다. 오른쪽은 find(5)를 한 번 한 뒤 1부터 5까지 모두 0을 바로 가리키는 모습이고 다음 find(5)는 2칸 만에 끝난다.](content/assets/algorithm/uf-path-compression.png)

코드는 `find`에서 한 줄만 바꾸면 됩니다.

```java
static int findWithCompression(int x) {
    if (parent[x] == x) return x;
    parent[x] = findWithCompression(parent[x]);
    return parent[x];
}
```

재귀가 대표를 찾아 돌아오는 길에 `parent[x]`를 그 대표로 덮어씁니다.
그래서 사슬 위의 모든 칸이 대표 `0`을 바로 가리키게 됩니다.

사슬에서 `find(5)`로 한 번 올라가 본 뒤 `findWithCompression(5)`로 압축하고 다시 부르면 지나는 칸 수가 어떻게 달라질지 예상해 보세요.

```text
사슬: [0, 0, 1, 2, 3, 4]
find(5) 방문 칸 수: 6
압축 뒤: [0, 0, 0, 0, 0, 0]
다시 find(5) 방문 칸 수: 2
```

처음에는 `5`부터 `0`까지 여섯 칸을 모두 지납니다.
압축한 뒤에는 `5`에서 바로 `0`으로 가니 두 칸이면 끝납니다.

### 크기 기준 합치기

두 번째 방법은 합칠 때 어느 쪽을 아래에 붙일지 정하는 것입니다.
**크기 기준 합치기**는 원소가 적은 그룹의 대표를 원소가 많은 그룹의 대표 아래에 붙입니다.

![왼쪽은 크기 3인 그룹의 대표 0을 크기 1인 3 아래에 붙여 높이가 2가 되고 1과 2가 한 칸 더 멀어진 모습이다. 오른쪽은 크기 1인 3을 크기 3인 그룹의 대표 0 아래에 붙여 높이가 1 그대로인 모습이다.](content/assets/algorithm/uf-union-by-size.png)

큰 그룹을 아래에 붙이면 그 안의 많은 원소가 모두 한 칸씩 대표에서 멀어집니다.
작은 그룹을 아래에 붙이면 멀어지는 원소가 적습니다.
그래서 크기를 기준으로 합치면 트리가 한쪽으로 길게 자라지 않습니다.
크기 대신 트리의 높이를 기준으로 삼는 방법도 있는데 이를 **랭크 기준 합치기**라고 부르며 효과는 비슷합니다.

두 방법을 함께 쓰면 `find`와 `union` 한 번은 사실상 상수 시간에 가깝게 끝납니다.
그룹마다 크기를 적어 두는 `size` 배열 구현은 [Java로 유니온 파인드 구현하기](#/learn/algorithm/union-find-java)에서 알아봅니다.

> [!note]- 전체 코드 보기
> 이 문서의 예제를 하나로 합친 프로그램입니다.
> `IslandBridges.java`로 저장해 실행해 볼 수 있습니다.
>
> ```java
> import java.util.Arrays;
>
> public class IslandBridges {
>     static int[] parent = new int[6];
>     static int steps;
>
>     static void reset() {
>         for (int i = 0; i < parent.length; i++) {
>             parent[i] = i;
>         }
>     }
>
>     static int find(int x) {
>         steps++;
>         if (parent[x] == x) return x;
>         return find(parent[x]);
>     }
>
>     static int findWithCompression(int x) {
>         steps++;
>         if (parent[x] == x) return x;
>         parent[x] = findWithCompression(parent[x]);
>         return parent[x];
>     }
>
>     static void union(int a, int b) {
>         int rootA = find(a);
>         int rootB = find(b);
>         if (rootA != rootB) parent[rootB] = rootA;
>     }
>
>     public static void main(String[] args) {
>         reset();
>         System.out.println("처음: " + Arrays.toString(parent));
>
>         union(0, 1);
>         union(1, 2);
>         union(3, 4);
>         System.out.println("다리 3개 뒤: " + Arrays.toString(parent));
>         System.out.println("0과 2: " + (find(0) == find(2)));
>         System.out.println("2와 4: " + (find(2) == find(4)));
>
>         union(2, 4);
>         System.out.println("2-4 다리 뒤: " + Arrays.toString(parent));
>         System.out.println("2와 4: " + (find(2) == find(4)));
>
>         reset();
>         union(4, 5);
>         union(3, 4);
>         union(2, 3);
>         union(1, 2);
>         union(0, 1);
>         System.out.println("사슬: " + Arrays.toString(parent));
>
>         steps = 0;
>         find(5);
>         System.out.println("find(5) 방문 칸 수: " + steps);
>
>         steps = 0;
>         findWithCompression(5);
>         System.out.println("압축 뒤: " + Arrays.toString(parent));
>
>         steps = 0;
>         findWithCompression(5);
>         System.out.println("다시 find(5) 방문 칸 수: " + steps);
>     }
> }
> ```
>
> ```text
> 처음: [0, 1, 2, 3, 4, 5]
> 다리 3개 뒤: [0, 0, 0, 3, 3, 5]
> 0과 2: true
> 2와 4: false
> 2-4 다리 뒤: [0, 0, 0, 0, 3, 5]
> 2와 4: true
> 사슬: [0, 0, 1, 2, 3, 4]
> find(5) 방문 칸 수: 6
> 압축 뒤: [0, 0, 0, 0, 0, 0]
> 다시 find(5) 방문 칸 수: 2
> ```

## 유니온 파인드의 활용

그렇다면 코딩테스트에서는 유니온 파인드를 어디에 쓸까요?
대표적인 쓰임은 연결 요소 수 세기와 사이클 판별입니다.

### 연결 요소 수 세기

**연결 요소**는 서로 이어진 원소끼리 묶은 그룹 하나를 말합니다.
섬 예제에서는 다리 3개를 놓은 뒤 연결 요소가 `{0, 1, 2}`·`{3, 4}`·`{5}`로 3개였습니다.

세는 방법은 간단합니다.
처음에는 원소 수만큼 그룹이 있다고 두고 `union`이 서로 다른 두 그룹을 실제로 합칠 때마다 하나씩 뺍니다.
섬 6개에서 다리 3개가 모두 다른 그룹을 이었으니 `6 - 3 = 3`입니다.
같은 그룹 안의 두 섬에 다리를 또 놓으면 그룹 수는 줄지 않습니다.

### 사이클 판별

다리를 하나씩 놓다 보면 출발한 섬으로 다시 돌아오는 길인 **사이클**이 생길 수 있습니다.
유니온 파인드로는 다리를 놓기 직전에 두 섬의 대표를 비교해서 사이클이 생기는 순간을 찾습니다.

![섬 0 · 1 · 2가 다리 0-1과 1-2로 한 그룹이 되어 있고 새 다리 2-0이 빨간 점선으로 그려져 있다. 오른쪽 설명은 새 다리를 놓기 전에 find(2)와 find(0)이 모두 0이라 이미 같은 그룹이고 이으면 0 → 1 → 2 → 0 사이클이 생긴다고 적혀 있다.](content/assets/algorithm/uf-cycle.png)

섬 `0`·`1`·`2`는 이미 다리 두 개로 이어져 있습니다.
여기에 다리 `2-0`을 놓기 전에 `find(2)`와 `find(0)`을 비교하면 둘 다 `0`입니다.
이미 이어진 두 섬을 또 이으면 `0 → 1 → 2 → 0`으로 한 바퀴 도는 길이 생기기 때문에 이 다리가 사이클을 만드는 간선입니다.

두 쓰임 모두 BFS·DFS로도 풀 수 있습니다.
차이는 연결이 늘어나는 도중에 질문이 계속 들어오는지에 있습니다.

| 상황 | 잘 맞는 방법 | 이유 |
| --- | --- | --- |
| 연결이 모두 주어진 뒤 한 번만 묻습니다 | BFS·DFS 또는 유니온 파인드 | 한 번 탐색하면 끝납니다 |
| 연결을 하나씩 추가하며 그때마다 묻습니다 | 유니온 파인드 | 탐색을 다시 하지 않고 대표만 비교합니다 |
| 최단 거리나 방문 순서가 필요합니다 | BFS·DFS | 유니온 파인드는 같은 그룹인지만 압니다 |

비용이 작은 다리부터 하나씩 고르며 사이클을 만드는 다리를 건너뛰는 최소 신장 트리 알고리즘(크루스칼)도 이 사이클 판별을 그대로 사용합니다.
그래프와 탐색은 [그래프와 BFS·DFS](#/learn/algorithm/bfs-dfs-graph-grid)에서 이어서 다룹니다.

## 정리

- 분리 집합은 원소를 겹치지 않는 그룹으로 나누고 유니온 파인드는 이를 대표를 찾는 `find`와 두 그룹을 잇는 `union`으로 다룹니다.
- 각 원소의 부모를 `parent` 배열에 적고 자기 자신을 가리키는 루트를 그룹의 대표로 씁니다.
- `union`은 원소가 아니라 두 대표를 이어야 그룹 전체가 합쳐집니다.
- 경로 압축과 크기 기준 합치기를 함께 쓰면 트리가 낮게 유지되어 연산 한 번이 상수 시간에 가깝습니다.

## 핵심 질문 답

유니온 파인드는 각 원소의 부모를 배열에 적어 그룹을 트리로 표현하고 루트를 그룹의 대표로 씁니다.
`find`는 부모를 따라 올라가 대표를 찾고 `union`은 두 대표 중 하나를 다른 대표 아래에 붙여 그룹을 합칩니다.
두 원소의 대표가 같은지 비교하면 같은 그룹인지 바로 알 수 있습니다.
경로 압축과 크기 기준 합치기로 트리를 낮게 유지하면 연결 요소 수 세기와 사이클 판별을 빠르게 처리할 수 있습니다.
