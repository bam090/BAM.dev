# 배열: 번호로 바로 꺼내는 자료구조

## 학습 목표

- 배열에서 인덱스로 값을 꺼내는 일이 `O(1)`이고 중간에 넣거나 빼는 일이 `O(n)`인 이유를 설명할 수 있습니다.
- 1차원 배열과 2차원 배열에서 원하는 칸을 인덱스로 찾을 수 있습니다.

## 한줄 요약

배열은 같은 타입의 값을 정해진 개수의 칸에 번호 순서대로 담는 자료구조이고 번호로는 바로 꺼내지만 중간에 넣거나 빼려면 뒤의 원소를 옮겨야 합니다.

## 배열이란

**배열**은 같은 타입의 값 여러 개를 정해진 개수의 칸에 번호 순서대로 담는 자료구조입니다.
값을 하나씩 따로 변수에 담으면 값이 100개일 때 변수도 100개가 필요합니다.
배열은 이 값들을 한 이름으로 묶고 칸마다 번호를 붙여서 다루기 때문에 몇 개든 같은 방법으로 넣고 꺼낼 수 있습니다.

배열에 담긴 값 하나하나를 **원소**라고 합니다.
칸에 붙은 번호는 **인덱스**이고 0부터 시작합니다.
칸의 개수는 **길이**라고 합니다.

예를 들어 칸이 5개인 책장을 떠올려 보세요.
칸마다 0번부터 4번까지 번호가 붙어 있고 한 칸에 책 한 권을 꽂습니다.
이 문서는 이 책장 하나로 처음부터 끝까지 설명합니다.

![칸이 5개인 배열 shelf. 0번부터 3번 칸에 자바·파이썬·SQL·리눅스가 들어 있고 4번 칸은 비어 있다. 인덱스 2로 꺼내면 앞 칸을 거치지 않고 2번 칸의 SQL로 바로 간다.](content/assets/algorithm/array-index.png)

Java로 이 책장을 만들고 책을 꽂아 보겠습니다.

```java
String[] shelf = new String[5];
System.out.println("처음: " + Arrays.toString(shelf));

shelf[0] = "자바";
shelf[1] = "파이썬";
shelf[2] = "SQL";
shelf[3] = "리눅스";
System.out.println("꽂은 뒤: " + Arrays.toString(shelf));
System.out.println("2번 칸: " + shelf[2]);
System.out.println("칸 수: " + shelf.length);
```

아무것도 넣지 않은 처음 책장은 어떻게 출력될지 먼저 예상해 보세요.

```text
처음: [null, null, null, null, null]
꽂은 뒤: [자바, 파이썬, SQL, 리눅스, null]
2번 칸: SQL
칸 수: 5
```

`new String[5]`는 칸 5개를 먼저 만들고 모든 칸을 기본값으로 채웁니다.
`String` 같은 참조 타입의 기본값은 `null`이고 `int`는 `0`이며 `boolean`은 `false`입니다.
그래서 아직 책을 꽂지 않은 4번 칸은 `null`로 남아 있습니다.

> [!question]- 배열을 그대로 출력하면?
> `Arrays.toString()` 없이 배열 변수를 바로 출력하면 원소가 나오지 않습니다.
>
> ```java
> System.out.println(shelf);
> ```
>
> ```text
> [Ljava.lang.String;@2b2fa4f7
> ```
>
> 이 글자는 배열의 타입 이름과 `@` 뒤에 붙은 해시코드이고 `@` 뒤의 값은 실행할 때마다 달라질 수 있습니다.
> 원소를 보려면 `Arrays.toString(shelf)`로 출력합니다.

## 인덱스와 O(1) 접근

배열의 가장 큰 장점은 번호만 알면 원하는 칸으로 바로 간다는 것입니다.
`shelf[2]`를 읽을 때 0번과 1번 칸을 먼저 거치지 않습니다.
칸들이 번호 순서대로 줄지어 있다고 보면 첫 칸의 위치와 번호만으로 그 칸의 위치를 바로 계산할 수 있기 때문입니다.

그래서 칸이 5개든 5만 개든 인덱스로 꺼내는 데 걸리는 시간은 같습니다.
이것을 시간 복잡도로 `O(1)`이라고 씁니다.
참고로 Java 명세는 배열이 실제 메모리에 어떤 모양으로 놓이는지까지 정해 두지 않습니다.
그러니 주소 계산 방식보다 **인덱스로 원하는 칸에 바로 접근한다**는 성질로 기억하면 됩니다.

반면 번호를 모르고 값만 알 때는 이야기가 다릅니다.
`리눅스`가 몇 번 칸에 있는지 찾으려면 0번 칸부터 하나씩 비교해야 합니다.
칸이 `n`개이면 최대 `n`번을 비교하므로 값으로 찾기는 `O(n)`입니다.

인덱스는 0부터 `길이 - 1`까지만 쓸 수 있습니다.
칸이 5개인 책장에서 `shelf[5]`를 읽으면 없는 칸이라 `ArrayIndexOutOfBoundsException`이 납니다.
마지막 칸은 `shelf[shelf.length - 1]`로 읽는다고 기억해 두면 이 실수를 줄일 수 있습니다.

## 배열의 삽입과 삭제

이번에는 빈칸이 하나 남은 책장의 1번 칸에 `HTML` 책을 끼워 넣어 보겠습니다.
1번 칸에는 이미 `파이썬`이 있으니 그 자리를 먼저 비워야 합니다.

![1번 칸에 HTML을 끼워 넣는 과정. 리눅스·SQL·파이썬이 뒤쪽부터 차례로 한 칸씩 오른쪽으로 옮겨 간 뒤 비워진 1번 칸에 HTML이 들어간다.](content/assets/algorithm/array-insert-shift.png)

그림처럼 뒤쪽 원소부터 한 칸씩 오른쪽으로 옮깁니다.
앞쪽부터 옮기면 옮길 자리에 있던 값을 덮어써 버리기 때문입니다.
코드로 옮기면 다음과 같습니다.

```java
for (int i = shelf.length - 1; i > 1; i--) {
    shelf[i] = shelf[i - 1];
}
shelf[1] = "HTML";
System.out.println("1번 칸에 끼운 뒤: " + Arrays.toString(shelf));
```

반복문이 몇 번 돌고 나서 `HTML`이 들어갈지 세어 보세요.

```text
1번 칸에 끼운 뒤: [자바, HTML, 파이썬, SQL, 리눅스]
```

반복문은 `i`가 4·3·2일 때 세 번 돌면서 `리눅스`·`SQL`·`파이썬`을 한 칸씩 옮깁니다.
끼울 자리가 앞쪽일수록 옮길 원소가 많아지고 맨 앞에 끼우면 모든 원소를 옮깁니다.
그래서 중간에 넣는 일은 `O(n)`입니다.

빼는 일도 같습니다.
1번 칸의 책을 빼면 생긴 빈자리를 메우려고 뒤의 원소를 한 칸씩 앞으로 당겨야 하므로 역시 `O(n)`입니다.
반대로 맨 끝의 빈칸에 넣거나 맨 끝의 값을 빼는 일은 옮길 원소가 없으니 `O(1)`입니다.

## 배열의 크기

배열은 만들 때 길이가 정해지고 그 뒤로는 바뀌지 않습니다.
책장의 칸 수가 처음부터 정해져 있는 것과 같습니다.

앞에서 `HTML`을 끼워 넣어 이제 다섯 칸이 모두 찼습니다.
그런데 책을 한 권 더 꽂아야 한다면 어떻게 할까요?
같은 배열의 칸을 늘릴 방법은 없습니다.
그래서 더 큰 배열을 새로 만들고 기존 값을 하나씩 옮겨 담아야 합니다.

![칸이 다 찬 길이 5 배열의 값 다섯 개를 길이 10인 새 배열로 하나씩 복사하는 모습. 새 배열의 뒤쪽 다섯 칸은 비어 있다.](content/assets/algorithm/array-grow.png)

원소가 `n`개이면 `n`개를 모두 옮기므로 크기를 늘리는 일은 `O(n)`입니다.
이렇게 개수가 계속 바뀌는 데이터를 다룰 때 이 일을 대신 해 주는 것이 `ArrayList`입니다.
`ArrayList`가 내부 배열을 어떻게 키우는지는 [ArrayList와 LinkedList](#/learn/algorithm/list-and-conditions)에서 알아봅니다.

## 배열의 종류

지금까지 본 책장처럼 칸이 한 줄로 늘어선 배열을 **1차원 배열**이라고 합니다.
그런데 책장이 여러 층이라면 몇 층의 몇 번 칸인지 두 번호가 필요합니다.
이렇게 행과 열 두 번호로 칸을 찾는 배열이 **2차원 배열**입니다.

![3층 4칸 책장 bookcase. 가로줄인 행은 0층·1층·2층이고 세로줄인 열은 0번부터 3번 칸이다. 1층 행과 2번 열이 만나는 칸에 React가 있다.](content/assets/algorithm/array-2d.png)

가로줄 하나를 **행**이라고 하고 세로줄 하나를 **열**이라고 합니다.
`bookcase[1][2]`는 앞 번호로 1층 행을 고르고 뒤 번호로 그 층의 2번 칸을 고릅니다.

```java
String[][] bookcase = {
    {"자바", "파이썬", "SQL", "리눅스"},
    {"HTML", "CSS", "React", "Node"},
    {"수학", "영어", "역사", "과학"}
};
System.out.println("1층 2번 칸: " + bookcase[1][2]);
System.out.println("층 수: " + bookcase.length + " | 한 층의 칸 수: " + bookcase[0].length);
```

그림을 보고 `bookcase[1][2]`에 어떤 책이 있는지 먼저 찾아보세요.

```text
1층 2번 칸: React
층 수: 3 | 한 층의 칸 수: 4
```

Java의 2차원 배열은 "배열을 원소로 담은 배열"입니다.
그래서 `bookcase.length`는 층 수인 3이고 `bookcase[0].length`는 한 층의 칸 수인 4입니다.
2차원 배열의 모든 칸을 보려면 행을 도는 반복문 안에 열을 도는 반복문을 넣으므로 행이 `r`개이고 열이 `c`개이면 `O(r × c)`입니다.

코딩테스트에서 지도·게임판·좌석표처럼 가로세로로 칸이 나뉜 입력이 나오면 대부분 2차원 배열에 담습니다.

## 배열 연산의 복잡도

지금까지 책장으로 확인한 연산을 한 표에 모아 보겠습니다.

| 연산 | 복잡도 | 이유 |
| --- | --- | --- |
| 인덱스로 읽기·바꾸기 | `O(1)` | 번호로 그 칸에 바로 갑니다 |
| 값으로 찾기 | `O(n)` | 0번 칸부터 하나씩 비교합니다 |
| 맨 끝의 빈칸에 넣기·맨 끝 값 빼기 | `O(1)` | 옮길 원소가 없습니다 |
| 중간에 넣기·빼기 | `O(n)` | 뒤의 원소를 한 칸씩 옮깁니다 |
| 크기 늘리기 | `O(n)` | 더 큰 배열을 만들고 모두 복사합니다 |

배열은 읽기가 아주 빠른 대신 크기가 고정되어 있고 중간을 고치는 일이 느립니다.
그래서 개수가 정해져 있고 번호로 자주 읽는 데이터에 잘 맞습니다.
Java에서 크기가 바뀌는 목록을 쓰는 방법은 [ArrayList와 LinkedList](#/learn/algorithm/list-and-conditions)에서 알아봅니다.

## 배열의 활용

배열은 거의 모든 코딩테스트 문제의 바탕이 됩니다.
입력으로 받은 값을 담아 두는 곳이 대부분 배열이기 때문입니다.
그 위에서 인덱스로 바로 읽는 성질을 살리면 다음과 같은 일을 빠르게 할 수 있습니다.

| 쓰는 곳 | 배열로 하는 일 |
| --- | --- |
| 입력 기록 저장 | 날짜별 기록을 번호 순서대로 담고 `i`번째 값을 바로 읽습니다 |
| 개수 세기 | 값 자체를 인덱스로 써서 `count[값]++`로 몇 번 나왔는지 셉니다 |
| 방문 표시 | `visited[번호] = true`로 이미 본 칸을 표시합니다 |
| 격자 탐색 | 지도나 게임판을 2차원 배열에 담고 `[행][열]`로 칸을 옮겨 다닙니다 |

배열 위에서 두 인덱스를 함께 움직여 반복을 줄이는 방법은 [투 포인터와 슬라이딩 윈도우](#/learn/algorithm/two-pointers-sliding-window)에서 다룹니다.
2차원 배열을 칸에서 칸으로 옮겨 다니는 탐색은 [그래프와 BFS·DFS](#/learn/algorithm/bfs-dfs-graph-grid)로 이어집니다.

## 정리

- 배열은 같은 타입의 값을 정해진 개수의 칸에 번호 순서대로 담고 인덱스는 0부터 `길이 - 1`까지입니다.
- 인덱스로 읽고 바꾸는 일은 `O(1)`이고 값으로 찾는 일은 `O(n)`입니다.
- 길이는 만들 때 정해지므로 늘리려면 새 배열로 복사해야 하고 중간에 넣거나 빼면 뒤의 원소를 옮기느라 `O(n)`이 걸립니다.
- 2차원 배열은 `[행][열]` 두 번호로 칸을 찾고 모든 칸을 보는 데 `O(행 × 열)`이 걸립니다.

## 핵심 질문 답

배열은 칸마다 번호가 붙어 있어서 번호만 알면 앞 칸을 거치지 않고 그 칸으로 바로 가므로 인덱스로 읽는 일이 `O(1)`입니다.
대신 길이가 만들 때 정해지고 원소는 번호 순서를 빈틈없이 지켜야 합니다.
그래서 중간에 넣거나 빼려면 뒤의 원소를 한 칸씩 옮겨야 하고 원소가 `n`개이면 최대 `n`개를 옮기므로 `O(n)`입니다.
2차원 배열은 행과 열 두 번호로 같은 방식으로 칸을 바로 찾습니다.
