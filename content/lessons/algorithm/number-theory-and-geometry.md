# 06. 정수론과 기하학

## 학습 목표

- 약수와 배수의 관계를 나머지로 설명할 수 있습니다.
- 유클리드 알고리즘으로 두 양의 정수의 최대공약수를 구할 수 있습니다.
- 좌표와 외적 값을 이용해 세 점의 방향을 구분할 수 있습니다.
- 정수 범위와 좌표계 같은 입력 조건을 먼저 확인할 수 있습니다.

## 왜 필요한가

숫자나 좌표를 다루는 코드는 계산식을 바로 쓰기 전에 관계를 정해야 합니다.
두 수가 정확히 나누어지는지, 여러 수가 같은 간격으로 묶이는지, 세 점이 어느 방향으로 놓였는지를 알아야 다음 판단을 올바르게 할 수 있습니다.

이 단원에서는 넓은 정수론과 기하학 전체를 다루지 않습니다.
정수의 나머지로 최대공약수를 구하는 방법과, 좌표의 외적으로 세 점의 방향을 판별하는 입문 개념에 집중합니다.

## 개념 연결

- 선행: `algo.condition`, `js.operators`, `js.control-flow`, `js.functions`, `js.objects`에서 배운 조건 판단, 연산자, 반복문, 함수와 객체를 사용합니다.
- 이 단원: `algo.number-theory`, `algo.geometry`로 정수의 나눗셈 관계와 좌표의 방향을 판단합니다.
- 후속: `algo.binary-search`, `algo.graph-representation`에서 수의 범위와 좌표·연결 관계를 더 구조적으로 탐색합니다.

## 정수론: 정수 사이의 규칙 찾기

**정수론**은 정수의 성질과 정수 사이의 관계를 다루는 수학 분야입니다.
여기서는 먼저 약수, 배수와 나머지를 연결합니다.

- 어떤 정수 `a`를 양의 정수 `b`로 나눈 나머지가 `0`이면 `b`는 `a`의 **약수**입니다.
- 같은 상황에서 `a`는 `b`의 **배수**입니다.
- 여러 정수를 모두 나누어떨어지게 하는 약수 중 가장 큰 양의 정수를 **최대공약수**라고 합니다.

예를 들어 `30 % 6`은 `0`입니다.
따라서 `6`은 `30`의 약수이고, `30`은 `6`의 배수입니다.

JavaScript의 `%`는 나눗셈 뒤 남는 **나머지 연산자**입니다.
음수가 들어오면 결과의 부호를 따로 살펴야 하므로 이 단원의 최대공약수 예제는 양의 정수만 입력받습니다.

## 유클리드 알고리즘

두 양의 정수 `a`, `b`에서 `a`를 `b`로 나눈 나머지를 `r`이라고 하겠습니다.
유클리드 알고리즘은 다음 관계를 반복해서 사용합니다.

`gcd(a, b) = gcd(b, r)`

`a = b × 몫 + r`이므로 `a`와 `b`의 공약수는 `b`와 `r`의 공약수와 같습니다.
나머지가 `0`이 되면 그때의 나누는 수가 최대공약수입니다.

### 최소 예제 1. 최대공약수

```javascript
function gcd(a, b) {
  let left = a;
  let right = b;

  while (right !== 0) {
    const remainder = left % right;
    left = right;
    right = remainder;
  }

  return left;
}

console.log(gcd(84, 30)); // 6
```

이 함수는 두 입력이 양의 정수라는 조건에서 사용합니다.
나머지가 매번 이전의 나누는 수보다 작아지므로 반복은 결국 끝납니다.
두 입력 중 작은 값을 `m`이라고 할 때 유클리드 알고리즘의 반복 횟수는 `O(log m)`입니다.
예제는 각 `Number` 나머지 연산을 한 번의 연산으로 세는 일반적인 분석을 사용합니다.

## 기하학: 좌표를 계산 가능한 값으로 바꾸기

**계산 기하학**은 점, 선분, 다각형 같은 도형의 관계를 계산으로 판단하는 분야입니다.
점 하나는 `{ x, y }`처럼 가로 위치 `x`와 세로 위치 `y`로 나타낼 수 있습니다.

세 점 `A`, `B`, `C`가 있을 때 `A`에서 `B`로 가는 벡터와 `A`에서 `C`로 가는 벡터를 만듭니다.
두 벡터의 2차원 외적 값은 다음과 같습니다.

`(B.x - A.x) × (C.y - A.y) - (B.y - A.y) × (C.x - A.x)`

일반적인 수학 좌표계처럼 오른쪽이 `x`의 양의 방향이고 위쪽이 `y`의 양의 방향일 때 결과를 이렇게 해석합니다.

- 양수: `A → B → C`가 반시계 방향입니다.
- 음수: `A → B → C`가 시계 방향입니다.
- `0`: 세 점이 한 직선 위에 있습니다.

### 최소 예제 2. 세 점의 방향

```javascript
function direction(a, b, c) {
  const cross =
    (b.x - a.x) * (c.y - a.y) -
    (b.y - a.y) * (c.x - a.x);

  if (cross > 0) return "반시계";
  if (cross < 0) return "시계";
  return "일직선";
}

const a = { x: 0, y: 0 };
const b = { x: 3, y: 0 };
const c = { x: 3, y: 2 };

console.log(direction(a, b, c)); // 반시계
```

이 예제는 작은 정수 좌표와 위쪽으로 커지는 `y`축을 사용합니다.
화면 좌표처럼 아래쪽으로 갈수록 `y`가 커지면 시계와 반시계의 부호 해석이 반대로 보일 수 있습니다.
세 점의 좌표로 정해진 수의 산술 연산과 비교만 하므로 방향 판별은 `O(1)` 시간과 `O(1)` 추가 공간을 사용합니다.

## 단계별 실행 흐름

### `gcd(84, 30)`

| 단계 | `left` | `right` | `left % right` |
| --- | ---: | ---: | ---: |
| 1 | 84 | 30 | 24 |
| 2 | 30 | 24 | 6 |
| 3 | 24 | 6 | 0 |

세 번째 단계에서 `right`가 `0`으로 바뀝니다.
반복이 끝났을 때 `left`는 `6`이므로 최대공약수는 `6`입니다.

### 세 점의 방향

1. `A → B`는 `(3, 0)`입니다.
2. `A → C`는 `(3, 2)`입니다.
3. 외적 값은 `3 × 2 - 0 × 3 = 6`입니다.
4. 값이 양수이므로 일반적인 수학 좌표계에서는 반시계 방향입니다.

## 입력 조건을 먼저 확인하기

같은 공식도 입력 조건이 달라지면 그대로 사용할 수 없습니다.

- 최대공약수 예제는 양의 정수를 입력받습니다. 소수나 음수가 들어오는 경우를 임의로 섞지 않습니다.
- `Number`로 큰 정수를 곱하면 안전하게 표현할 수 있는 정수 범위를 넘을 수 있습니다.
- 소수 좌표는 계산 오차 때문에 이론상 `0`인 외적이 아주 작은 값으로 나올 수 있습니다.
- 화면 좌표와 수학 좌표는 `y`축이 커지는 방향이 다를 수 있습니다.

따라서 코드를 작성하기 전에 값의 범위, 정수 여부와 좌표계 방향을 먼저 적어 두는 습관이 중요합니다.

## 흔한 실수

### 1. `%`를 나눗셈의 몫이라고 생각하기

`a % b`는 몫이 아니라 나머지입니다.
나누어떨어지는지는 결과가 `0`인지 확인합니다.

### 2. 유클리드 알고리즘에서 두 값을 같은 순서로 갱신하기

다음 단계는 `(기존 b, 기존 나머지)`입니다.
나머지를 먼저 저장하지 않으면 필요한 이전 값을 잃을 수 있습니다.

### 3. 외적 공식에서 기준점을 섞기

두 벡터는 모두 같은 기준점 `A`에서 시작해야 합니다.
`B - A`와 `C - A`를 사용했는지 확인합니다.

### 4. 좌표계의 `y`축 방향을 확인하지 않기

화면에서는 아래쪽으로 갈수록 `y`가 커지는 경우가 많습니다.
사용하는 좌표계에 맞춰 부호의 뜻을 해석해야 합니다.

### 5. 모든 숫자가 정확한 정수라고 가정하기

큰 정수의 곱이나 소수 계산은 `Number`의 표현 한계와 오차 영향을 받을 수 있습니다.
입력 범위를 확인한 뒤 알맞은 숫자 표현과 비교 기준을 선택합니다.

4. 계산 전에 정수 범위와 `y`축 방향을 확인하나요?

## 확인 문제

1. `a % b === 0`이면 양의 정수 `a`와 `b`는 어떤 관계인가요?
2. 유클리드 알고리즘이 `(84, 30)`을 `(30, 24)`, `(24, 6)`으로 바꾸는 이유는 무엇인가요?
3. 일반적인 수학 좌표계에서 세 점의 외적 값이 양수라는 것은 무엇을 뜻하나요?
4. 큰 좌표나 소수 좌표를 사용할 때 입력 조건을 먼저 확인해야 하는 이유는 무엇인가요?

## 면접 답변 예시

### 답변 1

양의 정수 `a`를 `b`로 나눈 나머지가 `0`이면 `b`는 `a`의 약수이고 `a`는 `b`의 배수입니다. 나머지가 있는지만 확인하면 나누어떨어지는 관계를 판단할 수 있습니다.

### 답변 2

유클리드 알고리즘은 두 수의 최대공약수가 나누는 수와 나머지의 최대공약수와 같다는 성질을 사용합니다. `84 % 30`은 `24`이므로 `(84, 30)`을 `(30, 24)`로 바꾸고, 나머지가 `0`이 될 때까지 반복합니다.

### 답변 3

오른쪽이 `x`의 양의 방향이고 위쪽이 `y`의 양의 방향인 좌표계에서 외적 값이 양수이면 `A → B → C`가 반시계 방향입니다. 음수이면 시계 방향이고 `0`이면 세 점이 한 직선 위에 있습니다.

### 답변 4

JavaScript의 `Number`는 모든 크기의 정수를 정확히 표현하지 못하고 소수 계산에는 오차가 생길 수 있습니다. 또한 화면과 수학 좌표계는 `y`축 방향이 다를 수 있으므로 값의 범위, 정수 여부와 좌표계 방향을 먼저 확인해야 합니다.
