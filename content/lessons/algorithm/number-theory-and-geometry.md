# 나머지와 최대공약수

## 학습 목표

- 나머지 연산의 성질을 써서 큰 수의 덧셈·곱셈 결과를 나머지로 계산할 수 있습니다.
- 유클리드 호제법으로 최대공약수와 최소공배수를 구하고 계산이 빨리 끝나는 이유를 설명할 수 있습니다.

## 한줄 요약

나머지는 나누고 남은 수이고 덧셈·곱셈 중간에 나머지를 구해도 결과가 같으며 최대공약수는 큰 수를 작은 수로 나눈 나머지로 바꿔 가는 유클리드 호제법으로 빠르게 구합니다.

## 나머지란

**나머지**는 어떤 수를 다른 수로 똑같이 나누고 남은 수입니다.
코딩테스트의 수학 문제는 대부분 이 나머지에서 출발합니다.
짝수인지 확인하는 일·요일을 세는 일·답이 너무 커서 일부만 출력하는 일이 모두 나머지로 풀리기 때문입니다.

`a`를 `b`로 나누면 `a = b × 몫 + 나머지`로 쓸 수 있습니다.
여기서 **몫**은 `b`가 `a` 안에 몇 번 들어가는지입니다.
`a`와 `b`가 양수이면 나머지는 늘 `0` 이상 `b` 미만입니다.
Java에서는 몫을 `/`로 구하고 나머지를 `%`로 구합니다.

예를 들어 가로 84칸·세로 30칸인 바닥에 타일을 깐다고 해 보겠습니다.
이 문서는 84와 30이라는 두 수로 끝까지 설명합니다.
먼저 84칸짜리 줄을 30칸씩 끊어 보겠습니다.

![84칸짜리 막대를 30칸씩 끊으면 30칸 묶음 두 개가 나오고 24칸이 남는다. 묶음 수 2가 몫이고 남은 24칸이 나머지다.](content/assets/algorithm/math-remainder-bar.png)

30칸 묶음이 두 개 나오고 24칸이 남습니다.
그래서 `84 / 30`은 `2`이고 `84 % 30`은 `24`입니다.
식으로 확인하면 `84 = 30 × 2 + 24`입니다.

나머지가 `0`이면 남는 칸 없이 똑같이 나누어떨어진다는 뜻입니다.
`84 % 6`은 `0`이므로 84칸은 6칸씩 빈틈없이 나뉩니다.
이 관계가 뒤에서 볼 약수와 배수의 기준이 됩니다.

## 나머지 연산의 성질

코딩테스트에는 `답을 1,000,000,007로 나눈 나머지를 출력하라`는 조건이 자주 붙습니다.
답이 `long`에도 담기지 않을 만큼 커질 수 있기 때문입니다.
그런데 결과를 다 구한 뒤에 나누려면 결국 그 큰 수를 담아야 합니다.

다행히 덧셈과 곱셈은 중간에 나머지를 구해도 마지막 나머지가 같습니다.
이렇게 나머지만 들고 계산하는 방식을 **모듈러 연산**이라고 합니다.

| 연산 | 성질 |
| --- | --- |
| 덧셈 | `(a + b) % m = ((a % m) + (b % m)) % m` |
| 곱셈 | `(a × b) % m = ((a % m) × (b % m)) % m` |
| 뺄셈 | `(a - b) % m = ((a % m) - (b % m) + m) % m` |

나머지는 시계처럼 `m`에 닿으면 다시 `0`으로 돌아옵니다.
`m`이 11인 시계에 84와 30을 올려 보겠습니다.

![0부터 10까지 적힌 원형 시계. 84는 11로 나눈 나머지 7에 놓이고 30은 나머지 8에 놓인다. 7에서 8칸을 더 돌면 한 바퀴를 넘어 4에 닿고 84 더하기 30인 114도 나머지 4에 놓인다.](content/assets/algorithm/math-mod-clock.png)

`84 % 11`은 `7`이고 `30 % 11`은 `8`입니다.
7에서 8칸을 더 돌면 한 바퀴를 넘어 `4`에 닿습니다.
실제로 `114 % 11`도 `4`이므로 두 수를 먼저 더하든 나머지끼리 더하든 도착하는 칸이 같습니다.

곱셈도 같은 방식으로 확인할 수 있습니다.
코드를 보기 전에 두 줄의 결과가 같을지 예상해 보세요.

```java
int m = 11;
System.out.println((84 * 30) % m);
System.out.println((84 % m) * (30 % m) % m);
```

```text
1
1
```

`84 × 30`은 2,520이고 11로 나누면 1이 남습니다.
나머지끼리 곱한 `7 × 8`은 56이고 11로 나누면 역시 1이 남습니다.
그래서 수가 아무리 커져도 매 단계 나머지만 남기면 값이 `m`보다 커지지 않습니다.

뺄셈은 나머지끼리 빼면 음수가 나올 수 있습니다.
`84 % 11 - 30 % 11`은 `7 - 8`이라 `-1`이 됩니다.
실제 `(84 - 30) % 11`은 `10`이므로 뺄셈 뒤에는 `m`을 한 번 더해 `(-1 + 11) % 11 = 10`으로 되돌립니다.

> [!question]- 나눗셈에는 이 성질이 없나요?
> 나눗셈은 나머지끼리 나누면 결과가 달라집니다.
> 예를 들어 `(84 / 6) % 11`은 `14 % 11`이라 `3`입니다.
> 반면 `(84 % 11) / (6 % 11)`은 `7 / 6`이라 `1`이 됩니다.
>
> 나머지 세계에서 나누려면 곱하면 1이 되는 수인 역원을 곱합니다.
> 역원을 빠르게 구하는 방법은 [빠른 거듭제곱](#/learn/algorithm/fast-power)에서 다룹니다.

## 약수와 배수

이제 나머지가 `0`인 경우를 자세히 보겠습니다.
`a % b`가 `0`이면 `b`를 `a`의 **약수**라고 하고 `a`를 `b`의 **배수**라고 합니다.
`84 % 6`이 `0`이므로 6은 84의 약수이고 84는 6의 배수입니다.

84와 30의 약수를 모두 적으면 이렇습니다.

| 수 | 약수 |
| --- | --- |
| 84 | 1 · 2 · 3 · 4 · 6 · 7 · 12 · 14 · 21 · 28 · 42 · 84 |
| 30 | 1 · 2 · 3 · 5 · 6 · 10 · 15 · 30 |
| 둘 다 | 1 · 2 · 3 · 6 |

두 수에 함께 들어 있는 약수를 **공약수**라고 하고 그중 가장 큰 수를 **최대공약수**라고 합니다.
84와 30의 최대공약수는 6입니다.
바닥으로 보면 한 변이 6칸인 정사각형 타일이 84×30 바닥을 빈틈없이 채우는 가장 큰 타일이라는 뜻입니다.

반대로 두 수의 배수에 함께 들어 있는 수를 **공배수**라고 하고 그중 가장 작은 수를 **최소공배수**라고 합니다.
최소공배수는 뒤에서 최대공약수로 한 번에 구합니다.

그런데 약수를 전부 적어서 비교하는 방법은 수가 커지면 느립니다.
가장 단순하게는 1부터 `a`까지 하나씩 나눠 봐야 하기 때문입니다.
10억 같은 수라면 10억 번을 나눠야 합니다.

## 유클리드 호제법

**유클리드 호제법**은 큰 수를 작은 수로 나눈 나머지로 바꿔 가며 최대공약수를 구하는 방법입니다.
규칙은 한 줄입니다.

`gcd(a, b) = gcd(b, a % b)`

여기서 `gcd`는 최대공약수(greatest common divisor)를 줄인 이름입니다.
나머지가 `0`이 되면 그때 남은 `b`가 최대공약수입니다.

규칙이 성립하는 이유는 바닥에서 정사각형을 잘라 내 보면 보입니다.
84×30 바닥에서 30×30 정사각형을 잘라 낼 수 있는 만큼 잘라 내고 남은 직사각형에서 같은 일을 반복합니다.

![84×30 직사각형에서 30×30 정사각형 두 개를 잘라 내면 24×30이 남고 거기서 24×24 정사각형 하나를 잘라 내면 24×6이 남는다. 24×6은 6×6 정사각형 네 개로 딱 나뉘므로 최대공약수는 6이다.](content/assets/algorithm/math-euclid-squares.png)

| 단계 | a | b | a % b | 바닥에서 한 일 |
| --- | --- | --- | --- | --- |
| 1 | 84 | 30 | 24 | 30×30 두 장을 잘라 내고 24×30이 남음 |
| 2 | 30 | 24 | 6 | 24×24 한 장을 잘라 내고 24×6이 남음 |
| 3 | 24 | 6 | 0 | 6×6 네 장으로 딱 나뉨 |

84×30 바닥을 빈틈없이 채우는 정사각형 타일은 잘라 낸 30×30 정사각형도 채우므로 남은 24×30도 채웁니다.
반대로 남은 24×30을 채우는 타일은 30×30 정사각형도 채우므로 원래 바닥 전체를 채웁니다.
그래서 `(84, 30)`·`(30, 24)`·`(24, 6)`은 모두 최대공약수가 같고 마지막에 남은 6이 답입니다.

이 방법이 빠른 이유는 나머지가 늘 나누는 수보다 작기 때문입니다.
게다가 두 단계를 지나면 수가 절반보다 작아집니다.
그래서 반복 횟수는 `O(log min(a, b))`이고 10억 같은 수도 수십 번 안에 끝납니다.

코드로 옮기면 반복문 하나입니다.
`a`를 바꾸기 전에 나머지부터 구해 두는 순서를 눈여겨보세요.

```java
static int gcd(int a, int b) {
    while (b != 0) {
        int r = a % b;
        a = b;
        b = r;
    }
    return a;
}
```

`a = b`를 먼저 쓰면 원래 `a`가 사라져서 나머지를 구할 수 없습니다.
그래서 `r`에 나머지를 먼저 담고 두 칸을 한 칸씩 당깁니다.

## 최소공배수

최대공약수를 알면 최소공배수는 계산 한 번으로 나옵니다.
두 수를 곱하면 최대공약수가 두 번 들어가므로 한 번을 나눠 주면 됩니다.

`lcm(a, b) = a / gcd(a, b) × b`

`lcm`은 최소공배수(least common multiple)를 줄인 이름입니다.
84와 30이면 `84 / 6 × 30 = 420`입니다.
바닥으로 보면 가로 84칸·세로 30칸 타일을 같은 방향으로 늘어놓아 처음으로 정사각형이 되는 크기가 420×420이라는 뜻입니다.

곱하기 전에 먼저 나누는 이유는 중간값을 작게 두기 위해서입니다.
`a × b`를 먼저 계산하면 두 수가 클 때 `int` 범위를 넘을 수 있기 때문입니다.
Java에서 쓰는 방법과 범위를 넘지 않게 계산하는 방법은 [Java로 정수 계산하기](#/learn/algorithm/integer-java)에서 알아봅니다.

> [!note]- 전체 코드 보기
> 이 문서의 예제를 하나로 합친 프로그램입니다.
> `TileGcd.java`로 저장해 실행해 볼 수 있습니다.
>
> ```java
> public class TileGcd {
>     static int gcd(int a, int b) {
>         while (b != 0) {
>             int r = a % b;
>             a = b;
>             b = r;
>         }
>         return a;
>     }
>
>     static int lcm(int a, int b) {
>         return a / gcd(a, b) * b;
>     }
>
>     public static void main(String[] args) {
>         System.out.println("몫: " + 84 / 30);
>         System.out.println("나머지: " + 84 % 30);
>
>         int m = 11;
>         System.out.println("덧셈: " + (84 + 30) % m + " " + (84 % m + 30 % m) % m);
>         System.out.println("곱셈: " + (84 * 30) % m + " " + (84 % m) * (30 % m) % m);
>         System.out.println("뺄셈: " + (84 % m - 30 % m + m) % m);
>
>         System.out.println("최대공약수: " + gcd(84, 30));
>         System.out.println("최소공배수: " + lcm(84, 30));
>     }
> }
> ```
>

> 덧셈: 4 4

> 뺄셈: 10

> ```

## 나머지와 최대공약수의 활용

코딩테스트에서 나머지와 최대공약수는 이런 모습으로 나옵니다.

| 문제에 나오는 말 | 쓰는 도구 |
| --- | --- |
| 답을 1,000,000,007로 나눈 나머지를 출력 | 덧셈·곱셈마다 `% m` |
| 짝수·홀수·N의 배수 | `x % N == 0` |
| 요일·순환하는 차례 | `(시작 + 이동) % 주기` |
| 가장 큰 정사각형·똑같이 나누기 | 최대공약수 |
| 두 주기가 처음 겹치는 때 | 최소공배수 |

문제에 나오는 말을 이 표의 도구로 바꾸고 나면 코드는 대부분 몇 줄로 끝납니다.
수가 셋 이상이면 앞의 두 수부터 차례로 `gcd`를 이어서 구합니다.
예를 들어 84·30·42의 최대공약수는 `gcd(gcd(84, 30), 42)`이고 `gcd(6, 42)`이므로 6입니다.

## 정리

- 나머지는 `a = b × 몫 + 나머지`에서 남은 수이고 `0` 이상 `b` 미만입니다.
- 덧셈·곱셈은 중간에 나머지를 구해도 결과가 같아서 큰 수를 `m` 미만으로 유지하며 계산할 수 있습니다.
- 유클리드 호제법은 `gcd(a, b) = gcd(b, a % b)`를 나머지가 `0`이 될 때까지 반복하며 `O(log min(a, b))`에 끝납니다.
- 최소공배수는 `a / gcd(a, b) × b`로 먼저 나눈 뒤 곱해서 구합니다.

## 핵심 질문 답

큰 수는 덧셈·곱셈을 할 때마다 나머지를 구해서 `m` 미만의 수로만 계산합니다.
덧셈과 곱셈은 중간에 나머지를 구해도 마지막 나머지가 같기 때문입니다.
최대공약수는 약수를 모두 적는 대신 `gcd(a, b) = gcd(b, a % b)`를 나머지가 `0`이 될 때까지 반복해서 구합니다.
나머지가 매번 나누는 수보다 작아져서 `O(log min(a, b))`번 안에 끝나고 최소공배수는 `a / gcd(a, b) × b`로 바로 구합니다.
