# 좌표와 기하: 거리와 외적

## 학습 목표

- 두 점 사이의 거리를 제곱한 값으로 비교하고 좌표 범위에 맞는 정수 타입을 고를 수 있습니다.
- 벡터의 외적 부호로 세 점이 시계 방향·반시계 방향·일직선 중 어느 쪽인지 판별할 수 있습니다.

## 한줄 요약

좌표 문제는 두 점의 차이로 만든 벡터로 계산하며 거리는 제곱한 채로 비교하고 세 점의 방향은 외적의 부호로 정수 계산만으로 판별합니다.

## 좌표란

**좌표**는 평면 위의 위치를 가로 위치 `x`와 세로 위치 `y` 두 수로 나타낸 것입니다.
코딩테스트의 기하 문제는 점과 선을 그림으로 보지 않고 이 두 수만으로 계산해서 답을 냅니다.
그래서 거리나 방향을 좌표 계산으로 바꾸는 방법만 알면 대부분의 기하 문제를 시작할 수 있습니다.

이 문서는 오른쪽으로 갈수록 `x`가 커지고 위로 갈수록 `y`가 커지는 수학의 좌표를 씁니다.
격자 문제처럼 아래로 갈수록 행 번호가 커지는 좌표와는 `y`의 방향이 반대입니다.

예를 들어 지도 위에 집·편의점·카페가 있다고 해 보겠습니다.
이 문서는 이 세 곳의 좌표로 끝까지 설명합니다.

![좌표 평면 위의 세 점. 집 A는 1과 1 · 편의점 B는 4와 5 · 카페 C는 5와 2에 있다. 집에서 편의점까지는 가로 3 세로 4인 직각삼각형의 빗변으로 거리 5이고 집에서 카페까지는 가로 4 세로 1인 직각삼각형의 빗변으로 거리의 제곱이 17이다.](content/assets/algorithm/math-geo-distance.png)

집은 `A(1, 1)`이고 편의점은 `B(4, 5)`이며 카페는 `C(5, 2)`입니다.
이제 집에서 어느 곳이 더 가까운지부터 계산해 보겠습니다.

## 두 점 사이의 거리

두 점 사이의 거리는 가로 차이와 세로 차이로 만든 직각삼각형의 빗변 길이입니다.
피타고라스 정리에 따라 빗변의 제곱은 두 변의 제곱을 더한 값과 같기 때문입니다.

`거리 = √((x₂ - x₁)² + (y₂ - y₁)²)`

집에서 편의점까지는 가로 3·세로 4이므로 `√(9 + 16) = √25 = 5`입니다.
집에서 카페까지는 가로 4·세로 1이므로 `√(16 + 1) = √17`이고 약 4.12입니다.
그래서 카페가 더 가깝습니다.

그런데 가까운지 비교할 때는 제곱근을 구하지 않아도 됩니다.
거리가 더 길면 그 제곱도 더 크기 때문에 25와 17만 비교해도 결론이 같습니다.
제곱근을 빼면 계산이 정수에서 끝나서 실수의 작은 오차를 걱정하지 않아도 됩니다.

실수 오차가 어떤 모습인지 한 줄로 확인해 보겠습니다.
`√2 × √2`는 수학에서는 정확히 2입니다.
Java에서 `Math.sqrt(2) * Math.sqrt(2) == 2`의 결과를 예상해 보세요.

```text
√2 × √2 == 2: false
```

`double`은 `√2` 같은 수를 정확히 담지 못하고 가장 가까운 값으로 저장합니다.
그래서 두 번 곱하면 2에서 아주 조금 벗어난 값이 되고 `==` 비교가 `false`가 됩니다.
정수 좌표에서 거리를 비교할 때는 제곱한 정수끼리 비교하는 것이 안전합니다.

> [!question]- 맨해튼 거리란?
> 맨해튼 거리는 대각선으로 가지 못하고 가로와 세로로만 움직일 때의 거리입니다.
> 식은 `|x₂ - x₁| + |y₂ - y₁|`이고 격자 위를 한 칸씩 움직이는 문제에서 씁니다.
>
> 집에서 편의점까지는 `3 + 4 = 7`이고 집에서 카페까지는 `4 + 1 = 5`입니다.
> 격자 탐색은 [그래프와 BFS·DFS](#/learn/algorithm/bfs-dfs-graph-grid)에서 다룹니다.

## 벡터

거리 계산에서 이미 두 점의 차이를 썼습니다.
이 차이를 방향까지 함께 담아 하나의 값으로 부르는 것이 벡터입니다.

**벡터**는 한 점에서 다른 점으로 가는 방향과 길이를 `(가로 이동, 세로 이동)`으로 나타낸 값입니다.
시작점에서 끝점을 빼서 만듭니다.
집에서 편의점으로 가는 벡터는 `B - A = (4 - 1, 5 - 1) = (3, 4)`입니다.
집에서 카페로 가는 벡터는 `C - A = (5 - 1, 2 - 1) = (4, 1)`입니다.

벡터의 길이는 앞의 거리와 같습니다.
그리고 벡터는 어디서 출발하든 같은 이동을 뜻하므로 두 벡터를 같은 시작점에 놓고 비교할 수 있습니다.
이 성질로 세 점의 방향을 판별합니다.

## 외적으로 세 점의 방향 판별

집에서 편의점으로 걸어간 뒤 카페 쪽으로 몸을 돌린다고 생각해 보세요.
왼쪽으로 돌까요 아니면 오른쪽으로 돌까요?
이 질문을 계산 한 번으로 답하는 것이 외적입니다.

두 벡터 `(x₁, y₁)`와 `(x₂, y₂)`의 **외적**은 `x₁ × y₂ - y₁ × x₂`로 계산하는 값입니다.
외적의 부호가 두 번째 벡터가 첫 번째 벡터의 어느 쪽에 있는지를 알려 줍니다.
그래서 세 점 `A`·`B`·`C`의 방향은 `A`에서 출발하는 두 벡터 `B - A`와 `C - A`의 외적으로 판별합니다.
이 판별을 흔히 **CCW**(counterclockwise·반시계)라고 부릅니다.

![세 가지 경우를 나란히 놓은 그림. 집에서 편의점을 지나 카페로 가면 오른쪽으로 꺾여 외적이 음수 13이고 시계 방향이다. 집에서 카페를 지나 편의점으로 가면 왼쪽으로 꺾여 외적이 13이고 반시계 방향이다. 집에서 편의점을 지나 7과 9로 가면 한 줄 위에 있어 외적이 0이고 일직선이다.](content/assets/algorithm/math-geo-ccw.png)

| 외적 값 | `A → B → C`의 방향 | 걸어가는 느낌 |
| --- | --- | --- |
| 양수 | 반시계 방향 | 왼쪽으로 꺾음 |
| 음수 | 시계 방향 | 오른쪽으로 꺾음 |
| 0 | 일직선 | 꺾지 않음 |

집 → 편의점 → 카페를 계산해 보겠습니다.
두 벡터는 `(3, 4)`와 `(4, 1)`이므로 외적은 `3 × 1 - 4 × 4 = 3 - 16 = -13`입니다.
음수이므로 시계 방향이고 그림에서도 편의점에서 카페 쪽으로 오른쪽으로 꺾입니다.

순서를 바꿔 집 → 카페 → 편의점으로 가면 두 벡터의 자리가 바뀝니다.
그래서 외적은 `4 × 4 - 1 × 3 = 13`으로 부호만 바뀌고 반시계 방향이 됩니다.
점 `(7, 9)`로 가는 벡터 `(6, 8)`은 `(3, 4)`와 방향이 같아서 외적이 `3 × 8 - 4 × 6 = 0`이고 일직선입니다.

외적은 방향만 알려 주지 않습니다.
외적의 절댓값은 두 벡터로 만든 평행사변형의 넓이이고 그 절반이 삼각형의 넓이입니다.
그래서 집·편의점·카페를 잇는 삼각형의 넓이는 `13 / 2 = 6.5`입니다.

코드로 옮기면 뺄셈 네 번과 곱셈 두 번입니다.
`record`는 좌표 두 개를 묶어 두는 짧은 클래스이고 값은 `a.x()`처럼 괄호를 붙여 꺼냅니다.

```java
record Point(long x, long y) {}

static long cross(Point a, Point b, Point c) {
    long abX = b.x() - a.x();
    long abY = b.y() - a.y();
    long acX = c.x() - a.x();
    long acY = c.y() - a.y();
    return abX * acY - abY * acX;
}
```

전체 코드에는 외적의 부호를 방향 이름으로 바꾸는 `direction` 메서드가 함께 있습니다.
`cross(home, store, cafe)`의 값과 세 경우의 방향이 어떻게 나올지 앞의 계산과 비교해 예상해 보세요.

```text
외적: -13
집 → 편의점 → 카페: 시계
집 → 카페 → 편의점: 반시계
집 → 편의점 → (7, 9): 일직선
```

외적 값은 앞에서 손으로 구한 `-13`과 같습니다.
세 방향도 음수는 시계 · 양수는 반시계 · 0은 일직선이라는 표의 규칙대로 나옵니다.

## 정수 범위 주의

좌표 문제에는 보통 `좌표는 -1,000,000,000 이상 1,000,000,000 이하`처럼 범위가 붙습니다.
좌표 하나는 `int`에 담기지만 거리의 제곱과 외적은 곱셈을 하므로 값이 훨씬 커집니다.

| 계산 | 가장 큰 크기 | 담을 타입 |
| --- | --- | --- |
| 좌표 | 10⁹ | `int` |
| 좌표의 차 | 2 × 10⁹ | `int`에 겨우 들어감 |
| 차의 곱 | 4 × 10¹⁸ | `long` |
| 외적·거리의 제곱 | 8 × 10¹⁸ | `long`에 들어감 |

`int`의 최댓값은 약 2.1 × 10⁹이고 `long`의 최댓값은 약 9.2 × 10¹⁸입니다.
그래서 곱셈이 들어가는 거리의 제곱과 외적은 반드시 `long`으로 계산합니다.
10억을 `int`로 제곱하면 어떻게 되는지 예상해 보세요.

```text
int 제곱: -1486618624
long 제곱: 1000000000000000000
```

`int`로 곱하면 범위를 넘어서 엉뚱한 음수가 나옵니다.
위 `Point`처럼 좌표를 처음부터 `long`으로 담아 두면 뺄셈과 곱셈이 모두 `long`에서 일어나 이런 실수를 막을 수 있습니다.
오버플로를 더 자세히 다루고 Java에서 막는 방법은 [Java로 정수 계산하기](#/learn/algorithm/integer-java)에서 알아봅니다.

> [!note]- 전체 코드 보기
> 이 문서의 예제를 하나로 합친 프로그램입니다.
> `MapGeometry.java`로 저장해 실행해 볼 수 있습니다.
>
> ```java
> public class MapGeometry {
>     record Point(long x, long y) {}
>
>     static long squaredDistance(Point p, Point q) {
>         long dx = q.x() - p.x();
>         long dy = q.y() - p.y();
>         return dx * dx + dy * dy;
>     }
>
>     static long manhattan(Point p, Point q) {
>         return Math.abs(q.x() - p.x()) + Math.abs(q.y() - p.y());
>     }
>
>     static long cross(Point a, Point b, Point c) {
>         long abX = b.x() - a.x();
>         long abY = b.y() - a.y();
>         long acX = c.x() - a.x();
>         long acY = c.y() - a.y();
>         return abX * acY - abY * acX;
>     }
>
>     static String direction(Point a, Point b, Point c) {
>         long value = cross(a, b, c);
>         if (value > 0) return "반시계";
>         if (value < 0) return "시계";
>         return "일직선";
>     }
>
>     public static void main(String[] args) {
>         Point home = new Point(1, 1);
>         Point store = new Point(4, 5);
>         Point cafe = new Point(5, 2);
>
>         System.out.println("편의점 거리의 제곱: " + squaredDistance(home, store));
>         System.out.println("카페 거리의 제곱: " + squaredDistance(home, cafe));
>         System.out.println("편의점 거리: " + Math.sqrt(squaredDistance(home, store)));
>         System.out.println("카페 거리: " + Math.sqrt(squaredDistance(home, cafe)));
>         System.out.println("맨해튼 거리: " + manhattan(home, store) + " " + manhattan(home, cafe));
>         System.out.println("√2 × √2 == 2: " + (Math.sqrt(2) * Math.sqrt(2) == 2));
>
>         System.out.println("외적: " + cross(home, store, cafe));
>         System.out.println("집 → 편의점 → 카페: " + direction(home, store, cafe));
>         System.out.println("집 → 카페 → 편의점: " + direction(home, cafe, store));
>         System.out.println("집 → 편의점 → (7, 9): " + direction(home, store, new Point(7, 9)));
>         System.out.println("삼각형 넓이: " + Math.abs(cross(home, store, cafe)) / 2.0);
>
>         int dx = 1_000_000_000;
>         System.out.println("int 제곱: " + dx * dx);
>         System.out.println("long 제곱: " + (long) dx * dx);
>     }
> }
> ```
>
> ```text
> 편의점 거리의 제곱: 25
> 카페 거리의 제곱: 17
> 편의점 거리: 5.0
> 카페 거리: 4.123105625617661
> 맨해튼 거리: 7 5
> √2 × √2 == 2: false
> 외적: -13
> 집 → 편의점 → 카페: 시계
> 집 → 카페 → 편의점: 반시계
> 집 → 편의점 → (7, 9): 일직선
> 삼각형 넓이: 6.5
> int 제곱: -1486618624
> long 제곱: 1000000000000000000
> ```

## 좌표와 기하의 활용

코딩테스트에서 좌표와 기하는 이런 모습으로 나옵니다.

| 문제에 나오는 말 | 쓰는 계산 |
| --- | --- |
| 가장 가까운 점·반지름 안에 있는지 | 거리의 제곱끼리 비교 |
| 가로·세로로만 이동 | 맨해튼 거리 |
| 세 점의 방향·한 줄 위에 있는지 | 외적의 부호 |
| 세 점으로 만든 삼각형의 넓이 | 외적의 절댓값 / 2 |
| 두 선분이 만나는지 | 외적으로 양쪽 끝점의 방향을 각각 확인 |

두 선분이 만나는지 판별할 때도 외적을 씁니다.
한 선분을 기준으로 다른 선분의 두 끝점이 서로 반대쪽에 있는지 외적 부호로 확인하고 반대 선분으로도 한 번 더 확인합니다.
어떤 계산이든 좌표 범위를 먼저 보고 곱셈이 들어가면 `long`으로 계산합니다.

## 정리

- 두 점의 거리는 `√(가로 차² + 세로 차²)`이고 비교할 때는 제곱한 정수끼리 비교해 실수 오차를 피합니다.
- 벡터는 끝점에서 시작점을 뺀 `(가로 이동, 세로 이동)`이고 같은 시작점에 놓고 비교할 수 있습니다.
- `B - A`와 `C - A`의 외적 `x₁ × y₂ - y₁ × x₂`가 양수면 반시계 · 음수면 시계 · 0이면 일직선입니다.
- 거리의 제곱과 외적은 곱셈이 들어가므로 좌표 범위가 크면 `long`으로 계산합니다.

## 핵심 질문 답

두 점 사이의 거리는 가로 차와 세로 차를 각각 제곱해 더한 값으로 비교하고 제곱근은 필요할 때만 구합니다.
세 점 `A`·`B`·`C`의 방향은 `B - A`와 `C - A` 두 벡터의 외적 `x₁ × y₂ - y₁ × x₂`의 부호로 판별합니다.
양수면 반시계 방향이고 음수면 시계 방향이며 0이면 일직선입니다.
두 계산 모두 곱셈이 들어가므로 좌표 범위를 먼저 확인하고 크면 `long`으로 계산합니다.
