## 동적 계획법이란

**동적 계획법**은 큰 문제를 작은 문제로 나누어 풀고 작은 문제의 답을 저장해 두었다가 다시 필요할 때 꺼내 쓰는 방법입니다.
영어 이름인 Dynamic Programming을 줄여 **DP**라고도 부릅니다.
재귀로 문제를 나누면 같은 작은 문제를 몇 번이고 다시 풀게 되는 경우가 많은데 DP는 이 반복 계산을 없애 줍니다.

여기서 **부분 문제**는 큰 문제를 풀려고 먼저 풀어야 하는 더 작은 문제입니다.
그리고 부분 문제의 답을 저장해 두는 배열을 흔히 **DP 표**라고 부릅니다.

예를 들어 앞의 두 수를 더해 다음 수를 만드는 **피보나치 수열**을 떠올려 보세요.
첫째와 둘째 수는 1이고 셋째부터는 바로 앞 두 수의 합입니다.

```text
1, 1, 2, 3, 5, 8, 13, 21, ...
```

`n`번째 피보나치 수를 `fib(n)`이라고 하면 `fib(5)`를 구하려면 `fib(4)`와 `fib(3)`이 필요합니다.
큰 문제의 답이 작은 문제의 답으로 만들어지는 셈입니다.
이 문서는 피보나치 수 하나로 끝까지 설명합니다.

## 중복 호출

피보나치의 정의를 그대로 재귀 함수로 옮기면 다음과 같습니다.

```java
static long fibPlain(int n) {
    calls++;
    if (n <= 2) return 1;
    return fibPlain(n - 1) + fibPlain(n - 2);
}
```

코드는 짧고 정의와 똑같아 보입니다.
그런데 `fib(5)`를 부르면 안에서 무슨 일이 일어나는지 호출 트리로 그려 보면 문제가 보입니다.

![fib(5)를 그냥 재귀로 부를 때의 호출 트리. fib(5) 아래에 fib(4)와 fib(3)이 있고 fib(4) 아래에 다시 fib(3)과 fib(2)가 있다. 주황색 fib(3)이 두 번 나오고 빨간색 fib(2)가 세 번 나온다. 호출은 모두 9번이지만 서로 다른 문제는 5개뿐이다.](content/assets/algorithm/dp-fib-call-tree.png)

`fib(3)`은 왼쪽 갈래와 오른쪽 갈래에서 한 번씩 모두 두 번 계산됩니다.
`fib(2)`는 세 번이나 계산됩니다.
이렇게 같은 부분 문제를 여러 번 푸는 것을 **중복 호출**이라고 합니다.

`n`이 5일 때는 9번이면 끝납니다.
`n`이 40이면 호출이 몇 번일지 예상해 보세요.

```text
그냥 재귀 fib(5) = 5 · 호출 9번
그냥 재귀 fib(40) = 102334155 · 호출 204668309번
```

`n`은 8배가 되었을 뿐인데 호출은 2억 번을 넘습니다.
한 번 부를 때마다 두 갈래로 나뉘어서 `n`이 하나 늘 때마다 호출 수가 약 1.6배씩 불어나기 때문입니다.
그런데 서로 다른 부분 문제는 `fib(1)`부터 `fib(40)`까지 40개뿐입니다.
나머지 호출은 모두 이미 푼 문제를 다시 푼 것입니다.

## 동적 계획법의 조건

그렇다면 어떤 문제에 DP를 쓸 수 있을까요?
두 가지 성질이 함께 있어야 합니다.

| 조건 | 뜻 | 피보나치에서 |
| --- | --- | --- |
| 겹치는 부분 문제 | 같은 부분 문제가 여러 번 필요합니다 | `fib(3)`이 여러 갈래에서 필요합니다 |
| 최적 부분 구조 | 큰 문제의 답을 부분 문제의 답만으로 만들 수 있습니다 | `fib(n)`은 `fib(n - 1)`과 `fib(n - 2)`의 합입니다 |

**겹치는 부분 문제**가 없다면 답을 저장해 두어도 다시 꺼낼 일이 없습니다.
예를 들어 [백트래킹](#/learn/algorithm/brute-force-backtracking-recursion)으로 순열을 만드는 문제는 갈래마다 다른 선택을 하므로 저장해 둔 답을 다시 쓸 일이 거의 없습니다.

**최적 부분 구조**는 부분 문제의 답이 정해지면 큰 문제의 답도 그것만으로 정해진다는 뜻입니다.
최솟값이나 최댓값을 구하는 문제에서는 큰 문제의 가장 좋은 답 안에 부분 문제의 가장 좋은 답이 들어 있어야 합니다.
피보나치는 큰 답이 작은 답의 합으로 바로 정해지므로 이 조건을 만족합니다.

## 동적 계획법 설계

DP로 풀기로 했다면 코드를 쓰기 전에 네 가지를 정합니다.

| 정할 것 | 뜻 | 피보나치에서 |
| --- | --- | --- |
| 상태 | 표의 한 칸이 무엇을 뜻하는지 | `dp[i]`는 `i`번째 피보나치 수 |
| 점화식 | 한 칸을 다른 칸으로 계산하는 식 | `dp[i] = dp[i - 1] + dp[i - 2]` |
| 초기값 | 점화식 없이 바로 아는 칸 | `dp[1] = 1` · `dp[2] = 1` |
| 계산 순서 | 필요한 칸이 먼저 채워지는 순서 | 작은 `i`부터 큰 `i`로 |

**상태**는 가장 먼저 정해야 합니다.
한 칸이 무엇을 뜻하는지 한 문장으로 말할 수 없으면 점화식도 초기값도 맞출 수 없기 때문입니다.
**점화식**은 앞에서 구한 칸으로 지금 칸을 계산하는 규칙입니다.

![i번 칸은 바로 앞 두 칸의 합이라는 점화식 그림. 1번부터 6번 칸까지 1·1·2·3·5·8이 적혀 있고 4번 칸의 3과 5번 칸의 5에서 나온 화살표가 6번 칸으로 모여 3 더하기 5는 8이 된다.](content/assets/algorithm/dp-recurrence.png)

그림처럼 `dp[6]`을 채울 때는 바로 앞 두 칸만 있으면 됩니다.
그래서 계산 순서는 앞 칸이 먼저 준비되도록 작은 번호부터 채우는 순서가 됩니다.
**초기값**은 점화식으로 만들 수 없는 맨 앞 칸입니다.
`dp[1]`과 `dp[2]`를 먼저 적어 두지 않으면 `dp[3]`을 계산할 재료가 없습니다.

## 동적 계획법의 종류

DP는 표를 채우는 방향에 따라 두 가지로 나뉩니다.
큰 문제에서 출발해 필요한 작은 문제를 불러 내려가는 **메모이제이션**과 작은 문제부터 차례로 채워 올라가는 **타뷸레이션**입니다.
메모이제이션을 **하향식**이나 **탑다운**이라 부르고 타뷸레이션을 **상향식**이나 **바텀업**이라 부르기도 합니다.

![왼쪽은 메모이제이션으로 fib(5)에서 출발해 재귀로 내려가며 두 번째로 필요한 fib(3)은 memo에서 꺼내 호출이 7번으로 줄어든 트리. 오른쪽은 타뷸레이션으로 초기값인 1번과 2번 칸을 파란색으로 두고 3번부터 5번 칸까지 왼쪽에서 오른쪽으로 채우는 표](content/assets/algorithm/dp-memo-vs-table.png)

### 메모이제이션

메모이제이션은 앞의 재귀 함수에 메모 배열 하나를 더한 것입니다.
답을 구하면 `memo`에 적어 두고 다음에 같은 문제가 오면 계산하지 않고 적어 둔 값을 돌려줍니다.

```java
static long fibMemo(int n, long[] memo) {
    calls++;
    if (n <= 2) return 1;
    if (memo[n] != 0) return memo[n];
    memo[n] = fibMemo(n - 1, memo) + fibMemo(n - 2, memo);
    return memo[n];
}
```

피보나치 수는 0이 나오지 않으므로 `memo[n]`이 0이면 아직 구하지 않은 칸이라고 볼 수 있습니다.
이번에는 `fib(40)`의 호출 수가 어떻게 바뀔지 예상해 보세요.

```text
메모이제이션 fib(5) = 5 · 호출 7번
메모이제이션 fib(40) = 102334155 · 호출 77번
```

2억 번이 넘던 호출이 77번으로 줄었습니다.
부분 문제마다 계산은 한 번씩만 하고 두 번째부터는 `memo`에서 바로 꺼내기 때문입니다.

### 타뷸레이션

타뷸레이션은 재귀 없이 반복문으로 표를 앞에서부터 채웁니다.
초기값을 먼저 적고 점화식을 계산 순서대로 적용합니다.

```java
static long fibTable(int n) {
    if (n <= 2) return 1;
    long[] dp = new long[n + 1];
    dp[1] = 1;
    dp[2] = 1;
    for (int i = 3; i <= n; i++) {
        dp[i] = dp[i - 1] + dp[i - 2];
    }
    return dp[n];
}
```

```text
타뷸레이션 fib(40) = 102334155
```

반복문이 `n`번 돌기 때문에 시간 복잡도는 `O(n)`입니다.
메모이제이션도 부분 문제를 한 번씩만 풀므로 같은 `O(n)`입니다.

| | 메모이제이션 | 타뷸레이션 |
| --- | --- | --- |
| 방향 | 큰 문제에서 작은 문제로 내려갑니다 | 작은 문제에서 큰 문제로 올라갑니다 |
| 쓰는 도구 | 재귀 호출과 메모 배열 | 반복문과 DP 표 |
| 계산하는 칸 | 실제로 필요한 칸만 | 표의 모든 칸 |
| 주의할 점 | 재귀가 너무 깊으면 스택이 넘칩니다 | 계산 순서를 직접 정해야 합니다 |
| 잘 맞는 경우 | 점화식을 재귀로 떠올리기 쉬울 때 | 채우는 순서가 분명하고 입력이 클 때 |

코딩테스트에서는 채우는 순서가 분명하면 타뷸레이션을 많이 씁니다.
재귀 호출이 쌓이지 않아서 입력이 커도 스택이 넘칠 걱정이 없기 때문입니다.
Java에서 DP 표를 만들고 채우는 방법은 [Java로 DP 표 채우기](#/learn/algorithm/dp-java)에서 알아봅니다.

> [!note]- 전체 코드 보기
> 이 문서의 예제를 하나로 합친 프로그램입니다.
> `FibonacciDp.java`로 저장해 실행해 볼 수 있습니다.
>
> ```java
> public class FibonacciDp {
>     static long calls = 0;
>
>     static long fibPlain(int n) {
>         calls++;
>         if (n <= 2) return 1;
>         return fibPlain(n - 1) + fibPlain(n - 2);
>     }
>
>     static long fibMemo(int n, long[] memo) {
>         calls++;
>         if (n <= 2) return 1;
>         if (memo[n] != 0) return memo[n];
>         memo[n] = fibMemo(n - 1, memo) + fibMemo(n - 2, memo);
>         return memo[n];
>     }
>
>     static long fibTable(int n) {
>         if (n <= 2) return 1;
>         long[] dp = new long[n + 1];
>         dp[1] = 1;
>         dp[2] = 1;
>         for (int i = 3; i <= n; i++) {
>             dp[i] = dp[i - 1] + dp[i - 2];
>         }
>         return dp[n];
>     }
>
>     public static void main(String[] args) {
>         for (int n : new int[] {5, 40}) {
>             calls = 0;
>             long value = fibPlain(n);
>             System.out.println("그냥 재귀 fib(" + n + ") = " + value + " · 호출 " + calls + "번");
>         }
>         for (int n : new int[] {5, 40}) {
>             calls = 0;
>             long value = fibMemo(n, new long[n + 1]);
>             System.out.println("메모이제이션 fib(" + n + ") = " + value + " · 호출 " + calls + "번");
>         }
>         System.out.println("타뷸레이션 fib(40) = " + fibTable(40));
>     }
> }
> ```
>
> ```text
> 그냥 재귀 fib(5) = 5 · 호출 9번
> 그냥 재귀 fib(40) = 102334155 · 호출 204668309번
> 메모이제이션 fib(5) = 5 · 호출 7번
> 메모이제이션 fib(40) = 102334155 · 호출 77번
> 타뷸레이션 fib(40) = 102334155
> ```

## 동적 계획법의 활용

DP는 코딩테스트에서 아주 자주 나오는 유형입니다.
문제를 읽을 때 아래 같은 표현이 보이면 DP를 먼저 의심해 봅니다.

| 문제에 나오는 표현 | DP 상태와 점화식의 예 |
| --- | --- |
| ~하는 방법은 모두 몇 가지인가요 | `dp[i]`는 `i`까지 오는 방법의 수 |
| 가장 적은 비용·가장 큰 점수는 얼마인가요 | `dp[i]`는 `i`까지의 최소 비용이나 최대 점수 |
| 한 번에 한 칸 또는 두 칸처럼 선택지가 몇 개로 정해져 있습니다 | 마지막 선택마다 앞 칸의 답을 모아 `dp[i]`를 만듭니다 |

점화식을 세울 때는 **마지막 한 걸음**을 생각하면 쉽습니다.
지금 칸에 오기 직전에 어떤 상태였을 수 있는지 모두 적고 그 상태들의 답으로 지금 답을 만듭니다.

DP와 자주 비교되는 방법이 [그리디](#/learn/algorithm/heap-and-greedy)입니다.
그리디는 매 순간 가장 좋아 보이는 선택 하나만 하고 되돌아보지 않습니다.
반면 DP는 가능한 이전 상태를 모두 비교하므로 그리디가 틀리는 문제에서도 답을 찾습니다.
행과 열처럼 두 정보가 필요한 상태와 선택을 복원하는 방법은 [동적 계획법 2](#/learn/algorithm/dynamic-programming-advanced)에서 이어서 다룹니다.

## 정리

- 동적 계획법은 부분 문제의 답을 저장해 두고 다시 꺼내 써서 중복 호출을 없앱니다.
- 겹치는 부분 문제와 최적 부분 구조가 함께 있을 때 DP를 씁니다.
- 상태·점화식·초기값·계산 순서를 정한 뒤 코드를 씁니다.
- 메모이제이션은 재귀로 위에서 아래로 내려가고 타뷸레이션은 반복문으로 아래에서 위로 채웁니다.

## 핵심 질문 답
