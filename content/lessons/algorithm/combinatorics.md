## 경우의 수란

**경우의 수**는 어떤 일이 일어날 수 있는 방법이 모두 몇 가지인지를 센 값입니다.
코딩테스트에서는 가능한 경우를 모두 만들어 볼지 판단할 때와 답 자체가 개수일 때 필요합니다.
경우가 너무 많으면 하나씩 만들어 보는 풀이는 시간 안에 끝나지 않기 때문입니다.

예를 들어 민지·도윤·서아·하준·지우 다섯 명이 알고리즘 스터디를 한다고 해 보겠습니다.
이 문서는 이 스터디 다섯 명으로 끝까지 설명합니다.
발표자를 뽑는 일·청소 당번을 정하는 일·발표 순서를 정하는 일이 모두 경우의 수를 세는 일입니다.

## 합의 법칙과 곱의 법칙

경우의 수를 세는 규칙은 두 가지에서 시작합니다.
오늘 발표 주제로 자료구조 주제 3개(배열·스택·큐)와 알고리즘 주제 2개(정렬·그리디)가 준비되어 있다고 해 보겠습니다.

![왼쪽은 자료구조 주제 3개 또는 알고리즘 주제 2개 중 하나만 고르는 합의 법칙으로 3 더하기 2는 5가지이고 오른쪽은 자료구조 주제 하나와 알고리즘 주제 하나를 짝지어 고르는 곱의 법칙으로 3 곱하기 2 격자에 6가지 짝이 채워져 있다.](content/assets/algorithm/math-comb-sum-product.png)

주제를 하나만 고른다면 자료구조에서 고르거나 알고리즘에서 고릅니다.
두 경우는 동시에 일어나지 않으므로 더해서 `3 + 2 = 5`가지입니다.
이것이 **합의 법칙**입니다.

반면 자료구조 주제 하나와 알고리즘 주제 하나를 모두 고른다면 이야기가 달라집니다.
자료구조 주제 3개 각각에 알고리즘 주제 2개를 짝지을 수 있으므로 `3 × 2 = 6`가지입니다.
이것이 **곱의 법칙**입니다.

구분하는 기준은 한 문장입니다.
`또는`으로 이어지면 더하고 `그리고`로 이어지면 곱합니다.
뒤에서 볼 순열과 조합은 모두 이 곱의 법칙에서 나옵니다.

## 순열과 팩토리얼

이제 다섯 명 중에서 발표자 한 명과 서기 한 명을 뽑아 보겠습니다.
발표자를 먼저 고르면 5가지이고 남은 네 명 중 서기를 고르면 4가지입니다.
곱의 법칙으로 `5 × 4 = 20`가지입니다.

이렇게 `n`개 중에서 `r`개를 골라 **순서 있게** 늘어놓는 경우의 수를 **순열**이라고 하고 `nPr`로 씁니다.
발표자가 민지이고 서기가 도윤인 경우와 그 반대는 역할이 다르므로 서로 다른 경우입니다.

`nPr = n × (n - 1) × … × (n - r + 1)`

다섯 명 전원의 발표 순서를 정하면 `5 × 4 × 3 × 2 × 1 = 120`가지입니다.
이렇게 1부터 `n`까지 모두 곱한 값을 **팩토리얼**이라고 하고 `n!`로 씁니다.
팩토리얼을 쓰면 순열을 `nPr = n! / (n - r)!`로 짧게 쓸 수 있습니다.
`0!`은 1로 정합니다.
그래야 다섯 명 전원을 줄 세우는 `5P5 = 5! / 0!`도 120으로 맞기 때문입니다.

## 조합

이번에는 다섯 명 중 청소 당번 두 명을 뽑아 보겠습니다.
청소 당번은 역할 구분이 없으므로 민지·도윤과 도윤·민지는 같은 경우입니다.
이렇게 `n`개 중에서 `r`개를 **순서 없이** 고르는 경우의 수를 **조합**이라고 하고 `nCr`로 씁니다.

순열과 조합의 차이는 표로 그려 보면 바로 보입니다.

![다섯 명을 행과 열에 놓은 5×5 표. 자기 자신과 짝짓는 대각선을 빼면 20칸이 남는데 이것이 발표자와 서기를 뽑는 순열 20가지다. 대각선 위쪽 10칸은 초록이고 이것이 청소 당번 두 명을 뽑는 조합 10가지다. 아래쪽 보라 10칸은 같은 두 명을 순서만 바꾼 것이다.](content/assets/algorithm/math-comb-perm-grid.png)

순열 20칸 중에서 같은 두 사람이 순서만 바꿔 두 번씩 나옵니다.
두 사람을 늘어놓는 순서는 `2!`가지이므로 순열을 `2!`로 나누면 조합이 됩니다.
그래서 `5C2 = 20 / 2 = 10`입니다.

`nCr = nPr / r! = n! / (r! × (n - r)!)`

조합에는 기억해 둘 성질이 하나 있습니다.
두 명을 당번으로 뽑는 일은 남을 세 명을 뽑는 일과 같습니다.
그래서 `5C2`와 `5C3`은 둘 다 10이고 일반적으로 `nCr = nC(n - r)`입니다.

| 뽑는 방식 | 순서 | 공식 | 스터디 예 | 값 |
| --- | --- | --- | --- | --- |
| 순열 | 중요함 | `n! / (n - r)!` | 발표자와 서기 | `5P2 = 20` |
| 조합 | 상관없음 | `n! / (r! × (n - r)!)` | 청소 당번 두 명 | `5C2 = 10` |
| 팩토리얼 | 전원을 줄 세움 | `n!` | 다섯 명의 발표 순서 | `5! = 120` |

공식은 개수를 셀 뿐이고 실제 경우를 하나씩 만들어 주지는 않습니다.
발표자와 서기 짝 20가지를 실제로 하나씩 만들어 확인하는 방법은 [Java로 순열·조합 만들기](#/learn/algorithm/permutations-combinations-java)에서 다룹니다.
경우의 수로 먼저 개수를 세어 보면 그 풀이가 시간 안에 끝날지 판단할 수 있습니다.

## 파스칼의 삼각형

공식으로 조합을 구하면 팩토리얼이 금방 커지는 문제가 있습니다.
`30!`은 33자리 수라서 `long`에도 담기지 않습니다.
그런데 `30C15`는 155,117,520으로 `int`에도 담기는 크기입니다.
중간 계산만 너무 커지는 것입니다.

이때 곱셈 대신 덧셈으로 조합을 구하는 방법이 있습니다.
청소 당번 두 명을 뽑을 때 지우를 기준으로 경우를 둘로 나눠 보겠습니다.

- 지우가 뽑히면 나머지 네 명 중 한 명만 더 뽑으면 되므로 `4C1 = 4`가지입니다.
- 지우가 뽑히지 않으면 나머지 네 명 중 두 명을 뽑아야 하므로 `4C2 = 6`가지입니다.

두 경우는 동시에 일어나지 않으므로 합의 법칙으로 더해 `5C2 = 4 + 6 = 10`입니다.
일반적으로 쓰면 `nCr = (n-1)C(r-1) + (n-1)Cr`입니다.
이 식을 윗줄부터 채워 나간 표가 **파스칼의 삼각형**입니다.

![파스칼의 삼각형 0행부터 5행까지. 각 줄의 양 끝은 1이고 안쪽 수는 바로 위 두 수의 합이다. 4행의 4와 6이 화살표로 5행의 10으로 이어지며 4C1 더하기 4C2가 5C2라는 것을 보여 준다.](content/assets/algorithm/math-comb-pascal.png)

맨 윗줄을 0행으로 세고 각 줄의 왼쪽 끝을 0번째로 세면 `n`행의 `r`번째 수가 `nCr`입니다.
줄의 양 끝은 하나도 안 뽑거나 모두 뽑는 경우라서 늘 1입니다.
안쪽 수는 바로 위 두 수를 더해서 채웁니다.

코드로 옮기면 2차원 배열을 윗줄부터 채우는 반복문입니다.
앞의 수로 다음 수를 채우는 이 방식은 [동적 계획법](#/learn/algorithm/binary-search-and-dynamic-programming)과 같은 모양입니다.

```java
static long[][] pascal(int n) {
    long[][] c = new long[n + 1][n + 1];
    for (int i = 0; i <= n; i++) {
        c[i][0] = 1;
        c[i][i] = 1;
        for (int j = 1; j < i; j++) {
            c[i][j] = c[i - 1][j - 1] + c[i - 1][j];
        }
    }
    return c;
}
```

`pascal(30)`으로 `30C15`를 구하고 팩토리얼 공식으로도 구하면 두 값이 같을지 예상해 보세요.

```text
파스칼 30C15 = 155117520
공식 30C15 = -54279
30! = -8764578968847253504
```

파스칼의 삼각형은 덧셈만 하므로 정확한 값이 나옵니다.
반면 공식은 중간값인 `30 × 29 × … × 16`이 `long` 범위를 넘어 엉뚱한 음수가 나왔습니다.
`30!`도 마찬가지로 범위를 넘어 음수로 바뀌었습니다.
삼각형은 칸이 약 `n²`개라서 시간과 메모리가 `O(n²)`이고 `n`이 1,000 정도까지면 충분히 빠릅니다.

> [!question]- 답을 1,000,000,007로 나눈 나머지로 구하라면?
> 파스칼의 삼각형은 덧셈만 하므로 칸을 채울 때마다 1,000,000,007로 나눈 나머지만 남기면 됩니다.
> 덧셈은 중간에 나머지를 구해도 결과가 같기 때문입니다.
>
> `n`이 1만을 넘으면 칸이 1억 개가 넘어서 표를 만들기 어렵습니다.
> 이때는 팩토리얼을 나머지로 미리 구해 두고 나눗셈 대신 역원을 곱합니다.
> 이 방법은 [빠른 거듭제곱](#/learn/algorithm/fast-power)에서 다룹니다.

Java에서 쓰는 방법과 범위를 넘지 않게 계산하는 방법은 [Java로 정수 계산하기](#/learn/algorithm/integer-java)에서 알아봅니다.

> [!note]- 전체 코드 보기
> 이 문서의 예제를 하나로 합친 프로그램입니다.
> `StudyCounting.java`로 저장해 실행해 볼 수 있습니다.
>
> ```java
> public class StudyCounting {
>     static long factorial(int n) {
>         long result = 1;
>         for (int i = 2; i <= n; i++) {
>             result *= i;
>         }
>         return result;
>     }
>
>     static long permutation(int n, int r) {
>         long result = 1;
>         for (int i = 0; i < r; i++) {
>             result *= n - i;
>         }
>         return result;
>     }
>
>     static long combination(int n, int r) {
>         return permutation(n, r) / factorial(r);
>     }
>
>     static long[][] pascal(int n) {
>         long[][] c = new long[n + 1][n + 1];
>         for (int i = 0; i <= n; i++) {
>             c[i][0] = 1;
>             c[i][i] = 1;
>             for (int j = 1; j < i; j++) {
>                 c[i][j] = c[i - 1][j - 1] + c[i - 1][j];
>             }
>         }
>         return c;
>     }
>
>     public static void main(String[] args) {
>         System.out.println("합의 법칙: " + (3 + 2));
>         System.out.println("곱의 법칙: " + 3 * 2);
>         System.out.println("5! = " + factorial(5));
>         System.out.println("5P2 = " + permutation(5, 2));
>         System.out.println("5C2 = " + combination(5, 2));
>         System.out.println("5C3 = " + combination(5, 3));
>
>         long[][] c = pascal(30);
>         System.out.println("파스칼 5C2 = " + c[5][2]);
>         System.out.println("파스칼 30C15 = " + c[30][15]);
>         System.out.println("공식 30C15 = " + combination(30, 15));
>         System.out.println("30! = " + factorial(30));
>     }
> }
> ```
>
> ```text
> 합의 법칙: 5
> 곱의 법칙: 6
> 5! = 120
> 5P2 = 20
> 5C2 = 10
> 5C3 = 10
> 파스칼 5C2 = 10
> 파스칼 30C15 = 155117520
> 공식 30C15 = -54279
> 30! = -8764578968847253504
> ```

## 경우의 수의 활용

코딩테스트에서는 문제의 말을 보고 어떤 공식을 쓸지 고릅니다.

| 문제에 나오는 말 | 고를 공식 |
| --- | --- |
| A 또는 B 중 하나 | 합의 법칙 |
| A를 고르고 이어서 B를 고름 | 곱의 법칙 |
| 줄 세우기·자리 배치·역할이 다른 선택 | 순열 `nPr`·팩토리얼 `n!` |
| 팀 뽑기·부분집합 고르기 | 조합 `nCr` |
| 격자에서 오른쪽과 아래로만 가는 길의 수 | 조합 또는 파스칼의 삼각형 |

경우의 수는 완전 탐색을 쓸지 정하는 데도 씁니다.
예를 들어 10명 중 5명을 뽑는 조합은 `10C5 = 252`가지라서 모두 만들어 봐도 금방 끝납니다.
10명을 줄 세우는 순열도 `10! = 3,628,800`가지라서 아직 만들어 볼 만합니다.
반면 15명을 줄 세우면 `15! = 1,307,674,368,000`가지라서 시간 안에 끝나지 않습니다.

## 정리

- `또는`으로 이어지는 경우는 더하는 합의 법칙으로 세고 `그리고`로 이어지는 경우는 곱하는 곱의 법칙으로 셉니다.
- 순서가 중요하면 순열 `nPr = n! / (n - r)!`로 세고 순서가 상관없으면 조합 `nCr = nPr / r!`로 셉니다.
- 파스칼의 삼각형은 `nCr = (n-1)C(r-1) + (n-1)Cr`을 덧셈으로 채워서 팩토리얼이 넘치는 문제를 피합니다.
- 경우의 수로 개수를 먼저 세면 하나씩 만들어 보는 풀이가 시간 안에 끝날지 알 수 있습니다.

## 핵심 질문 답

동시에 일어날 수 없는 경우는 더하고 이어서 일어나는 경우는 곱해서 경우의 수를 셉니다.
`n`개 중 `r`개를 순서 있게 늘어놓으면 순열 `n! / (n - r)!`이고 순서 없이 고르면 조합 `n! / (r! × (n - r)!)`입니다.
조합은 팩토리얼의 중간값이 쉽게 넘치므로 코딩테스트에서는 파스칼의 삼각형으로 위 두 수를 더해서 구합니다.
공식은 개수만 세고 실제 경우를 하나씩 만드는 일은 백트래킹이 맡습니다.
