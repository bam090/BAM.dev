## 자료구조와 알고리즘이란

**자료구조**는 데이터를 어떤 모양으로 담고 꺼낼지 정한 방식입니다.
**알고리즘**은 그 데이터로 문제를 푸는 절차입니다.

두 가지는 늘 함께 움직입니다.
같은 문제라도 데이터를 어떤 자료구조에 담느냐에 따라 쓸 수 있는 알고리즘이 달라지고 풀리는 속도도 달라지기 때문입니다.
그래서 코딩테스트를 준비할 때는 자료구조와 알고리즘을 한 묶음으로 배웁니다.

예를 들어 스터디 모임의 출석부에서 `지우`라는 이름이 있는지 확인한다고 해 보겠습니다.
이 문서는 이 출석부 하나로 끝까지 설명합니다.

![왼쪽은 배열에 담긴 다섯 이름을 처음부터 하나씩 비교해 다섯 번째에 지우를 찾는 모습이고 오른쪽은 해시가 지우라는 이름으로 칸 번호를 바로 계산해 한 번에 찾는 모습](content/assets/algorithm/algo0-search-compare.png)

이름을 배열에 담았다면 처음부터 하나씩 비교해야 합니다.
반면 해시라는 자료구조에 담았다면 이름으로 저장된 칸을 바로 계산해서 찾습니다.
코드로 보면 다음과 같습니다.

```java
String[] members = {"민지", "도윤", "서아", "하준", "지우"};

int checks = 0;
for (String member : members) {
    checks++;
    if (member.equals("지우")) break;
}
System.out.println("배열: " + checks + "번 비교");

Set<String> attendance = new HashSet<>(List.of(members));
System.out.println("해시: " + attendance.contains("지우"));
```

배열에서 `지우`를 찾으려면 몇 번 비교해야 할지 먼저 세어 보세요.

```text
배열: 5번 비교
해시: true
```

지금은 다섯 명이라 차이가 작습니다.
하지만 출석부에 10만 명이 있다면 배열은 최대 10만 번을 비교해야 하고 해시는 여전히 거의 한 번에 찾습니다.
어떤 자료구조를 고르느냐가 곧 풀이의 속도를 정하는 셈입니다.

## 이 과정에서 배울 자료구조와 알고리즘

알고리즘 과정은 아래 순서로 자료구조와 알고리즘을 하나씩 익힙니다.
지금 모두 외울 필요는 없고 어떤 문제에 쓰는지만 가볍게 훑어보세요.

| 번호 | 키워드 | 이럴 때 씁니다 |
| --- | --- | --- |
| 1 | 배열 | 값을 순서대로 담고 번호로 꺼낼 때 |
| 2 | 스택 | 가장 나중에 넣은 것부터 꺼낼 때 |
| 3 | 큐 | 먼저 들어온 것부터 차례로 처리할 때 |
| 4 | 해시 | 이름이나 키로 값을 바로 찾을 때 |
| 5 | 트리 | 계층을 표현하거나 정렬된 순서를 유지할 때 |
| 6 | 집합 | 서로 연결된 그룹을 합치고 찾을 때 |
| 7 | 그래프 | 지점과 지점 사이의 연결과 경로를 다룰 때 |
| 8 | 백트래킹 | 가능한 경우를 모두 시도해 봐야 할 때 |
| 9 | 정렬 | 값을 크기 순서로 늘어놓을 때 |
| 10 | 시뮬레이션 | 문제에 적힌 규칙을 그대로 따라 할 때 |
| 11 | 동적 계획법 | 작은 문제의 답을 모아 큰 문제를 풀 때 |
| 12 | 그리디 | 매 순간 가장 좋은 선택을 해도 답이 될 때 |
| 13 | 수학 | 나머지·약수·경우의 수 같은 계산이 필요할 때 |

어떤 것을 고를지 판단하는 기준이 바로 다음 절의 시간 복잡도입니다.

## 시간 복잡도

**시간 복잡도**는 입력의 크기가 커질 때 실행해야 하는 연산 횟수가 얼마나 빨리 늘어나는지를 나타낸 것입니다.
실제 실행 시간을 초로 재지 않는 이유는 같은 코드라도 컴퓨터마다 걸리는 시간이 다르기 때문입니다.
대신 입력 크기를 `n`이라고 두고 연산 횟수를 `n`에 대한 식으로 나타냅니다.

앞의 출석부로 보면 배열에서 이름을 찾는 일은 사람이 `n`명일 때 최대 `n`번 비교합니다.
이것을 **빅오 표기**로 `O(n)`이라고 씁니다.
빅오 표기는 `n`이 아주 커졌을 때 가장 크게 늘어나는 부분만 남기고 나머지는 지웁니다.
예를 들어 연산 횟수가 `3n + 5`번이라면 `n`이 커질수록 `3`과 `5`는 별 차이를 만들지 못하므로 `O(n)`으로 씁니다.

### 시간 복잡도의 종류

코딩테스트에서 자주 만나는 복잡도는 여섯 가지입니다.
위에서 아래로 갈수록 느립니다.

| 표기 | 읽는 법 | 이런 코드에서 나옵니다 | n = 1,000일 때 대략 |
| --- | --- | --- | --- |
| `O(1)` | 상수 시간 | 배열의 번호로 바로 꺼내기·해시에서 찾기 | 1번 |
| `O(log n)` | 로그 시간 | 범위를 매번 절반으로 줄이며 찾기 | 10번 |
| `O(n)` | 선형 시간 | 배열을 처음부터 끝까지 한 번 훑기 | 1,000번 |
| `O(n log n)` | 선형 로그 시간 | 효율적인 정렬 | 10,000번 |
| `O(n²)` | 제곱 시간 | 반복문 안에 반복문 | 1,000,000번 |
| `O(2ⁿ)` | 지수 시간 | 모든 부분집합 만들어 보기 | 셀 수 없이 많음 |

그래프로 그려 보면 차이가 더 분명해집니다.

![입력 크기 n이 커질 때 연산 횟수가 늘어나는 곡선. O(1)과 O(log n)은 거의 바닥에 붙어 있고 O(n)은 완만하게 오르며 O(n log n)은 더 가파르게 오르고 O(n²)은 금방 그래프 위로 벗어난다](content/assets/algorithm/algo0-growth.png)

잠깐 생각해 보세요.
`n`이 10배 커지면 `O(n²)` 코드의 연산 횟수는 몇 배가 될까요?
`n × n`이므로 10 × 10 = 100배가 됩니다.
그래서 `O(n²)` 풀이는 입력이 작을 때는 괜찮다가 입력이 커지면 갑자기 시간 안에 끝나지 않습니다.

## 공간 복잡도

**공간 복잡도**는 입력이 커질 때 추가로 필요한 메모리가 얼마나 늘어나는지를 나타냅니다.
표기 방법은 시간 복잡도와 같습니다.

출석부를 해시에 담으면 이름을 빨리 찾는 대신 사람 수만큼 해시를 만들 메모리가 더 필요합니다.
즉 공간 복잡도 `O(n)`을 쓰고 시간 복잡도를 `O(n)`에서 `O(1)`로 줄인 것입니다.
이렇게 메모리를 조금 더 써서 시간을 줄이는 선택은 코딩테스트에서 아주 흔합니다.
다만 코딩테스트는 보통 시간 제한이 먼저 문제가 되므로 이 과정에서는 시간 복잡도를 중심으로 봅니다.

## 코딩테스트에서 고르는 순서

코딩테스트 문제를 받으면 코드를 쓰기 전에 아래 순서로 생각합니다.

1. 문제의 입력 크기(`n`의 최댓값)와 시간 제한을 확인합니다.
2. 그 크기에서 시간 안에 끝나는 시간 복잡도가 무엇인지 가늠합니다.
3. 그 복잡도를 낼 수 있는 자료구조와 알고리즘을 고릅니다.
4. 코드를 작성하고 작은 예제로 결과를 확인합니다.

예를 들어 출석부에 최대 10만 명이 있고 이름 확인을 10만 번 해야 한다면 배열로 매번 훑는 풀이는 10만 × 10만 번을 비교합니다.
해시에 담아 두면 확인 한 번이 거의 한 번의 연산이라 전체가 10만 번 정도로 끝납니다.
입력 크기별로 어느 복잡도까지 괜찮은지와 코드에서 복잡도를 세는 방법은 [코드에서 시간 복잡도 계산하기](#/learn/algorithm/time-complexity-in-code)에서 자세히 알아봅니다.

## 정리

- 자료구조는 데이터를 담는 방식이고 알고리즘은 그 데이터로 문제를 푸는 절차입니다.
- 시간 복잡도는 입력이 커질 때 연산 횟수가 늘어나는 정도이고 빅오 표기로 가장 크게 늘어나는 부분만 씁니다.
- `O(1)` → `O(log n)` → `O(n)` → `O(n log n)` → `O(n²)` → `O(2ⁿ)` 순서로 느려집니다.
- 코딩테스트에서는 입력 크기로 필요한 복잡도를 먼저 정하고 그에 맞는 자료구조와 알고리즘을 고릅니다.
