# HTML 개념을 요구사항에 연결하기

## 학습 목표

새 요구사항에서 내용·관계·요소 선택 이유를 표시하고 구현 뒤 검사 계획을 세울 수 있습니다.

## 한줄 요약

내용 목록 → 제목과 큰 구조 → 정보 관계 → 입력 흐름 → 문법·의미·접근성 점검 순서로 요구사항을 연결합니다.

## 먼저 확인할 개념

[HTML 검증: 문법·의미·접근성 점검](#/learn/html/wiki-inspection)의 관계를 알고 있으면 이 문서를 읽기 쉽습니다.

## 코드를 쓰기 전의 여섯 단계

1. 요구사항에 등장한 내용을 빠짐없이 목록으로 만든다.
2. 페이지 대표 제목과 하위 제목의 관계를 정한다.
3. 페이지 소개·주요 이동·중심 내용·보조 내용·마무리를 나눈다.
4. 링크·이미지·목록·표가 맡은 정보 관계를 찾는다.
5. 입력받을 값과 제출할 이름, 검증 조건을 찾는다.
6. 구현 뒤에 문법 검사와 의미·접근성 점검을 따로 계획한다.

이 순서를 사용하면 디자인의 네모 상자를 모두 `div`로 옮기는 일을 줄일 수 있다.
`div`가 틀린 것이 아니라, 먼저 표현할 수 있는 정보 관계를 놓치지 않는 것이 목적이다.

디자인에 보이는 상자 하나가 HTML 요소 하나와 반드시 대응하지는 않는다.
알맞은 의미 요소가 없다면 `div`와 `span`으로 필요한 내용을 묶을 수 있다.

## 예시 요구사항 읽기

다음은 Markdown으로 작성한 페이지 요구사항 메모다.

> `별빛 주민센터 가을 행사` 안내 페이지를 만든다. 소개와 일정으로 바로 이동하는 메뉴가 있다. 행사 포스터와 준비물을 보여 준다. 날짜·행사·장소는 표로 정리한다. 이름과 이메일을 받아 참가 신청을 보낸다. 마지막에는 주민센터 문의 정보를 적는다.

요구사항을 바로 코드로 바꾸지 않고 표시한다.

| 찾은 정보 | 관계 | 선택 후보와 이유 |
| --- | --- | --- |
| 별빛 주민센터 가을 행사 | 페이지 대표 제목 | 본문의 `h1` |
| 소개, 일정 | 주요 이동 | `nav` 안의 문서 내부 링크 |
| 행사 안내 전체 | 현재 문서의 중심 내용 | `main` |
| 소개, 준비물, 일정, 참가 신청 | 서로 다른 주제 | 제목이 있는 `section` |
| 행사 포스터 | 정보를 전하는 이미지 | 목적에 맞는 `alt`가 있는 `img` |
| 준비물 | 순서가 중요하지 않은 항목 | `ul` |
| 날짜·행사·장소 | 행과 열의 관계 | `table`, `caption`, `th`, `td` |
| 이름·이메일 | 사용자가 입력할 값 | 연결된 `label`, `input`, `name` |
| 신청 보내기 | 현재 폼을 제출하는 행동 | `<button type="submit">` |
| 문의 정보 | 페이지 마무리 | `footer` |

다른 구조도 타당할 수 있다.
예를 들어 각 행사가 페이지 밖에서도 독립적으로 배포되는 소식이라면 `article`을 검토할 수 있다.
중요한 것은 요소 이름 하나를 정답처럼 외우는 것이 아니라 선택 이유를 요구사항에서 찾는 일이다.

## 분석한 결과를 HTML로 연결하기

문서 기본 골격은 [HTML 문서의 기본 골격](#/learn/html/wiki-document-skeleton)에서 확인했으므로, 여기서는 요구사항에 따라 달라지는 `body` 구조만 짧게 본다.

```html
<header>
  <h1>별빛 주민센터 가을 행사</h1>
  <nav>
    <a href="#intro">행사 소개</a>
    <a href="#schedule">행사 일정</a>
  </nav>
</header>

<main>
  <section id="intro">
    <h2>행사 소개</h2>
    <img
      src="images/autumn-event.jpg"
      alt="주민들이 화분과 책을 나누는 가을 행사"
      width="640"
      height="360"
    >
    <h3>준비물</h3>
    <ul>
      <li>개인 물병</li>
      <li>나누고 싶은 책 한 권</li>
    </ul>
  </section>

  <section id="schedule">
    <h2>행사 일정</h2>
    <table>
      <caption>2026년 가을 행사 시간표</caption>
      <tr>
        <th scope="col">시간</th>
        <th scope="col">행사</th>
        <th scope="col">장소</th>
      </tr>
      <tr>
        <th scope="row">오전 10시</th>
        <td>화분 나눔</td>
        <td>앞마당</td>
      </tr>
    </table>
  </section>

  <section>
    <h2>참가 신청</h2>
    <p>이름과 이메일은 모두 필수입니다.</p>
    <form action="/event-applications" method="post">
      <label for="participant-name">이름 (필수)</label>
      <input id="participant-name" name="participantName" type="text" required>
      <label for="participant-email">이메일 (필수)</label>
      <input id="participant-email" name="email" type="email" required>
      <button type="submit">신청 보내기</button>
    </form>
  </section>
</main>

<footer>
  <p>문의: 별빛 주민센터 02-0000-0000</p>
</footer>
```

이 코드는 다음 연결을 한 번에 보여 준다.

`요구사항 → 제목과 큰 구조 → 정보 관계에 맞는 요소 → 폼의 제출 흐름 → 검사할 문서`

가상 이미지 파일과 `/event-applications` 주소는 구조 설명용이다.
실제 파일 로딩과 서버 제출을 완료했다고 뜻하지 않는다.

## 마지막 검사는 두 갈래로 나눈다

### 자동으로 빠르게 찾을 것

Nu HTML Checker로 다음을 확인한다.

- 태그와 속성 문법
- 허용되지 않는 중첩
- 필요한 일부 문서 정보와 속성
- 브라우저가 예상과 다르게 해석할 수 있는 구조

### 사람이 문맥과 사용으로 확인할 것

- `title`과 `h1`이 페이지를 알맞게 설명하는가?
- 제목 단계가 내용 관계를 따르는가?
- `nav`는 주요 이동을, `main`은 중심 내용을 나타내는가?
- 링크 문구만 읽어도 목적지를 알 수 있는가?
- 정보를 전하는 포스터라면 보지 않아도 `alt`와 주변 글을 통해 빠지는 핵심 정보가 없는가?
- 표 머리글이 행과 열의 데이터를 알맞게 설명하는가?
- 사용자가 조작하고 제출할 입력에 레이블과 `name`이 있고 오류를 고칠 방법을 알 수 있는가?
- 키보드만으로 링크·입력·제출을 순서대로 사용할 수 있는가?

Checker 통과와 의미·접근성 확인은 서로 대신하지 않는다.

Checker 오류가 0개여도 접근성 확인이나 학습 숙달까지 끝났다는 뜻은 아니다.

## 막혔을 때 돌아갈 질문

| 막힌 곳 | 다시 물을 질문 | 돌아갈 문서 |
| --- | --- | --- |
| 큰 구조를 못 정함 | 이 내용은 소개·이동·중심·보조·마무리 중 무엇인가? | [시맨틱 HTML: 내용의 역할과 제목 계층](#/learn/html/wiki-semantic-structure) |
| 링크·목록·표를 못 고름 | 사용 결과와 항목 사이의 관계는 무엇인가? | [링크와 버튼](#/learn/html/wiki-links-buttons) · [목록](#/learn/html/wiki-lists) · [표](#/learn/html/wiki-tables) |
| 폼 속성이 헷갈림 | 사람에게 보이는 질문과 서버에 보낼 이름은 무엇인가? | [입력의 레이블과 제출 이름](#/learn/html/wiki-input-names) |
| 검사 결과를 못 나눔 | 도구가 찾을 문법인가, 사람이 볼 의미·이용 문제인가? | [HTML 검증: 문법·의미·접근성 점검](#/learn/html/wiki-inspection) |

## 핵심 질문 답

내용을 빠짐없이 목록으로 만들고 대표/하위 제목, 소개·이동·중심·보조·마무리를 나눕니다.
링크·이미지·목록·표의 관계와 입력값·제출 이름·조건을 찾고 각 요소를 고른 이유를 요구사항의 말로 설명합니다.
구현 뒤에는 Checker의 문법 검사와 사람이 하는 의미·접근성 점검을 나누어 진행합니다.
다른 구조도 타당할 수 있고 검사 통과는 숙달의 증명이 아닙니다.
