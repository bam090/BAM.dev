# HTML 개념을 요구사항에 연결하기

## 학습 목표

- 요구사항에서 내용·제목·정보 관계를 찾아 HTML 요소를 선택할 수 있습니다.
- 이미지·목록·표·폼을 하나의 페이지 구조로 연결할 수 있습니다.
- 구현 뒤 문법 검사와 의미·접근성 점검을 나누어 계획할 수 있습니다.

## 선수 개념

[HTML 검증: 문법·의미·접근성 점검](#/learn/html/wiki-inspection)의 관계를 알고 있으면 이 문서를 읽기 쉽습니다.

## 요구사항과 HTML의 관계

요구사항은 페이지가 전달할 내용과 사용자가 수행할 행동을 설명한 조건입니다.
앞 문서에서는 HTML의 문법·의미·접근성을 나누어 점검했습니다.
이제 같은 밤마을 책모임 페이지에서 요구사항을 요소 선택과 점검 계획까지 연결합니다.

## 요구사항 분석의 여섯 단계

1. 요구사항에 등장한 내용을 빠짐없이 목록으로 만듭니다.
2. 페이지 대표 제목과 하위 제목의 관계를 정합니다.
3. 페이지 소개·주요 이동·중심 내용·보조 내용·마무리를 나눕니다.
4. 링크·이미지·목록·표가 맡은 정보 관계를 찾습니다.
5. 입력받을 값과 제출할 이름, 검증 조건을 찾습니다.
6. 구현 뒤에 문법 검사와 의미·접근성 점검을 따로 계획합니다.

이 순서를 사용하면 디자인의 네모 상자를 모두 `div`로 옮기는 일을 줄일 수 있습니다.
`div`가 틀린 것이 아니라, 먼저 표현할 수 있는 정보 관계를 놓치지 않는 것이 목적입니다.

디자인에 보이는 상자 하나가 HTML 요소 하나와 반드시 대응하지는 않습니다.
알맞은 의미 요소가 없다면 `div`와 `span`으로 필요한 내용을 묶을 수 있습니다.

이 순서를 실제 책모임 페이지의 요구사항에 적용합니다.

## 책모임 안내 페이지의 요구사항

다음은 Markdown으로 작성한 페이지 요구사항 메모입니다.

> `밤마을 책모임` 안내 페이지를 만듭니다.
> 소개와 일정으로 바로 이동하는 메뉴가 있습니다.
> 책모임 포스터와 준비물을 보여 줍니다.
> 날짜와 시간·모임·장소는 표로 정리합니다.
> 이름과 이메일을 받아 참가 신청을 보냅니다.
> 마지막에는 책모임 문의 정보를 적습니다.

요구사항을 바로 코드로 바꾸지 않고 표시합니다.

| 찾은 정보 | 관계 | 선택 후보와 이유 |
| --- | --- | --- |
| 밤마을 책모임 | 페이지 대표 제목 | 본문의 `h1` |
| 소개, 일정 | 주요 이동 | `nav` 안의 문서 내부 링크 |
| 모임 안내 전체 | 현재 문서의 중심 내용 | `main` |
| 소개, 준비물, 일정, 참가 신청 | 서로 다른 주제 | 제목이 있는 `section` |
| 책모임 포스터 | 정보를 전하는 이미지 | 목적에 맞는 `alt`가 있는 `img` |
| 준비물 | 순서가 중요하지 않은 항목 | `ul` |
| 날짜와 시간·모임·장소 | 행과 열의 관계 | `table`, `caption`, `th`, `td` |
| 이름·이메일 | 사용자가 입력할 값 | 연결된 `label`, `input`, `name` |
| 신청 보내기 | 현재 폼을 제출하는 행동 | `<button type="submit">` |
| 문의 정보 | 페이지 마무리 | `footer` |

다른 구조도 타당할 수 있습니다.
예를 들어 각 모임이 페이지 밖에서도 독립적으로 배포되는 소식이라면 `article`을 검토할 수 있습니다.
중요한 것은 요소 이름 하나를 정답처럼 외우는 것이 아니라 선택 이유를 요구사항에서 찾는 일입니다.

## 요구사항과 HTML의 연결

문서 기본 골격은 [HTML 시작하기: 요소와 문서의 기본 골격](#/learn/html/wiki-markup)에서 확인했으므로 여기서는 요구사항에 따라 달라지는 `body` 구조만 짧게 봅니다.

```html
<header>
  <h1>밤마을 책모임</h1>
  <nav>
    <a href="#intro">모임 소개</a>
    <a href="#schedule">모임 일정</a>
  </nav>
</header>

<main>
  <section id="intro">
    <h2>모임 소개</h2>
    <img
      src="images/reading-club-poster.jpg"
      alt="9월 20일 오후 7시 별빛도서관에서 열리는 밤마을 책모임"
      width="640"
      height="360"
    >
    <h3>준비물</h3>
    <ul>
      <li>개인 물병</li>
      <li>나누고 싶은 책 한 권</li>
    </ul>
  </section>

  <section id="schedule">
    <h2>모임 일정</h2>
    <table>
      <caption>2026년 밤마을 책모임 일정</caption>
      <tr>
        <th scope="col">날짜와 시간</th>
        <th scope="col">모임</th>
        <th scope="col">장소</th>
      </tr>
      <tr>
        <th scope="row">9월 20일 오후 7시</th>
        <td>책 이야기</td>
        <td>별빛도서관 모임방</td>
      </tr>
    </table>
  </section>

  <section>
    <h2>참가 신청</h2>
    <p>이름과 이메일은 모두 필수입니다.</p>
    <form action="/club-applications" method="post">
      <label for="participant-name">이름 (필수)</label>
      <input id="participant-name" name="participantName" type="text" required>
      <label for="participant-email">이메일 (필수)</label>
      <input id="participant-email" name="email" type="email" required>
      <button type="submit">신청 보내기</button>
    </form>
  </section>
</main>

<footer>
  <p>문의: 밤마을 책모임 hello@example.com</p>
</footer>
```

이 코드는 다음 연결을 한 번에 보여 줍니다.

`요구사항 → 제목과 큰 구조 → 정보 관계에 맞는 요소 → 폼의 제출 흐름 → 검사할 문서`

가상 이미지 파일과 `/club-applications` 주소는 구조 설명용입니다.
실제 파일 로딩과 서버 제출을 완료했다고 뜻하지 않습니다.

## 자동 검사와 직접 점검

### 자동 문법 검사

Nu HTML Checker로 다음을 확인합니다.

- 태그와 속성 문법
- 허용되지 않는 중첩
- 필요한 일부 문서 정보와 속성
- 브라우저가 예상과 다르게 해석할 수 있는 구조

### 의미와 실제 사용 점검

- `title`과 `h1`이 페이지를 알맞게 설명하는가?
- 제목 단계가 내용 관계를 따르는가?
- `nav`는 주요 이동을, `main`은 중심 내용을 나타내는가?
- 링크 문구만 읽어도 목적지를 알 수 있는가?
- 정보를 전하는 포스터라면 보지 않아도 `alt`와 주변 글을 통해 빠지는 핵심 정보가 없는가?
- 표 머리글이 행과 열의 데이터를 알맞게 설명하는가?
- 사용자가 조작하고 제출할 입력에 레이블과 `name`이 있고 오류를 고칠 방법을 알 수 있는가?
- 키보드만으로 링크·입력·제출을 순서대로 사용할 수 있는가?

Checker 통과와 의미·접근성 확인은 서로 대신하지 않습니다.

Checker 오류가 0개여도 접근성 확인이나 학습 숙달까지 끝났다는 뜻은 아닙니다.

| 큰 구조를 못 정함 | 이 내용은 소개·이동·중심·보조·마무리 중 무엇인가? | [시맨틱 HTML: 내용의 역할과 제목 계층](#/learn/html/wiki-semantic-structure) |

## 정리

- 요구사항의 내용과 관계를 찾은 뒤 그 관계에 맞는 요소를 고릅니다.
- 제목·이동·이미지·목록·표·폼을 한 페이지의 목적에 맞게 연결합니다.
- 자동 문법 검사와 사람이 확인하는 의미·접근성 점검을 함께 계획합니다.

## 핵심 질문 답

내용을 빠짐없이 목록으로 만들고 대표/하위 제목, 소개·이동·중심·보조·마무리를 나눕니다.
링크·이미지·목록·표의 관계와 입력값·제출 이름·조건을 찾고 각 요소를 고른 이유를 요구사항의 말로 설명합니다.
구현 뒤에는 Checker의 문법 검사와 사람이 하는 의미·접근성 점검을 나누어 진행합니다.
다른 구조도 타당할 수 있고 검사 통과는 숙달의 증명이 아닙니다.
