# 시맨틱 HTML: 내용의 역할과 제목 계층

## 학습 목표

요구사항에서 내용의 역할과 제목 계층을 찾고 의미 요소와 범용 묶음을 구분할 수 있습니다.

## 한줄 요약

소개·이동·중심·보조·마무리와 제목의 상하 관계를 먼저 찾은 뒤 그 관계에 맞는 요소를 고릅니다.

## 요구사항에서 구조를 찾는 순서

다음 요구사항을 받았다고 하자.

> 밤마을 책모임 소개 페이지를 만든다. 페이지 이름과 이번 달 책을 보여 준다. 이번 달 책 안내는 주소를 따로 공유해도 이해할 수 있는 소식이다. 소개와 일정으로 바로 이동하는 메뉴가 있다. 본문에는 모임 소개와 이번 달 책을 넣고, 따로 읽어도 되는 준비 안내를 덧붙인다. 마지막에는 문의 주소를 적는다.

요소 이름부터 떠올리지 말고 내용의 역할을 표시한다.

1. 페이지 전체의 이름: 밤마을 책모임
2. 주요 이동 경로: 소개, 일정
3. 현재 페이지의 중심 내용: 모임 소개와 이번 달 책
4. 따로 공유해도 완결되는 소식: 이번 달 책
5. 중심 내용과 관련 있지만 따로 읽어도 되는 내용: 준비 안내
6. 마무리 정보: 문의 주소

이제 역할에 맞는 요소를 고른다.

| 역할 | 먼저 검토할 요소 | 고르는 이유 |
| --- | --- | --- |
| 페이지나 한 구역의 소개 | `header` | 화면 맨 위라는 위치보다 소개 역할을 나타낸다. |
| 주요 이동 링크 묶음 | `nav` | 다른 페이지나 같은 문서의 주요 위치로 이동한다. |
| 현재 문서의 중심 내용 | `main` | 반복 메뉴나 페이지 마무리와 중심 내용을 구분한다. |
| 하나의 주제로 묶인 구역 | `section` | 보통 제목이 있는 주제 단위다. 꾸미기 상자는 아니다. |
| 따로 떼어도 완결되는 내용 | `article` | 게시물·소식처럼 독립적으로 재사용할 수 있다. |
| 주변 내용과 관련된 보조 내용 | `aside` | 단순히 오른쪽에 놓였다는 뜻이 아니다. |
| 가까운 구역이나 페이지의 마무리 | `footer` | 저자·문의·관련 정보 같은 마무리 역할을 나타낸다. |

한 문서에서 현재 화면에 표시되는 중심 내용은 `main` 하나로 감싼다.
모든 링크 묶음을 `nav`로 감싸지 않고 주요 탐색에 사용한다.
`header`와 `footer`는 페이지 전체뿐 아니라 `article`이나 `section` 같은 가까운 구역에도 있을 수 있다.

페이지 수준의 `header`, `nav`, `main`, `footer` 등은 보조 기술이 페이지의 큰 구조를 찾아 이동하는 데 도움을 준다.
다만 `article`이나 `section` 안의 `header`·`footer`는 페이지 전체의 머리말·마무리와 역할이 다르다.

## 제목은 글자 크기가 아니라 내용의 단계다

`h1`부터 `h6`까지의 숫자는 내용의 상하 관계를 나타낸다.

```text
h1 밤마을 책모임
├─ h2 모임 소개
├─ h2 이번 달 책
└─ h2 일정
   └─ h3 9월 모임
```

글자를 크게 보이게 하려고 `h1`을 고르지 않는다.
위 예에서 `9월 모임`은 `일정` 안의 세부 내용이므로 `h3`가 된다.
새로운 하위 단계로 들어갈 때 `h2` 다음 `h4`처럼 건너뛰지 않는 편이 이해하기 쉽다.

HTML 문법이 모든 문서에 `h1`을 정확히 하나만 강제한다고 설명하지 않는다.
밤데브의 초보 교안에서는 페이지의 대표 제목을 쉽게 찾도록 분명한 `h1` 하나를 사용하는 원칙으로 시작한다.

## 시맨틱 요소와 논시맨틱 요소

시맨틱 요소는 내용의 역할을 요소 이름으로 알려 준다.
`nav`는 주요 이동 경로, `main`은 중심 내용이라는 뜻을 가진다.

`div`와 `span`은 자체적인 특별한 의미가 없는 범용 묶음 요소다.
그래서 논시맨틱 요소라고 부른다.
나쁜 요소라는 뜻은 아니다.

- 알맞은 의미 요소가 있으면 그 요소를 먼저 고른다.
- 알맞은 의미 요소가 없고 여러 내용을 한 상자로 묶어 꾸미거나 다뤄야 하면 `div`를 검토한다.
- 한 문장 안의 짧은 일부를 묶어야 하면 `span`을 검토한다.

시맨틱 요소를 썼다는 사실만으로 접근성이 완성되지는 않는다.
제목 관계, 링크 문구, 대체 텍스트, 키보드 동작도 따로 확인해야 한다.

## 요구사항을 HTML 뼈대로 바꾸기

```html
<!doctype html>
<html lang="ko">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>밤마을 책모임 소개</title>
  </head>
  <body>
    <header>
      <h1>밤마을 책모임</h1>
      <nav>
        <ul>
          <li><a href="#intro">소개</a></li>
          <li><a href="#schedule">일정</a></li>
        </ul>
      </nav>
    </header>

    <main>
      <section id="intro">
        <h2>모임 소개</h2>
        <p>한 달에 한 권을 읽고 서로의 생각을 나눕니다.</p>
      </section>

      <article>
        <h2>이번 달 책</h2>
        <p>이번 달에는 《느린 밤의 산책》을 읽습니다.</p>
      </article>

      <section id="schedule">
        <h2>일정</h2>
        <p>9월 20일 오후 7시에 만납니다.</p>
      </section>

      <aside>
        <h2>준비 안내</h2>
        <p>기억에 남은 문장 하나를 골라 오세요.</p>
      </aside>
    </main>

    <footer>
      <p>문의: hello@example.com</p>
    </footer>
  </body>
</html>
```

이 예제의 핵심은 요소 개수가 아니다.
요구사항에서 찾은 역할이 코드의 구조로 이어졌다는 점이다.

## 핵심 질문 답

요구사항의 페이지 이름·주요 이동·중심 내용·독립 소식·보조 내용·마무리를 먼저 표시합니다.
소개는 header, 주요 이동은 nav, 중심은 main, 주제 구역은 section, 독립 소식은 article처럼 역할에 맞게 고르고 제목 숫자는 내용의 상하 관계에 맞춥니다.
알맞은 의미가 없는 묶음에는 div·span을 사용할 수 있으며 의미 요소만으로 접근성이 완성되지는 않습니다.
