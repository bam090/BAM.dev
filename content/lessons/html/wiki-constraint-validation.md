# 내장 검증의 역할과 한계

## 학습 목표

입력 조건에 맞는 검증 속성을 고르고 내장 검증과 서버 검증의 경계를 설명할 수 있습니다.

## 한줄 요약

내장 검증은 흔한 실수를 먼저 알려 주지만 우회할 수 있으므로 서버 검증과 이해할 수 있는 안내가 별도로 필요합니다.

## 먼저 확인할 개념

[입력의 레이블과 제출 이름](#/learn/html/wiki-input-names), [받을 값과 선택 관계에 맞는 입력](#/learn/html/wiki-form-controls)의 관계를 알고 있으면 이 문서를 읽기 쉽습니다.

## 내장 검증은 흔한 입력 실수를 먼저 알려 준다

HTML 검증 속성을 사용하면 브라우저가 제출 전에 일부 잘못된 입력을 확인할 수 있다.

| 속성 | 확인하는 것 | 주의할 점 |
| --- | --- | --- |
| `required` | 값을 비워 둘 수 없는가 | 빈 값을 막는 역할이다. |
| `minlength`, `maxlength` | 문자열 길이가 범위 안인가 | `minlength`만으로 빈 값을 막지는 않는다. |
| `min`, `max` | 숫자·날짜·시간 값이 범위 안인가 | 글자 수를 정하는 속성이 아니다. |
| `pattern` | 허용한 전체 형식과 맞는가 | 빈 값도 막으려면 `required`가 따로 필요하다. |
| `type="email"` | 이메일 주소 형식에 맞는가 | 실제 주소가 존재하는지까지 확인하지는 않는다. |

입력 형식은 사용자가 틀린 뒤에만 보여 주지 말고 입력하기 전에 보이는 글로 알려 준다.
지나치게 엄격한 `pattern`은 정상적인 전화번호나 이름까지 막을 수 있으므로 목적에 필요한 만큼만 사용한다.

직접 오류 문구를 만들 때는 어떤 입력이 왜 잘못됐고 어떻게 고칠지를 글로 설명한다.
색만으로 오류를 구분하지 않고, 가능하면 오류 문구를 해당 입력과 연결한다.

브라우저 내장 검증은 사용자에게 빠른 안내를 주지만 우회할 수 있다.
서버는 받은 값을 반드시 다시 검증해야 한다.
내장 검증을 통과했다는 사실만으로 데이터가 안전하거나 폼이 접근 가능하다고 판정하지 않는다.

## 핵심 질문 답

required는 빈 값을 막고 minlength는 글자 수, min/max는 숫자·날짜 범위, pattern은 허용 형식을 검사합니다.
minlength나 pattern만으로 빈 값이 금지되지는 않고 email 형식 검사도 실제 주소 존재를 확인하지는 않습니다.
사용자가 조건과 고칠 방법을 글로 알 수 있게 안내하며, 클라이언트 검사는 우회할 수 있어 서버가 값을 다시 검증해야 합니다.
