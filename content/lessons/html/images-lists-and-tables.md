# 03. 이미지·목록·표로 콘텐츠 구조화하기

## 학습 목표

- 이미지가 현재 문맥에서 전달하는 목적에 맞게 `alt`를 작성할 수 있습니다.
- 정보 이미지와 장식 이미지를 구분하고 장식 이미지에 `alt=""`를 사용할 수 있습니다.
- 순서의 의미에 따라 `ol`과 `ul`을 선택할 수 있습니다.
- 표 형식 데이터에 `caption`, `th`, `scope`를 사용해 행과 열의 관계를 표현할 수 있습니다.
- 표를 화면 레이아웃 도구로 사용하지 않아야 하는 이유를 설명할 수 있습니다.

## 50분 학습 순서

1. 5분: 이미지가 사라진 상황을 관찰합니다.
2. 15분: 이미지 목적에 따라 대체 텍스트를 결정합니다.
3. 10분: 순서 있는 목록과 순서 없는 목록을 구분합니다.
4. 15분: 표의 제목·행·열·머리글 관계를 만듭니다.
5. 5분: 확인 문제에 답합니다.

## 먼저 관찰하기

다음 이미지를 볼 수 없다고 가정해 보세요.

```html
<img src="course-progress.png" alt="이미지" />
```

`alt="이미지"`만으로는 이 이미지가 학습 진도 그래프인지, 로고인지, 장식인지 알 수 없습니다. 대체 텍스트는 파일의 종류를 말하는 문구가 아니라 **현재 문맥에서 이미지가 전달하는 정보나 기능**을 대신해야 합니다.

## 이미지의 목적부터 판단하기

### 정보를 전달하는 이미지

```html
<img
  src="weekly-progress.png"
  alt="월요일 20%, 화요일 40%, 수요일 70%로 증가한 주간 학습 진도"
  width="640"
  height="360"
/>
```

- `src`는 이미지 자원의 위치입니다.
- `alt`는 이미지를 사용할 수 없을 때 대신 전달할 텍스트입니다.
- `width`와 `height`는 이미지의 비율에 맞는 공간을 브라우저가 미리 계산하는 데 도움을 줍니다.

같은 이미지도 문맥에 따라 알맞은 `alt`가 달라질 수 있습니다. 상품 링크 안에 있는 이미지라면 상품의 시각적 묘사보다 링크의 목적이 중요할 수 있습니다. 그래프처럼 정보가 복잡하다면 핵심 요약을 `alt`에 짧게 쓰고 상세 데이터는 주변 텍스트나 표로도 제공합니다.

### 장식 이미지

구분선이나 배경 무늬처럼 주변 내용을 이해하는 데 새 정보를 더하지 않는 이미지는 빈 대체 텍스트를 사용합니다.

```html
<img src="sparkle.svg" alt="" />
```

`alt`를 생략하는 것과 `alt=""`는 같지 않습니다. 빈 값은 이 이미지가 장식이므로 보조 기술에서 건너뛰어도 된다는 의도를 표현합니다. 사이트 전체의 순수한 배경 장식이라면 HTML 이미지보다 CSS 배경으로 제공하는 방식도 검토합니다.

### 이미지와 설명 묶기

```html
<figure>
  <img
    src="html-dom-tree.png"
    alt="article 아래에 h2와 p가 있고 p 안에 strong이 있는 DOM 트리"
  />
  <figcaption>학습 기록 마크업을 DOM 트리로 표현한 모습</figcaption>
</figure>
```

`figure`는 본문에서 하나의 단위로 참조할 수 있는 이미지·도표·코드 등을 묶고, `figcaption`은 그 콘텐츠의 설명을 제공합니다. `alt`와 `figcaption`에 같은 긴 문장을 그대로 반복하기보다 각각 이미지 대체와 그림 설명이라는 역할에 맞게 작성합니다.

## 목록에서 순서의 의미 표현하기

순서를 바꾸어도 뜻이 유지되는 항목은 `ul`로 나타냅니다.

```html
<h2>오늘의 준비물</h2>
<ul>
  <li>노트북</li>
  <li>충전기</li>
  <li>학습 노트</li>
</ul>
```

단계, 순위, 시간 순서처럼 순서를 바꾸면 의미가 달라지는 항목은 `ol`로 나타냅니다.

```html
<h2>HTML 점검 순서</h2>
<ol>
  <li>문서 구조를 읽습니다.</li>
  <li>링크와 이미지의 목적을 확인합니다.</li>
  <li>검사 도구로 문법 오류를 확인합니다.</li>
</ol>
```

`ul`과 `ol`의 목록 항목은 `li`로 표현합니다. 화면에 점이나 숫자를 보이게 하는 목적만으로 목록 종류를 선택하지 않습니다. 표시 모양은 CSS로 바꿀 수 있지만 순서의 의미는 HTML에 남습니다.

## 표는 행과 열의 데이터에 사용하기

요일별 학습 시간을 행과 열로 비교하려면 표가 알맞습니다.

```html
<table>
  <caption>이번 주 언어별 학습 시간</caption>
  <thead>
    <tr>
      <th scope="col">요일</th>
      <th scope="col">언어</th>
      <th scope="col">시간</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">월요일</th>
      <td>HTML</td>
      <td>60분</td>
    </tr>
    <tr>
      <th scope="row">화요일</th>
      <td>CSS</td>
      <td>45분</td>
    </tr>
  </tbody>
</table>
```

- `table`: 표 전체
- `caption`: 표가 어떤 데이터를 나타내는지 설명하는 제목
- `thead`, `tbody`: 머리글 행과 본문 행의 구역
- `tr`: 하나의 행
- `th`: 행 또는 열을 설명하는 머리글 셀
- `td`: 실제 데이터 셀
- `scope="col"`, `scope="row"`: 머리글이 어느 방향의 셀을 설명하는지 표시

단순한 표에서는 `scope`로 머리글 관계를 명확하게 만들 수 있습니다. 복잡한 다단계 표는 더 많은 관계 표현이 필요할 수 있으므로, 먼저 표를 단순하게 설계할 수 있는지도 검토합니다.

## 표를 레이아웃에 사용하지 않기

`table`은 두 개 이상의 차원으로 관계가 있는 데이터를 나타냅니다. 카드 두 개를 가로로 배치하거나 사이드바와 본문을 나누는 일은 데이터 관계가 아니므로 CSS Grid나 Flexbox 같은 CSS 레이아웃을 사용합니다.

레이아웃용 표는 보조 기술이 각 상자를 데이터 셀로 해석하게 만들어 읽는 흐름을 혼란스럽게 할 수 있습니다. “행과 열 머리글로 설명할 데이터인가?”라는 질문에 답할 수 없다면 표가 아닌 구조를 검토합니다.

## 직접 판단하기

다음 요구사항에 알맞은 요소를 골라 보세요.

1. 학습할 언어 HTML, CSS, JavaScript: 순서를 바꾸어도 의미가 같으므로 `ul`
2. 파일 생성, 코드 작성, 브라우저 확인: 실행 순서가 중요하므로 `ol`
3. 요일과 학습 시간을 서로 비교하는 데이터: `table`
4. 본문 옆에 관련 링크를 배치하는 화면 레이아웃: 표가 아니라 의미 있는 HTML 구조와 CSS
5. 내용과 무관한 별 모양 구분선: `img`를 사용한다면 `alt=""`

## 흔한 혼동

- `alt="사진"`처럼 파일 종류만 반복합니다.
- 장식 이미지에서 `alt` 자체를 생략합니다.
- 이미지 안의 모든 시각 정보를 매우 긴 `alt` 하나에 넣고 상세 설명을 제공하지 않습니다.
- 목록 앞에 숫자가 보이게 하려는 이유만으로 `ol`을 선택합니다.
- 표의 첫 행을 모두 `td`로 작성해 어떤 셀이 머리글인지 표현하지 않습니다.
- `caption` 대신 표 바깥의 일반 문단만 두어 표와 제목의 관계를 끊습니다.
- 요소를 가로로 배치하려고 `table`을 사용합니다.

## 확인 문제

1. 장식 이미지에서 `alt`를 생략하지 않고 빈 문자열로 두는 이유는 무엇인가요?
2. 조리법의 단계를 `ul`보다 `ol`로 표현하는 편이 알맞은 이유는 무엇인가요?
3. `th scope="col"`과 `th scope="row"`는 각각 어느 방향의 데이터를 설명하나요?
4. 표의 `caption`은 어떤 질문에 답하는 내용이어야 하나요?
5. 그래프가 많은 정보를 담고 있어 짧은 `alt`만으로 부족하다면 무엇을 추가해야 하나요?
6. 화면의 두 영역을 나란히 배치하기 위해 표를 사용하지 않아야 하는 이유를 설명해 보세요.
