# 읽기 쉬운 글자: 단위·글꼴·색

## 학습 목표

- `px`·`%`·`rem`·`em`이 무엇을 기준으로 계산되는지 찾고 같은 `em`도 속성에 따라 기준이 달라지는 경우를 설명할 수 있습니다.
- 글꼴을 쓸 수 없거나 글자가 커져도 읽히도록 대체 글꼴 목록과 단위 없는 `line-height`를 정할 수 있습니다.
- 글자와 배경의 대비를 확인하고 상태를 색 하나에만 맡기지 않는 단서를 고를 수 있습니다.
- 배경만 반투명하게 할 때 `opacity` 대신 배경색의 알파를 고를 수 있습니다.

## 먼저 확인할 개념

[CSS 기초: 적용 방법과 선택자](#/learn/css/wiki-css-basics)에서 속성과 값의 관계를 보고 [캐스케이드와 상속](#/learn/css/wiki-cascade)에서 값이 자식에게 이어지는 방식을 먼저 확인해 보세요.

## 글자 스타일이란

글자 스타일은 글자의 크기·글꼴·줄 간격·색을 정하는 CSS 선언의 묶음입니다.
네 가지는 서로 다른 속성으로 적지만 글이 읽기 쉬운지는 함께 결정합니다.
크기가 알맞아도 줄이 겹치면 읽기 어렵고 글꼴이 좋아도 배경과 색이 비슷하면 보이지 않기 때문입니다.

글자 크기와 간격·너비는 `px`·`rem` 같은 단위로 적습니다.
단위는 숫자 뒤에 붙어 그 숫자를 무엇을 기준으로 계산할지 정하는 표시입니다.
그래서 같은 `1`이라도 단위에 따라 16px이 되기도 하고 20px이 되기도 합니다.

예를 들어 마을 주민 모임을 알리는 안내 카드를 만든다고 해 보겠습니다.
이 카드에는 네 가지 요구가 있습니다.

- 카드의 글자 크기와 안쪽 간격을 글자 크기에 맞춰 정합니다.
- 원하는 글꼴이 없거나 제목이 두 줄이 되어도 읽힙니다.
- 신청 칸의 오류를 색을 구분하기 어려운 사람도 알아봅니다.
- 카드 배경만 살짝 비치게 하고 글자는 선명하게 둡니다.

이 문서는 이 카드 하나로 단위·글꼴·줄 간격·색을 차례로 살펴봅니다.

## 길이 단위의 종류

길이 단위는 이름보다 기준을 먼저 찾으면 헷갈리지 않습니다.

| 단위 | 계산 기준 | 카드에서 쓰는 곳 |
| --- | --- | --- |
| `px` | CSS 기준 픽셀 | 테두리 두께처럼 늘 같은 크기 |
| `%` | 그 속성이 정한 기준값 | 부모 너비에 맞춘 카드 너비 |
| `rem` | 루트 요소의 계산된 글자 크기 | 카드 사이 간격 |
| `em` | 그 요소의 계산된 글자 크기 · `font-size`에 쓰면 부모의 글자 크기 | 글자 크기에 맞춘 안쪽 간격 |

CSS의 1px은 화면의 물리 픽셀 한 칸과 언제나 같지는 않습니다.
기기 배율이나 확대 상태에 따라 여러 물리 픽셀로 그려질 수 있습니다.

`%`는 속성마다 기준이 다릅니다.
`width: 80%`는 화면 너비가 아니라 그 요소를 담는 부모 상자(포함 블록)의 너비를 기준으로 합니다.
그래서 화면이 1000px이어도 부모가 400px이면 `width: 50%`인 자식의 너비는 200px입니다.
반면 `font-size`의 `%`는 부모의 글자 크기를 기준으로 하고 `transform`의 `%`는 요소 자신의 크기를 기준으로 합니다.

> [!note]- 화면 영역 단위 vw·vh
> `vw`와 `vh`는 화면(viewport)의 너비와 높이를 기준으로 합니다.
> 높이에는 주소창이 보일 때의 작은 영역 `svh`와 숨었을 때의 큰 영역 `lvh`와 지금 바뀌는 영역 `dvh`도 있습니다.
> 기본 `vh`는 보통 큰 영역을 기준으로 하므로 모바일에서 주소창이 보이는 순간의 높이와 다를 수 있습니다.

네 단위 가운데 가장 헷갈리는 것은 글자 크기를 기준으로 하는 `em`과 `rem`입니다.
두 단위를 같은 카드에 함께 써 보겠습니다.

## em과 rem 사용법

안내 카드에 다음 규칙을 적었습니다.
카드는 content 너비가 500px인 부모 상자 안에 있습니다.
카드의 `padding`·`margin-block`·`width`와 제목의 글자 크기가 각각 몇 px일지 먼저 예상해 보세요.

```css
html {
  font-size: 16px;
}

.meeting-card {
  font-size: 20px;
  width: 80%;
  padding: 1em;
  margin-block: 1rem;
}

.meeting-card h2 {
  font-size: 1.5em;
}
```

![점선 부모 상자 안에 주민 모임 카드가 있다. 표에는 브라우저가 계산한 값이 있다. 카드 padding 1em은 20px이고 margin-block 1rem은 16px이며 width 80%는 400px이고 제목 font-size 1.5em은 30px이다.](content/assets/css/units-em-rem.png)

padding의 em은 그 요소 자신의 계산된 글자 크기를 기준으로 합니다.
margin-block의 rem은 루트 요소의 계산된 글자 크기를 기준으로 합니다.
그래서 같은 `1`이라도 `padding`은 20px이 되고 `margin-block`은 16px이 됩니다.

`width: 80%`는 부모의 content 너비 500px을 기준으로 하므로 400px입니다.

제목의 `font-size: 1.5em`은 30px입니다.
`font-size`에 쓴 em은 자신의 글자 크기를 아직 모르므로 부모인 카드의 20px을 기준으로 삼기 때문입니다.
반면 제목에 `padding: 1em`을 더하면 제목 자신의 계산된 글자 크기 30px을 기준으로 해서 30px이 됩니다.
그래서 em은 늘 부모 기준이라고 외우기보다 그 em을 어느 속성에 썼는지부터 확인합니다.

루트의 16px은 계산을 보여 주려고 적은 값입니다.
실제 프로젝트에서 루트 글자 크기를 px로 고정하면 사용자가 정한 글자 크기 설정을 무시할 수 있습니다.

> [!question]- em이 예상과 다를 때 확인할 것
> 1. 그 em을 `font-size`에 썼나요 아니면 다른 속성에 썼나요?
> 2. 개발자 도구의 Computed 탭에서 부모와 자신의 최종 `font-size`는 몇 px인가요?
> 3. em을 쓴 조상이 여러 겹이라 크기가 곱해지지 않았나요?

이제 카드의 글자 크기가 정해졌습니다.
다음은 그 글자를 어떤 글꼴로 몇 줄 간격에 그릴지 정할 차례입니다.

## 글꼴과 줄 간격 사용법

카드에 글꼴과 줄 간격을 적습니다.

```css
.meeting-card {
  font-family: "Pretendard", Arial, sans-serif;
  line-height: 1.5;
}
```

`font-family`는 쓰고 싶은 글꼴을 후보 목록으로 적는 속성입니다.
브라우저는 목록을 앞에서부터 확인하다가 쓸 수 없는 글꼴이면 다음 후보로 넘어갑니다.
앞 글꼴이 있어도 특정 글자의 모양을 제공하지 않으면 그 글자만 다음 후보로 그립니다.
마지막에는 `sans-serif` 같은 일반 글꼴 계열을 두어 어떤 환경에서도 읽을 수 있는 대안을 남깁니다.

이 선언만으로 Pretendard 파일이 내려받아지지는 않습니다.
사용자 기기에 Pretendard가 없고 웹폰트로도 제공하지 않으면 카드는 Arial로 그려집니다.
그래서 대체 글꼴로 보았을 때도 줄이 어디서 바뀌는지와 버튼이 겹치지 않는지 확인합니다.

`line-height`는 한 글줄이 차지하는 높이를 정하는 속성입니다.
`1.5`처럼 단위 없는 숫자로 적을 수도 있고 `30px`처럼 길이로 적을 수도 있습니다.
카드의 20px 글자에서는 둘 다 30px입니다.
그렇다면 30px 제목이 두 줄로 넘어갈 때 두 카드의 줄 간격은 같을까요?

![왼쪽 카드는 line-height 1.5이고 30px 제목의 줄 높이가 45px이라 두 줄 사이가 넉넉하다. 오른쪽 카드는 line-height 30px이고 제목의 줄 높이도 30px이라 두 줄이 거의 붙어 있다.](content/assets/css/units-line-height.png)

왼쪽 제목의 줄 높이는 45px이고 오른쪽 제목은 30px입니다.
단위 없는 숫자는 숫자 그대로 자식에게 상속되어 자식이 자신의 글자 크기에 곱하기 때문입니다.
반면 `30px`은 카드에서 계산된 길이가 그대로 상속되어 글자가 큰 제목에서도 30px로 남습니다.
같은 원리로 부모가 `font-size: 16px; line-height: 1.5`이면 24px 제목의 줄 높이는 24px이 아니라 36px입니다.

글자가 커질 수 있는 곳을 고정된 높이의 상자에 가두면 문장이 겹치거나 잘릴 수 있습니다.
그래서 줄 간격은 단위 없는 숫자로 적고 상자 높이는 내용에 맡기는 편이 안전합니다.

> [!note]- WCAG의 글자 간격 기준
> WCAG가 모든 문서의 기본 `line-height`를 1.5로 정하라고 요구하지는 않습니다.
> 대신 사용자가 줄 간격을 글자 크기의 1.5배로 늘리고 글자·단어·문단 간격을 넓혀도 내용이나 기능이 사라지지 않아야 합니다.
> 두 조건은 서로 다른 이야기이므로 기본값을 정하는 일과 간격을 늘려 보는 확인을 따로 합니다.

> [!note]- 웹폰트와 굵기
> 웹폰트는 `@font-face`로 제공하고 `font-display`로 불러오는 동안 글자를 어떻게 보여 줄지 정합니다.
> `normal`은 400과 같고 `bold`는 700과 같습니다.
> 그 굵기의 파일이 없으면 브라우저가 가까운 굵기를 고르거나 비슷하게 굵게 만들 수 있습니다.

글자의 모양과 줄 간격을 정했으니 이제 그 글자가 배경 위에서 잘 보이는지 확인할 차례입니다.

## 색과 대비 사용법

카드에 글자색과 배경색을 적습니다.

```css
.meeting-card {
  color: rgb(22 50 79);
  background-color: rgb(237 246 255);
}
```

`color`는 글자색을 정하고 `background-color`는 배경색을 정합니다.
글자색 하나만 보고는 잘 읽히는지 알 수 없으므로 실제로 맞닿는 배경과의 대비를 확인합니다.
대비는 두 색의 밝기 차이를 `4.5:1`처럼 비율로 나타낸 값입니다.
이 카드의 두 색은 약 12:1입니다.

WCAG의 최소 기준은 일반 글자 4.5:1이고 큰 글자 3:1입니다.
큰 글자는 굵지 않으면 18pt(약 24 CSS px) 이상이고 굵으면 14pt(약 18.7 CSS px) 이상인 글자입니다.
로고나 비활성 요소처럼 기준에서 빠지는 경우도 있지만 커 보인다는 느낌만으로 기준을 낮추지는 않습니다.
그래서 색을 고른 뒤에는 실제 화면의 글자 크기와 배경 조합으로 대비를 검사합니다.

대비가 충분해도 색만으로는 전달되지 않는 정보가 있습니다.
카드의 신청 칸에서 전화번호를 잘못 넣었을 때 빨간 테두리로만 알린다고 해 보겠습니다.
색을 뺀 화면에서 두 칸이 어떻게 보일지 예상해 보세요.

```html
<label for="phone">전화번호</label>
<input id="phone" class="error" value="abc">
<p class="field-error">
  <span aria-hidden="true">⚠</span>
  전화번호에는 숫자를 입력해 주세요.
</p>
```

![위 줄은 원래 색이고 아래 줄은 색을 뺀 모습이다. 빨간 테두리만 있는 왼쪽 칸은 색을 빼면 어두운 테두리만 남아 오류인지 알 수 없다. 경고 모양과 오류 문구가 있는 오른쪽 칸은 색을 빼도 무엇을 고칠지 읽을 수 있다.](content/assets/css/units-noncolor-cue.png)

색을 빼자 왼쪽 칸은 오류인지 알 수 없게 되었습니다.
오른쪽 칸은 문구가 오류의 이유와 고칠 행동을 알려 주므로 색이 없어도 뜻이 남습니다.
경고 모양은 `aria-hidden`으로 장식 역할만 하고 내용은 문장이 전달합니다.

테두리를 더 진한 빨강으로 바꾸거나 깜빡이게 해도 무엇을 고칠지는 알 수 없습니다.
마우스를 올릴 때만 보이는 변화는 키보드나 터치 사용자에게 닿지 않습니다.
그래서 오류·선택·현재 위치 같은 상태에는 문구·밑줄·테두리 모양 같은 단서를 색과 함께 둡니다.

이제 마지막 요구인 반투명 배경이 남았습니다.
투명도를 주는 방법에 따라 글자의 대비도 함께 바뀝니다.

## 배경 알파와 opacity

카드 뒤에 줄무늬 배경이 있고 카드 배경을 50%만 비치게 하려고 합니다.
세 가지 방법 가운데 글자가 선명하게 남는 것은 무엇일지 예상해 보세요.

![줄무늬 배경 위에 세 카드가 있다. opacity 0.5인 카드와 opacity 0.5에 글자만 opacity 1을 준 카드는 둘 다 글자까지 흐리다. background-color에 50% 알파를 준 카드는 배경만 비치고 글자는 선명하다.](content/assets/css/units-opacity-alpha.png)

배경색에 알파를 준 오른쪽 카드만 글자가 선명합니다.
`opacity`는 요소와 그 안의 내용을 한 장으로 합친 결과 전체에 적용되기 때문입니다.
그래서 자식 글자에 `opacity: 1`을 주어도 부모 전체에 적용된 투명도를 되돌리지 못합니다.

배경만 반투명하게 하려면 배경색의 알파를 씁니다.
현재 `rgb()` 문법은 `rgb(150 120 230 / 50%)`처럼 `/` 뒤에 알파를 받습니다.
그래서 알파를 쓰려고 꼭 `rgba()`라는 이름을 쓸 필요는 없습니다.

반투명한 배경은 뒤에 놓인 색과 섞여 최종 색이 됩니다.
그래서 알파를 바꾼 뒤에는 실제 뒤 배경 위에서 글자의 대비를 다시 확인합니다.

## 글자 스타일의 활용

지금까지 안내 카드의 네 요구를 단위·글꼴·줄 간격·색으로 풀었습니다.
실제 페이지에서는 요구에서 거꾸로 속성을 찾아가면 됩니다.

| 요구 | 고를 값 | 함께 확인할 것 |
| --- | --- | --- |
| 간격을 그 요소의 글자 크기에 맞춘다 | `em` | 그 em을 `font-size`에 썼는지 |
| 페이지 전체에서 같은 간격을 쓴다 | `rem` | 루트 글자 크기를 px로 고정하지 않았는지 |
| 부모 너비에 맞춘다 | `%` | 그 속성의 `%` 기준이 무엇인지 |
| 원하는 글꼴이 없어도 읽힌다 | `font-family` 후보 목록 | 마지막에 일반 글꼴 계열이 있는지 |
| 제목과 본문의 줄 간격을 함께 맞춘다 | 단위 없는 `line-height` | 상자 높이를 고정하지 않았는지 |
| 상태를 알린다 | 색과 문구·모양 | 색을 빼도 뜻이 남는지 |
| 배경만 비치게 한다 | 배경색의 알파 | 뒤 배경 위에서 대비가 충분한지 |

마지막으로 브라우저의 글자 크기를 키우고 긴 제목과 대체 글꼴로 바꿔 봅니다.
그래도 글이 겹치거나 잘리지 않고 상태가 읽혀야 글자 스타일이 끝난 것입니다.

## 정리

- `rem`은 루트 글자 크기를 따르고 `em`은 그 요소의 글자 크기를 따르지만 `font-size`의 `em`은 부모 글자 크기를 따르며 `%`는 속성마다 기준이 다릅니다.
- `font-family`에는 대체 후보와 일반 글꼴 계열을 두고 `line-height`는 단위 없는 숫자로 적어 각 요소의 글자 크기를 따르게 합니다.
- 글자는 실제 배경과의 대비로 확인하고 상태는 색과 다른 단서를 함께 쓰며 배경만 비치게 할 때는 `opacity` 대신 배경색의 알파를 씁니다.

## 핵심 질문 답

`px`는 CSS 기준 픽셀이고 `%`는 속성마다 정한 기준값을 따르며 `rem`은 루트의 계산된 글자 크기를 따릅니다.
`em`은 보통 그 요소의 계산된 글자 크기를 따르지만 `font-size`에 쓰면 부모의 글자 크기를 따릅니다.
글꼴은 대체 후보와 일반 글꼴 계열로 적고 줄 간격은 단위 없는 `line-height`로 적어 글자가 커져도 겹치지 않게 합니다.
색은 실제 배경과의 대비로 확인하고 상태에는 문구 같은 다른 단서를 함께 두며 배경만 비치게 할 때는 배경색의 알파를 씁니다.
