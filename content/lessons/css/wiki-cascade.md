# 캐스케이드와 명시도

## 학습 목표

같은 요소의 같은 속성에 선언이 겹칠 때 적용 조건·우선순위·명시도·작성 순서로 결과를 설명할 수 있습니다.

## 한줄 요약

캐스케이드는 겹친 선언 중 하나를 고르며 명시도와 작성 순서는 앞선 우선순위 조건이 같을 때 비교합니다.

## 먼저 확인할 개념

[선택자로 원하는 요소 찾기](#/learn/css/wiki-selectors)에서 한 요소가 여러 선택자와 일치할 수 있음을 확인해 보세요.

## 같은 속성의 후보를 찾는다

다음 예제는 같은 작성자의 일반 규칙이며 inline style·레이어·애니메이션·전환·`@scope`를 사용하지 않는다.

```html
<p id="today" class="notice">오늘 저녁 7시에 만납니다.</p>
```

```css
p { color: gray; }
.notice { color: navy; }
#today { color: darkgreen; }
```

세 선택자가 같은 문단과 일치하지만 글자색은 하나로 정해져야 한다.
이렇게 한 요소의 한 속성에 겹친 선언을 우선순위로 비교하는 과정이 캐스케이드다.

## 마지막 줄보다 앞선 기준이 있다

선택자와 조건이 실제 요소에 맞는지 먼저 확인한다.
후보끼리는 출처·중요도·레이어처럼 명시도보다 앞선 기준을 비교한다.
그 조건이 같을 때 명시도를 비교하고, 명시도까지 같으면 나중에 작성된 선언이 이긴다.

브라우저 기본 스타일·사용자 스타일·사이트 작성자 스타일은 출처가 다르다.
전체 캐스케이드에는 애니메이션·전환 등의 기준도 있으므로, 위 관찰 순서를 모든 상황의 전체 순서로 외우지 않는다.
이 문서의 계산 예제는 앞에서 밝힌 일반 작성자 규칙끼리의 비교다.

## 명시도는 세 칸을 비교한다

명시도(specificity)는 선택자의 구체성을 세 칸으로 비교한다.
십진수 점수 하나로 더하지 않고 왼쪽 칸부터 본다.

```text
(ID 개수, class·속성·가상 클래스 개수, 요소·가상 요소 개수)
```

| 선택자 | 명시도 |
| --- | --- |
| `p` | `(0, 0, 1)` |
| `.notice` | `(0, 1, 0)` |
| `article .notice` | `(0, 1, 1)` |
| `#today` | `(1, 0, 0)` |

앞의 예에서는 ID 칸이 가장 큰 `#today`가 선택되므로 글자색은 darkgreen이다.
클래스가 많아져도 ID 칸으로 올림되지 않는다.

```css
.notice { color: navy; }
.notice { color: darkgreen; }
```

이 두 선언처럼 앞선 조건과 명시도가 같을 때만 뒤의 darkgreen이 선택된다.
클래스가 재사용하기 쉽다는 장점은 캐스케이드의 승패 기준이 아니다.

## 직접 적은 스타일과 important의 경계

같은 작성자의 일반 선언끼리 비교하면 요소의 `style` 속성에 직접 적은 선언이 선택자 규칙보다 우선한다.
`!important`는 명시도 점수를 높이지 않고 선언을 다른 중요도 그룹에서 비교하게 한다.
둘 다 모든 출처와 상황에서 무조건 최우선인 것은 아니다.

규칙이 예상과 다르면 `!important`부터 붙이지 않는다.
개발자 도구에서 같은 속성의 이긴 선언을 찾고, 어떤 비교 기준이 달랐는지 확인한다.

### 선택 확장: 레이어

`@layer base, components;`처럼 선언하면 스타일 묶음의 순서를 정할 수 있다.
같은 작성자의 일반 선언에서는 뒤 레이어가 앞서고 레이어 밖 선언이 레이어 안보다 앞선다.
중요 선언에서는 레이어 순서가 반대이므로, 작은 예제에 사용하지 않는다면 지금은 비교 범위만 알아 둔다.

## 핵심 질문 답

같은 요소의 같은 속성에 적용되는 후보인지 먼저 확인합니다.
출처·중요도·레이어 같은 앞선 기준이 같으면 명시도의 세 칸을 왼쪽부터 비교하고, 그것도 같으면 나중 선언을 고릅니다.
따라서 마지막 줄이나 큰 명시도가 언제나 이기는 것은 아니며 important도 명시도 점수를 더하는 문법이 아닙니다.
