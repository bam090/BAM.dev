# CSS 위치 지정: position과 z-index

## 학습 목표

- 요소를 일반 흐름에 남길지에 따라 `relative`와 `absolute`를 고르고 `absolute`가 따르는 위치 기준을 찾을 수 있습니다.
- 스크롤할 때 화면에 고정할지 한 영역 안에서만 붙일지에 따라 `fixed`와 `sticky`를 고를 수 있습니다.
- 위치를 정한 요소끼리 겹칠 때 `z-index` 숫자보다 쌓임 맥락을 먼저 찾아 앞뒤를 설명할 수 있습니다.
- 요소끼리 서로 밀어내야 하는 배치에서는 `position` 대신 Flexbox나 Grid를 고를 수 있습니다.

## 먼저 확인할 개념

[일반 흐름과 넘침](#/learn/css/wiki-display)와 [박스 모델과 간격](#/learn/css/wiki-box-model)을 먼저 확인해 보세요.

## position이란

`position`은 요소를 일반 흐름 안에 둘지와 무엇을 기준으로 위치를 정할지를 고르는 속성입니다.
일반 흐름은 요소가 HTML 순서대로 위에서 아래로 자리를 차지하며 쌓이는 기본 배치입니다.
대부분의 요소는 이 흐름만으로 충분합니다.
그런데 카드 모서리의 배지나 화면 구석의 버튼처럼 흐름과 상관없이 특정 자리에 놓아야 하는 요소도 있습니다.

`position`을 정한 뒤에는 `top`·`right`·`bottom`·`left`로 기준에서 얼마나 떨어질지 적습니다.
네 방향을 한 번에 적는 축약 속성은 `inset`입니다.
같은 `top: 10px`이라도 `position` 값에 따라 무엇에서 10px 떨어지는지가 달라집니다.

예를 들어 마을 소식 게시판 페이지를 만든다고 해 보겠습니다.
이 페이지에는 네 가지 요구가 있습니다.

- 소식 카드의 오른쪽 위에 `새 소식` 배지를 붙입니다.
- 도움말 버튼은 스크롤해도 화면 오른쪽 아래에 있습니다.
- 긴 일정 목록을 내리는 동안 목록 제목은 위에 붙어 있습니다.
- 겹친 상자 가운데 어느 것이 앞에 보일지 정합니다.

이 문서는 이 페이지 하나로 `position`의 모든 값과 `z-index`를 차례로 살펴봅니다.

## position의 종류

`position`의 값은 두 질문으로 나눌 수 있습니다.
하나는 일반 흐름에 원래 자리를 남기는지이고 다른 하나는 무엇을 기준으로 놓이는지입니다.

| 값 | 원래 자리 | 위치 기준 | 게시판에서 쓰는 곳 |
| --- | --- | --- | --- |
| `static` | 남음 | 기본 배치이며 `inset`이 적용되지 않음 | 대부분의 요소 |
| `relative` | 남음 | 일반 흐름에 놓였던 자신의 원래 위치 | 배지의 기준이 되는 카드 |
| `absolute` | 빠짐 | 위치 기준을 만드는 가장 가까운 조상 | 카드 모서리의 배지 |
| `fixed` | 빠짐 | 보통 화면(viewport) | 도움말 버튼 |
| `sticky` | 남음 | 가장 가까운 스크롤 영역 | 일정 목록 제목 |

기본값은 `static`입니다.
나머지 네 값을 두 쌍으로 묶어 살펴보겠습니다.
먼저 원래 자리를 남기는 `relative`와 흐름에서 빠지는 `absolute`입니다.

## relative와 absolute 사용법

같은 B 상자에 두 값을 하나씩 준다고 해 보겠습니다.
C 상자가 어디에 놓일지 먼저 예상해 보세요.

![왼쪽은 B에 position relative와 top 20px left 28px을 준 결과다. B는 오른쪽 아래로 옮겨져 보이지만 점선으로 표시한 원래 자리가 비어 있고 C는 원래 위치에 그대로 있다. 오른쪽은 B에 position absolute와 top 10px right 10px을 준 결과다. B가 흐름에서 빠져 C가 A 바로 아래로 올라왔고 B는 점선 테두리 상자의 오른쪽 위에 놓였다.](content/assets/css/position-relative-absolute.png)

`relative`인 B는 보이는 위치만 옮겨졌습니다.
원래 자리는 비어 있고 C도 제자리에 있습니다.
`relative`는 흐름 속 자리를 그대로 두고 그림만 옮기기 때문입니다.

반면 `absolute`인 B는 흐름에서 빠졌습니다.
그래서 C가 B의 빈자리로 올라왔습니다.
B는 점선 테두리 상자를 기준으로 위와 오른쪽에서 10px 떨어진 곳에 놓였습니다.

`absolute`가 기준으로 삼는 상자를 위치 기준 박스(containing block)라고 합니다.
위치 기준 박스는 `position`이 `static`이 아닌 가장 가까운 조상이 만듭니다.
그래서 이동값 없이 `position: relative`만 주어 자손의 기준을 만드는 경우가 많습니다.

이제 게시판의 소식 카드에 배지를 붙여 보겠습니다.

```html
<article class="notice-card">
  <h2>마을 회의</h2>
  <p>이번 주 토요일 오전 10시에 마을회관에서 회의를 엽니다.</p>
  <span class="new-badge">새 소식</span>
</article>
```

```css
.notice-card {
  position: relative;
  padding-right: 5.5rem;
}

.new-badge {
  position: absolute;
  top: 0.5rem;
  right: 0.5rem;
}
```

![마을 회의 카드의 오른쪽 위 모서리에 새 소식 배지가 붙어 있다. 카드 오른쪽의 빗금 영역은 padding-right로 비운 공간이며 제목과 본문은 그 앞에서 줄을 바꾼다.](content/assets/css/position-badge.png)

카드가 `relative`이므로 배지는 카드의 오른쪽 위에서 0.5rem씩 떨어진 곳에 놓입니다.
배지는 흐름에서 빠졌기 때문에 제목과 본문은 배지가 있는지 모릅니다.
그래서 카드에 `padding-right`를 주어 글자가 배지 밑으로 들어가지 않게 공간을 비웠습니다.

> [!note]- 가장 가까운 조상이 항상 부모일까요?
> 위치 기준 박스는 바로 위 부모가 아니라 조건에 맞는 가장 가까운 조상이 만듭니다.
> `position`이 `static`이 아닌 조상 말고도 `transform`이 `none`이 아닌 조상처럼 기준을 만드는 속성이 더 있습니다.
> 기준을 만드는 조상이 하나도 없으면 문서의 처음 기준 박스까지 올라갑니다.

배지는 카드 안에서 자리를 잡았습니다.
다음은 카드가 아니라 화면이나 스크롤 영역을 기준으로 삼는 두 값입니다.

## fixed와 sticky 사용법

도움말 버튼과 일정 목록 제목은 둘 다 스크롤해도 보여야 합니다.
그런데 버튼은 화면에 계속 있어야 하고 제목은 일정 목록을 보는 동안만 붙어 있으면 됩니다.

```css
.help-button {
  position: fixed;
  right: 1rem;
  bottom: 1rem;
}

.schedule-title {
  position: sticky;
  top: 0;
  background: white;
}
```

`fixed`인 도움말 버튼은 흐름에서 빠져 화면을 기준으로 놓입니다.
그래서 페이지를 스크롤해도 화면 오른쪽 아래의 같은 자리에 보입니다.
다만 조상에 `transform`이 있으면 그 조상이 기준이 되어 화면에 고정되지 않습니다.

`sticky`인 목록 제목은 원래 자리를 남긴 채 흐름에 있습니다.
스크롤하다가 `top: 0` 경계에 닿으면 그때부터 붙어 보입니다.
스크롤을 내리며 제목이 어떻게 움직일지 예상해 보세요.

![sticky 제목의 세 장면이다. 첫째 스크롤 전에는 이번 달 일정 제목이 안내 문단 아래 원래 자리에 있다. 둘째 목록을 지나는 중에는 제목이 스크롤 영역 위쪽에 붙어 있고 그 아래로 일정이 지나간다. 셋째 목록이 끝난 뒤에는 제목이 목록과 함께 위로 밀려 올라가고 다음 문단이 보인다.](content/assets/css/position-sticky.png)

제목은 목록 상자를 지나는 동안만 위에 붙어 있습니다.
목록 상자가 끝나면 제목도 함께 밀려 올라갑니다.
`sticky`는 자신을 감싼 상자 범위를 넘어서까지 붙어 있지 않기 때문입니다.
그래서 화면 전체에서 계속 보여야 하는 버튼에는 `fixed`를 쓰고 한 영역 안에서만 붙이는 제목에는 `sticky`를 씁니다.

> [!question]- sticky가 붙지 않을 때 확인할 것
> 1. 붙을 방향에 `top`처럼 `auto`가 아닌 값을 적었나요?
> 2. 실제로 스크롤할 거리가 있나요?
> 3. 조상의 `overflow`가 예상하지 못한 스크롤 영역을 만들지 않았나요?
> 4. 제목을 감싼 상자가 너무 짧아 움직일 범위가 없지 않나요?

이제 게시판에는 흐름에서 빠진 요소가 여럿 생겼습니다.
흐름에서 빠진 요소는 다른 요소와 겹칠 수 있으므로 어느 쪽이 앞에 보일지도 정해야 합니다.

## 쌓임 맥락과 z-index

`z-index`는 겹친 요소 가운데 무엇을 앞에 그릴지 정하는 숫자입니다.
숫자가 클수록 앞에 그려집니다.
그런데 이 숫자는 페이지 전체에서 겨루는 순위가 아닙니다.
같은 쌓임 맥락 안에서만 비교합니다.

쌓임 맥락은 요소들을 한 묶음으로 쌓는 단위입니다.
여러 장의 종이를 끼운 파일철과 비슷합니다.
뒤 파일철 안에서 종이 한 장을 맨 앞으로 옮겨도 앞 파일철보다 앞으로 나오지는 못합니다.

게시판에서 두 묶음이 겹친다고 해 보겠습니다.
뒤 묶음은 `z-index: 1`이고 그 안의 자식은 `z-index: 9999`입니다.
앞 묶음은 `z-index: 2`입니다.
노란 자식과 앞 묶음 가운데 어느 쪽이 앞에 보일지 예상해 보세요.

```html
<div class="stack-demo">
  <section class="back-group">
    <div class="very-high">자식 · z-index 9999</div>
  </section>
  <section class="front-group">앞 묶음 · z-index 2</section>
</div>
```

```css
.stack-demo { position: relative; }
.back-group { position: absolute; z-index: 1; }
.very-high { position: absolute; z-index: 9999; }
.front-group { position: absolute; z-index: 2; }
```

크기·위치·색 선언은 생략했습니다.

![파란 뒤 묶음 z-index 1 안에 노란 자식 z-index 9999가 있고 초록 앞 묶음 z-index 2가 오른쪽 아래에서 겹친다. 겹친 부분에서는 초록 앞 묶음이 노란 자식을 가린다.](content/assets/css/position-stacking.png)

앞 묶음이 노란 자식을 가렸습니다.
두 묶음은 각각 쌓임 맥락을 만듭니다.
바깥에서는 두 묶음의 `1`과 `2`만 비교하므로 앞 묶음이 위에 그려집니다.
자식의 `9999`는 뒤 묶음 안에서만 쓰이는 순서라서 앞 묶음을 넘지 못합니다.

그래서 겹친 요소의 순서가 이상하면 자식의 숫자를 키우기 전에 두 요소가 어느 묶음에 속하는지부터 찾습니다.
새 쌓임 맥락을 만드는 대표 조건은 다음과 같습니다.

- 문서의 루트 요소
- `relative`나 `absolute`이면서 `z-index`가 `auto`가 아닌 요소
- `fixed`나 `sticky`인 요소
- `opacity`가 1보다 작은 요소
- `transform`이 `none`이 아닌 요소

> [!note]- 숫자가 같거나 auto이면 어떻게 되나요?
> 같은 쌓임 맥락에서 `z-index`가 같거나 `auto`이면 CSS의 그리기 순서와 HTML 순서가 함께 앞뒤를 정합니다.
> 그래서 나중에 나온 요소가 늘 앞에 온다고 외우기보다 실제로 어떤 묶음에 속하는지 확인합니다.

## position의 활용

지금까지 게시판의 네 요구를 모두 `position`으로 풀었습니다.
실제 페이지에서는 어떤 값을 고르는지를 요구에서 거꾸로 찾아가면 됩니다.

| 요구 | 고를 값 | 함께 확인할 것 |
| --- | --- | --- |
| 원래 자리를 두고 조금만 옮긴다 | `relative` | 주변 요소는 움직이지 않습니다 |
| 부모 상자의 특정 모서리에 붙인다 | 부모는 `relative` · 자식은 `absolute` | 가려질 내용의 공간을 비웁니다 |
| 화면에 계속 보이게 한다 | `fixed` | 조상의 `transform`을 확인합니다 |
| 한 영역을 지나는 동안만 붙인다 | `sticky` | `top` 값과 스크롤 영역을 확인합니다 |
| 겹친 요소의 앞뒤를 바꾼다 | `z-index` | 두 요소의 쌓임 맥락을 먼저 찾습니다 |

반대로 요소끼리 서로 밀어내야 하는 배치에는 `position`을 쓰지 않습니다.
예를 들어 배지 문구의 길이가 달라져 제목과 자리를 나눠 가져야 한다면 [Flexbox](#/learn/css/wiki-flexbox)나 [Grid](#/learn/css/wiki-grid)로 흐름 안에 두는 편이 안전합니다.
흐름에서 빠진 요소는 내용이 길어져도 다른 요소를 밀어내지 않기 때문입니다.

고정하거나 붙인 요소를 만든 뒤에는 화면을 확대해 보고 긴 문구로 바꿔 봅니다.
그 요소가 본문이나 버튼 또는 키보드 포커스를 가리지 않아야 위치 지정이 끝난 것입니다.

## 정리

- `relative`는 원래 자리를 남긴 채 보이는 위치만 옮기고 `absolute`는 흐름에서 빠져 가장 가까운 위치 기준 박스를 따릅니다.
- `fixed`는 흐름에서 빠져 보통 화면에 고정되고 `sticky`는 자리를 남긴 채 자신을 감싼 상자 안에서만 붙습니다.
- `z-index`는 같은 쌓임 맥락 안에서만 비교하므로 자식의 숫자는 부모 묶음을 넘지 못합니다.

## 핵심 질문 답

원래 자리를 남긴 채 조금만 옮기려면 `relative`를 쓰고 흐름에서 빼 특정 기준에 놓으려면 `absolute`를 씁니다.
`absolute`는 `position`이 `static`이 아니거나 `transform`이 있는 가장 가까운 조상을 기준으로 삼습니다.
화면에 계속 보여야 하면 `fixed`를 쓰고 한 영역을 지나는 동안만 붙이려면 `top` 같은 값과 함께 `sticky`를 씁니다.
겹친 요소의 앞뒤는 `z-index` 숫자보다 먼저 두 요소가 속한 쌓임 맥락을 찾아 비교합니다.
