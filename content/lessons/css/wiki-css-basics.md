# CSS 기초: 적용 방법과 선택자

## 학습 목표

- HTML과 CSS의 역할을 구분하고 외부 스타일시트를 `link`로 연결할 수 있습니다.
- CSS 규칙을 선택자·속성·값으로 나눠 읽고 적용되지 않는 선언의 원인을 찾을 수 있습니다.
- 클래스·ID·속성 선택자로 규칙을 적용할 요소를 고를 수 있습니다.
- 공백과 결합자를 보고 같은 요소의 조건인지 요소 사이의 관계인지 구분할 수 있습니다.

## 먼저 확인할 개념

[HTML의 역할과 요소 읽기](#/learn/html/wiki-markup)와 [HTML 문서의 기본 골격](#/learn/html/wiki-document-skeleton)을 알면 CSS를 어디에 연결할지 찾기 쉽습니다.

## CSS란

CSS(Cascading Style Sheets)는 HTML 문서의 내용을 어떤 색·크기·간격·배치로 보여 줄지 정하는 언어입니다.
HTML은 제목·문단·링크처럼 내용의 구조와 의미를 나타냅니다.
CSS는 그 내용이 화면에서 어떻게 보일지를 맡습니다.
그래서 CSS로 링크를 카드처럼 꾸며도 링크가 가진 HTML의 의미는 바뀌지 않습니다.

예를 들어 동네 책모임 안내 페이지를 만든다고 해 보겠습니다.
이 페이지에는 모임 소식을 담은 카드가 있습니다.

```html
<article class="meeting-card">
  <h2>저녁 책모임</h2>
  <p class="notice">오늘 저녁 7시에 만납니다.</p>
</article>
```

이 카드에 CSS를 연결하면 무엇이 바뀌고 무엇이 그대로일지 먼저 예상해 보세요.

![CSS를 연결하지 않은 왼쪽 카드는 브라우저 기본 모양의 제목과 문단만 보인다. styles.css를 연결한 오른쪽 카드는 같은 제목과 문단에 회색 테두리와 안쪽 간격이 생기고 문단 글자가 남색으로 바뀌었다.](content/assets/css/basics-role.png)

두 카드의 제목과 문단은 똑같이 남아 있습니다.
바뀐 것은 테두리·안쪽 간격·글자색뿐입니다.
CSS는 내용을 바꾸지 않고 보이는 모습만 정하기 때문입니다.

이 문서는 책모임 페이지 하나로 CSS 연결 방법·규칙 읽는 법·선택자를 차례로 살펴봅니다.
먼저 CSS 파일을 HTML에 연결하는 방법부터 보겠습니다.

## 스타일시트 연결 방법

CSS 규칙을 모아 둔 파일을 스타일시트라고 합니다.
보통 스타일시트는 별도 파일로 만들고 HTML의 `head`에 `link` 요소를 둡니다.

```html
<link rel="stylesheet" href="styles.css">
```

`rel="stylesheet"`는 스타일시트 연결임을 알리고 `href`는 파일의 위치를 가리킵니다.
이 예의 `styles.css`는 HTML 문서 위치를 기준으로 찾습니다.
여러 HTML 문서가 같은 파일을 사용하고 구조와 표현을 나눠 관리할 수 있습니다.

책모임 사이트의 폴더가 다음과 같다고 해 보겠습니다.

```text
site/
├── pages/
│   └── meeting.html
└── css/
    └── site.css
```

`meeting.html`에서 `site.css`를 연결하려면 경로를 어떻게 적어야 할지 예상해 보세요.

```html
<link rel="stylesheet" href="../css/site.css">
```

`meeting.html`은 `pages` 폴더 안에 있습니다.
`..`로 한 단계 위인 `site` 폴더로 올라간 뒤 `css/site.css`를 찾아야 합니다.
`href="css/site.css"`라고만 적으면 `pages` 폴더 안의 `css` 폴더를 찾기 때문에 파일을 불러오지 못합니다.
`link`는 주소를 `href`에 적으며 `src`에 적으면 연결할 주소가 지정되지 않습니다.

CSS를 적는 곳은 외부 파일 말고도 두 곳이 더 있습니다.

| 적는 곳 | 모양 | 쓰는 경우 |
| --- | --- | --- |
| 외부 파일 | `<link rel="stylesheet" href="styles.css">` | 일반 프로젝트의 기본 방법 |
| `style` 요소 | `<style> .notice { color: navy; } </style>` | 한 파일에서 확인하는 작은 예제 |
| `style` 속성 | `<p style="color: navy;">` | 재사용하기 어렵고 HTML과 표현이 섞이기 쉬움 |

그래서 일반 프로젝트에서는 외부 파일부터 사용합니다.
이제 연결한 파일 안의 규칙을 읽어 보겠습니다.

## CSS 규칙의 구조

CSS 규칙은 어떤 요소에 어떤 모양을 줄지를 한 덩어리로 적은 것입니다.

```css
.notice {
  color: navy;
  padding: 1rem;
}
```

| 부분 | 예 | 역할 |
| --- | --- | --- |
| 선택자 | `.notice` | 규칙을 적용할 요소를 찾습니다 |
| 속성 | `color` | 바꾸려는 성질을 정합니다 |
| 값 | `navy` | 속성에 사용할 값을 정합니다 |
| 선언 | `color: navy;` | 속성과 값을 한 쌍으로 적습니다 |

중괄호 안은 선언 블록입니다.
콜론은 속성과 값을 나누고 세미콜론은 선언과 선언을 나눕니다.
선택자가 요소와 맞아야 그 규칙이 적용될 후보가 됩니다.

그런데 선언 하나의 값이 잘못되면 어떻게 될까요?
`color`에 색이 아닌 `12px`를 적었을 때 문단이 어떻게 보일지 예상해 보세요.

![왼쪽은 color navy와 padding 1rem이 모두 올바른 규칙으로 남색 글자와 안쪽 간격이 적용되었다. 오른쪽은 color를 12px로 잘못 적은 규칙으로 글자는 기본 검은색이지만 안쪽 간격은 그대로 적용되었다.](content/assets/css/basics-invalid.png)

오른쪽 문단은 글자색만 기본색으로 돌아갔고 안쪽 간격은 그대로입니다.
브라우저는 값이 잘못된 `color` 선언 하나만 무시하고 세미콜론으로 나뉜 `padding` 선언은 계속 처리하기 때문입니다.
CSS 파일 전체가 무효가 되지 않고 오류 창도 뜨지 않습니다.

한 선언만 적용되지 않는다면 속성 이름과 그 속성에 허용되는 값을 확인합니다.
브라우저는 보통 유효하지 않은 선언을 무시하므로 오류 창을 기다리기보다 개발자 도구의 Styles에서 규칙이 인식되는지 살핍니다.

> [!note]- 개발자 도구에서 무시된 선언은 어떻게 보이나요?
> 브라우저의 개발자 도구에서 요소를 고르면 Styles 창에 그 요소와 맞는 규칙이 모두 보입니다.
> 값이 잘못된 선언은 줄이 그어지거나 경고 표시가 붙습니다.
> 규칙 자체가 보이지 않으면 선택자가 요소와 맞지 않거나 파일이 연결되지 않은 것입니다.

선언은 규칙의 절반입니다.
나머지 절반인 선택자가 요소를 어떻게 찾는지 살펴보겠습니다.

## 선택자의 종류

선택자는 규칙을 적용할 요소를 고르는 조건입니다.
책모임 페이지의 요소를 무엇으로 찾는지에 따라 선택자의 모양이 달라집니다.

| 선택자 | 찾는 대상 | 책모임 페이지에서 쓰는 곳 |
| --- | --- | --- |
| `p` | `p`라는 요소 이름을 가진 모든 문단 | 페이지의 모든 문단 |
| `.notice` | `notice` 클래스를 가진 요소 | 안내 문단 |
| `#today` | `today`라는 ID를 가진 요소 | 오늘 모임 문단 하나 |
| `input[required]` | `required` 속성이 있는 input | 신청 폼의 필수 칸 |
| `input[type="email"]` | type 속성값이 email인 input | 신청 폼의 이메일 칸 |

같은 역할의 여러 요소가 모양을 공유하면 클래스를 재사용합니다.
ID는 문서 안에서 대상 하나를 고유하게 식별하는 값입니다.
그래서 CSS를 강하게 만들려고 같은 ID를 여러 요소에 반복하지 않습니다.

클래스는 `.`으로 찾고 ID는 `#`으로 찾습니다.
`class="meeting-card"`를 찾을 때는 `.meeting-card`를 쓰며 `#meeting-card`와 바꿔 쓸 수 없습니다.
`#meeting-card`는 `id="meeting-card"`인 요소를 요구하기 때문입니다.

선택자 하나로 요소를 찾을 수 있게 되었습니다.
이제 선택자 여러 개를 이어 조건을 좁혀 보겠습니다.

## 결합자 사용법

선택자를 이을 때는 사이에 무엇을 두는지가 중요합니다.
공백 없이 이으면 같은 요소가 가진 조건이 늘어납니다.
공백이나 `>`·`+`·`~`를 두면 요소 사이의 관계를 나타냅니다.
요소 사이의 관계를 나타내는 이 기호를 결합자(combinator)라고 합니다.

책모임 카드가 이달의 추천 카드여서 `featured` 클래스가 붙었다고 해 보겠습니다.
안쪽 제목에도 같은 이름의 클래스가 있습니다.
두 규칙이 각각 바깥 article과 안쪽 h2 가운데 어느 요소를 바꿀지 먼저 예상해 보세요.

```html
<article class="meeting-card featured">
  <h2 class="featured">이달의 책</h2>
  <p class="notice">오늘 저녁 7시에 만납니다.</p>
</article>
```

```css
.meeting-card.featured {
  border-color: royalblue;
}

.meeting-card .featured {
  color: royalblue;
}
```

![왼쪽은 공백 없이 이은 meeting-card.featured 선택자로 article 자체의 테두리가 파랗게 바뀌었다. 오른쪽은 공백을 넣은 meeting-card featured 선택자로 article 안쪽 제목 이달의 책의 글자만 파랗게 바뀌었다.](content/assets/css/basics-compound.png)

`.meeting-card.featured`는 두 클래스를 동시에 가진 같은 요소를 선택합니다.
`.meeting-card .featured`의 공백은 후손 관계이므로 카드 안쪽의 별도 featured 요소를 선택합니다.
이 예에서는 앞 선택자가 article과 일치하고 뒤 선택자가 h2와 일치합니다.

공백 하나 때문에 CSS가 찾는 대상이 달라집니다.
같은 이유로 `article .meeting-card`는 article 안쪽에 있는 다른 `.meeting-card` 후손을 찾습니다.
이 예의 article은 자신이 카드이므로 이 선택자와 일치하지 않습니다.

공백 말고도 관계를 나타내는 결합자가 세 가지 더 있습니다.
카드 안에 지난 모임을 담은 div가 있을 때 각 결합자가 어느 요소를 고르는지 보겠습니다.

```html
<article class="meeting-card">
  <h2>이번 달 모임</h2>
  <p>첫째 문단</p>
  <p>둘째 문단</p>
  <div class="past">
    <h2>지난 모임</h2>
    <p>지난 문단</p>
  </div>
</article>
```

![같은 카드에 네 선택자를 적용한 결과다. meeting-card h2는 이번 달 모임과 div 안의 지난 모임 제목을 모두 고른다. meeting-card 자식 결합자 h2는 이번 달 모임 제목만 고른다. h2 더하기 p는 첫째 문단과 지난 문단을 고른다. h2 물결 p는 첫째 문단과 둘째 문단과 지난 문단을 고른다.](content/assets/css/basics-combinators.png)

| 선택자 | 관계 | 이 카드에서 고른 요소 |
| --- | --- | --- |
| `.meeting-card h2` | 카드 안의 모든 단계에 있는 h2 후손 | 이번 달 모임 · 지난 모임 |
| `.meeting-card > h2` | 카드 바로 아래의 h2 자식 | 이번 달 모임 |
| `h2 + p` | 같은 부모 안에서 h2 바로 다음에 오는 p 형제 | 첫째 문단 · 지난 문단 |
| `h2 ~ p` | 같은 부모 안에서 h2 뒤에 오는 p 형제들 | 첫째 · 둘째 · 지난 문단 |

카드 안에 div가 있고 그 안에 h2가 있다면 `.meeting-card h2`는 그 h2와 일치하지만 `.meeting-card > h2`는 일치하지 않습니다.
지난 모임 제목의 바로 위 부모는 카드가 아니라 div이기 때문입니다.
`+`와 `~`는 같은 부모 안의 뒤쪽 형제만 찾습니다.
그래서 `.meeting-card + h2`는 카드 안쪽 제목이 아니라 카드 바로 뒤에 오는 형제 h2를 찾습니다.

> [!note]- .meeting-card.h2는 h2 요소를 고를까요?
> 공백 없이 이은 `.h2`는 요소 이름이 아니라 `h2`라는 클래스를 뜻합니다.
> 그래서 `.meeting-card.h2`는 두 클래스를 모두 가진 요소를 찾습니다.
> 요소 이름으로 찾으려면 점 없이 `h2`라고 적습니다.

이제 선택자를 읽을 수 있게 되었습니다.
마지막으로 실제 페이지에서 선택자를 어떻게 고르고 문제를 찾는지 정리해 보겠습니다.

## 선택자의 활용

선택자는 HTML 구조를 따라 얼마든지 길게 만들 수 있습니다.
그런데 HTML 구조에 의존하는 긴 선택자는 HTML이 조금만 바뀌어도 요소와 일치하지 않을 수 있습니다.

```css
/* 구조에 기댄 선택자 */
.meeting-card > div > h2 { color: gray; }

/* 역할을 나타내는 클래스 */
.past-title { color: gray; }
```

지난 모임 제목을 감싼 div가 하나 더 생기면 첫 규칙은 더 이상 제목과 일치하지 않습니다.
반면 제목에 `past-title` 클래스를 붙인 둘째 규칙은 구조가 바뀌어도 그대로 적용됩니다.
그래서 HTML 구조에 의존하는 선택자를 계속 길게 만들기보다 역할을 나타내는 클래스 하나로 찾을 수 있는지 먼저 살핍니다.

스타일이 예상과 다를 때는 다음 순서로 원인을 좁힙니다.

| 증상 | 먼저 확인할 것 |
| --- | --- |
| CSS가 전혀 보이지 않음 | 파일 경로·이름·대소문자와 개발자 도구 Network의 요청 성공 여부 |
| 한 규칙이 전혀 적용되지 않음 | HTML의 `class`와 CSS 선택자가 맞는지와 공백·결합자 |
| 한 선언만 적용되지 않음 | 속성 이름과 그 속성이 받는 값의 종류 |

원하는 규칙이 보이지 않으면 선언을 고치기 전에 개발자 도구에서 실제로 선택된 요소를 확인합니다.

## 정리

- CSS는 HTML 내용의 표현을 정하며 보통 `head`의 `link`에 HTML 문서 기준 경로를 적어 외부 파일로 연결합니다.
- 규칙은 선택자와 선언으로 이루어지고 값이 잘못된 선언은 그 선언 하나만 무시됩니다.
- 공백 없이 이은 선택자는 같은 요소의 조건이고 공백·`>`·`+`·`~`는 후손·자식·형제 관계입니다.

이어서 [캐스케이드와 상속](#/learn/css/wiki-cascade)에서 여러 규칙이 한 요소에 겹칠 때 어느 값이 남는지 확인해 보세요.

## 공식 자료

- [WHATWG HTML — link 요소](https://html.spec.whatwg.org/multipage/semantics.html#the-link-element)
- [CSS Syntax Module Level 3](https://www.w3.org/TR/css-syntax-3/)
- [Selectors Level 4 — 선택자 구조](https://www.w3.org/TR/selectors-4/#structure)

## 핵심 질문 답

HTML은 내용의 구조와 의미를 맡고 CSS는 그 내용의 표현을 맡습니다.
보통 `head`의 `link`에 HTML 문서 기준 경로를 적어 외부 CSS 파일을 연결하고 규칙의 선택자로 대상을 찾은 뒤 속성에 값을 적용합니다.
선택자를 공백 없이 이으면 같은 요소의 조건이 되고 공백이나 `>`·`+`·`~`를 넣으면 후손·자식·형제 관계를 나타냅니다.
스타일이 전혀 보이지 않으면 연결 경로부터 확인하고 일부 선언만 빠지면 선택자와 속성·값을 확인합니다.
