# 일반 흐름과 넘침: display와 overflow

## 학습 목표

- 일반 흐름에서 block과 inline 박스가 놓이는 방식을 보고 같은 줄·새 줄·숨김 요구에 맞는 `display` 값을 고를 수 있습니다.
- `display`가 바깥 흐름과 자식 배치를 정할 뿐 HTML 의미는 바꾸지 않는다는 점을 구분할 수 있습니다.
- 흐름에 놓인 박스보다 내용이 커질 때 넘침의 원인을 찾고 줄바꿈으로 해결할 수 있습니다.
- 높이를 제한해야 할 때 `overflow` 값을 골라 내용을 자르지 않고 모두 읽게 할 수 있습니다.

## 먼저 확인할 개념

[박스 모델과 간격](#/learn/css/wiki-box-model)에서 요소가 차지하는 영역과 너비에 포함되는 부분을 먼저 확인해 보세요.

## 일반 흐름이란

일반 흐름은 따로 배치를 정하지 않았을 때 박스가 HTML 순서대로 자리를 차지하는 기본 배치입니다.
제목과 문단 같은 요소는 위에서 아래로 쌓이고 링크 같은 요소는 글줄 안에서 글자처럼 이어집니다.
이 흐름 위에서 박스가 놓이는 방식을 바꾸는 속성이 `display`입니다.
그리고 박스보다 내용이 커서 밖으로 나오는 것을 넘침이라고 하며 넘친 부분을 어떻게 보일지는 `overflow`가 정합니다.

예를 들어 마을 도서관 소식 페이지를 만든다고 해 보겠습니다.
이 페이지에는 네 가지 요구가 있습니다.

- 소식 카드에 제목과 문단과 `자세히 보기` 링크를 둡니다.
- 문장 안에 `NEW` 배지를 붙입니다.
- 공백 없는 긴 예약 번호를 카드 안에 보여 줍니다.
- 길이를 알 수 없는 대출 알림 기록을 일정 높이까지만 보여 줍니다.

먼저 소식 카드부터 아무 배치도 정하지 않고 적어 보겠습니다.

```html
<article class="notice">
  <h2>오늘의 마을 소식</h2>
  <p>도서관은 오후 8시에 문을 닫습니다. 내일부터 새 책 대출을 시작합니다. <a href="/library">자세히 보기</a></p>
</article>
```

![왼쪽은 소식 카드다. 제목과 문단은 각각 카드 너비를 가득 채운 block 박스로 위아래에 놓이고 자세히 보기 링크는 문단의 둘째 줄 글자 뒤에 이어진다. 오른쪽은 너비 300px 부모 안의 width 100px block 두 개다. 오른쪽에 빈 공간이 남아도 둘째가 첫째 아래 새 줄에 놓인다.](content/assets/css/flow-normal.png)

별도 배치를 정하지 않으면 제목과 문단은 보통 새 줄에 놓이고 링크는 글줄 안에서 이어집니다.
이처럼 문서 순서를 바탕으로 박스가 놓이는 기본 배치가 일반 흐름입니다.
HTML 순서만으로도 내용을 이해할 수 있게 만든 뒤 필요한 곳에 다른 배치를 적용합니다.

오른쪽 그림처럼 block 박스는 가로 공간이 남아도 옆에 붙지 않습니다.
부모가 Flexbox나 Grid가 아닌 일반 block 배치라면 형제 block은 문서 순서대로 위에서 아래로 놓이기 때문입니다.

그렇다면 배지처럼 글줄 안에 두면서 박스 크기도 정하고 싶을 때는 어떻게 할까요?

## display의 종류

`display`의 값은 박스가 주변 흐름에서 새 줄을 차지하는지와 크기를 다룰 수 있는지로 나눌 수 있습니다.

| 값 | 놓이는 자리 | width·height | 도서관 페이지에서 쓰는 곳 |
| --- | --- | --- | --- |
| `block` | 보통 새 줄 | 적용됨 | 제목·문단 |
| `inline` | 글줄 안 | 일반적인 비대체 요소에는 적용되지 않음 | 링크·강조 글자 |
| `inline-block` | 글줄 안의 박스 하나 | 적용됨 | 문장 안의 배지 |
| `none` | 박스를 만들지 않음 | 없음 | 지금 보이지 않아야 하는 안내 |

비대체 요소는 `span`이나 `a`처럼 내용을 글자로 그리는 요소입니다.
반대로 `img`처럼 외부 내용으로 채워지는 요소는 대체 요소라 inline이어도 크기를 정할 수 있습니다.

같은 배지에 크기와 padding을 주고 `display`만 바꿔 보겠습니다.
배지가 줄 안에 남을지와 5rem 너비가 적용될지 먼저 예상해 보세요.

```css
.badge {
  width: 5rem;
  height: 2rem;
  padding: 0.25rem 0.5rem;
}
```

![같은 NEW 배지에 display 값만 바꾼 네 결과다. inline은 글자와 padding만큼만 칠해지고 width와 height가 적용되지 않는다. inline-block은 문장과 같은 줄에서 5rem 너비 2rem 높이 박스가 된다. block은 배지 앞뒤로 줄이 나뉜다. none은 배지와 그 자리가 모두 사라진다.](content/assets/css/flow-display-badge.png)

inline-block은 같은 줄에 놓이면서도 너비·높이를 가진 하나의 박스로 다룰 수 있습니다.
일반적인 비대체 inline은 글줄의 흐름이 우선이고 block은 보통 새 줄에 놓입니다.
그래서 문장 안의 배지에는 `display: inline-block`을 씁니다.

> [!note]- inline에 준 padding은 왜 보이나요?
> inline 박스에도 padding과 배경은 그려집니다.
> 그런데 위아래 padding은 줄 높이를 늘리지 않아 윗줄이나 아랫줄과 겹칠 수 있습니다.
> 위아래 공간까지 박스처럼 차지해야 한다면 inline-block을 고릅니다.

배지의 모양은 정했습니다.
이제 `display`가 자식 배치와 HTML 의미에는 어떤 영향을 주는지 살펴보겠습니다.

## display 사용법

`display`는 두 가지를 함께 정합니다.
하나는 이 박스가 바깥 흐름에 어떻게 참여하는지이고 다른 하나는 바로 아래 자식을 어떻게 배치하는지입니다.

```css
.notice-list {
  display: flex;
}
```

`display: flex`인 목록은 바깥 흐름에서는 block처럼 하나의 박스로 새 줄을 차지합니다.
그리고 바로 아래 자식을 flex item으로 배치합니다.
grid도 직접 자식의 안쪽 배치 규칙을 바꿉니다.
손자까지 자동으로 flex item이나 grid item이 되지는 않습니다.

`display`를 바꿔도 HTML 의미가 바뀌지는 않습니다.
`div`를 inline으로 표시해도 링크나 버튼이 되지 않습니다.
그래서 의미에 맞는 HTML 요소를 먼저 고르고 모양은 `display`로 맞춥니다.

요소를 숨길 때도 같은 원칙을 따릅니다.
`display: none`은 요소의 박스를 없애며 일반적으로 접근성 트리에서도 제외합니다.
그래서 화면 낭독기 같은 보조 기술도 그 내용을 읽지 않습니다.
화면에서만 숨기고 보조 기술에는 내용을 남기려는 목적과는 다릅니다.

> [!note]- visibility: hidden은 무엇이 다른가요?
> `visibility: hidden`은 공간을 남기지만 그려지지 않으며 보통 조작과 읽기 대상에서도 빠집니다.
> 다만 이 값을 상속받은 자손에 `visibility: visible`을 주면 그 자손은 다시 보입니다.
> 그래서 공간이 남는지만 보고 접근성 결과를 판단하지 않고 중요한 기능은 실제 브라우저와 보조 기술에서 확인합니다.

지금까지는 박스가 흐름에 놓이는 방식을 정했습니다.
그런데 박스 크기를 정해 두면 그 안에 든 내용이 박스보다 커지는 일이 생깁니다.

## 넘침의 원인

넘침은 박스가 내용을 담기에 작을 때 생깁니다.
그래서 먼저 박스 크기를 어떻게 정했는지 확인합니다.

```css
.notice {
  box-sizing: border-box;
  width: 100%;
  max-width: 17rem;
  padding: 1rem;
  border: 2px solid #6941b8;
}
```

`width`는 기본 크기입니다.
`min-width`는 줄어들 수 있는 아래 한계이고 `max-width`는 커질 수 있는 위 한계입니다.
이 카드는 부모만큼 넓어지다가 17rem에서 멈춥니다.
고정 너비 하나만 정하기보다 부모가 좁아지거나 내용이 길 때 어디까지 줄고 커질지 생각합니다.
padding과 border가 있다면 `box-sizing`이 무엇인지도 함께 확인합니다.

이제 이 카드에 공백과 하이픈이 없는 긴 예약 번호를 넣어 보겠습니다.
카드 너비가 줄어들 수 있는데도 번호가 카드 안에 머물지 예상해 보세요.

```html
<article class="notice">
  <h3>예약 번호</h3>
  <p>ABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789</p>
</article>
```

```css
.notice p {
  overflow-wrap: anywhere;
}
```

![위는 기본값인 overflow-wrap normal 결과다. 예약 번호가 한 줄로 이어져 카드 오른쪽 테두리 밖으로 나간다. 아래는 overflow-wrap anywhere를 준 결과다. 같은 번호가 카드 너비 안에서 세 줄로 나뉘어 모두 보인다.](content/assets/css/flow-long-token.png)

기본값에서는 번호가 카드 밖으로 나갔습니다.
영문과 숫자로 이어진 문자열은 보통 공백이나 하이픈에서만 줄이 바뀌는데 이 번호에는 끊을 곳이 없기 때문입니다.
`overflow-wrap: anywhere`를 주면 한 줄에 들어가지 않는 문자열의 아무 곳에서나 줄을 바꿀 수 있습니다.
그래서 카드 너비를 유지한 채 번호 전체를 여러 줄로 읽을 수 있습니다.

넘침의 원인은 긴 문자열만이 아닙니다.
부모보다 큰 고정 크기·빠뜨린 padding과 border 계산·큰 이미지·Flex나 Grid 자식의 기본 최소 크기도 넘침을 만듭니다.
그래서 줄바꿈 한 줄을 넣기 전에 무엇이 박스보다 큰지부터 찾습니다.

> [!note]- break-word와 anywhere는 무엇이 다른가요?
> 두 값 모두 끊을 곳이 없는 문자열의 중간에서 줄을 바꿉니다.
> 차이는 요소의 최소 크기를 계산할 때 나타납니다.
> `anywhere`는 그 줄바꿈 가능성을 최소 크기에 반영하므로 Flex나 Grid 안에서 항목이 더 좁게 줄어들 수 있습니다.

넘침의 원인을 고칠 수 없을 때도 있습니다.
길이를 알 수 없는 기록을 일정 높이까지만 보여 줘야 할 때가 그렇습니다.

## overflow의 종류

`overflow`는 박스를 넘친 내용을 어떻게 보일지 정하는 속성입니다.

| 값 | 넘친 내용 | 스크롤 |
| --- | --- | --- |
| `visible` | 기본값이며 박스 밖에도 그대로 보임 | 없음 |
| `auto` | 박스 안에서만 보임 | 실제로 넘칠 때만 스크롤할 수 있음 |
| `scroll` | 박스 안에서만 보임 | 넘치지 않아도 스크롤 영역을 만듦 |
| `hidden` | 잘림 | 사용자가 직접 스크롤하는 수단은 없고 프로그램 스크롤은 가능함 |
| `clip` | 잘림 | 프로그램 스크롤도 허용하지 않음 |

대출 알림 기록 패널에 높이와 overflow를 세 가지 조합으로 주어 보겠습니다.
12줄짜리 기록이 각 조합에서 어떻게 보일지와 기록이 3줄뿐일 때 auto 패널의 높이를 먼저 예상해 보세요.

```css
.log-panel {
  max-height: 12rem;
  overflow: auto;
}
```

![대출 알림 기록 패널의 네 결과다. 첫째 height 12rem과 overflow hidden은 10번째 줄부터 잘리고 스크롤 막대가 없다. 둘째 height 12rem과 overflow visible은 넘친 10번째부터 12번째 줄이 패널 밖으로 흘러 다음 문단과 겹친다. 셋째 max-height 12rem과 overflow auto는 12rem에서 멈추고 스크롤 막대가 생겨 끝까지 내리면 12번째 줄까지 보인다. 넷째 같은 선언에 기록이 3줄이면 패널이 3줄 높이만 차지한다.](content/assets/css/flow-log-panel.png)

max-height는 내용이 짧을 때 필요한 높이를 쓰면서 최대 높이를 제한합니다.
overflow auto를 함께 쓰면 제한을 넘는 내용을 스크롤해 확인할 수 있습니다.
고정 height와 hidden으로 자르면 직접 읽을 수 있는 스크롤 수단이 사라집니다.
고정 height와 visible을 쓰면 넘친 내용이 뒤따르는 문단과 겹칩니다.

내용을 자르는 것은 원인을 해결하는 것과 다릅니다.
잘린 곳에 버튼이나 링크가 있다면 사용자가 그 기능을 보지 못하거나 닿지 못할 수 있습니다.
그래서 `hidden`이나 `clip`을 쓰기 전에 가려지는 정보와 조작 수단이 없는지 확인합니다.

스크롤 영역을 만들었다면 키보드와 보조 기술로도 그 안을 탐색할 수 있는지 확인합니다.
설명 문단처럼 높이를 제한할 필요가 없다면 내용이 자연스럽게 늘어나게 두는 편이 단순합니다.

> [!question]- 스크롤 영역을 키보드로 내릴 수 없을 때
> 1. 영역 안에 링크나 버튼처럼 포커스를 받을 요소가 있나요?
> 2. 없다면 영역에 `tabindex="0"`을 주어 Tab으로 들어갈 수 있게 했나요?
> 3. 포커스를 받는 영역에 무엇을 담았는지 알려 주는 이름을 붙였나요?

## 일반 흐름과 넘침의 활용

지금까지 도서관 페이지의 네 요구를 흐름과 넘침으로 풀었습니다.
실제 페이지에서는 요구에서 거꾸로 값을 찾아가면 됩니다.

| 요구 | 고를 값 | 함께 확인할 것 |
| --- | --- | --- |
| 제목과 문단을 새 줄에 둔다 | 기본 `block` | HTML 순서만으로 읽히는지 확인합니다 |
| 문장 안에서 박스 크기를 정한다 | `inline-block` | 줄 높이와 겹치지 않는지 봅니다 |
| 자식을 가로로 나란히 둔다 | 부모에 `flex`나 `grid` | 바로 아래 자식만 배치됩니다 |
| 요소를 박스와 자리까지 없앤다 | `none` | 보조 기술에서도 사라집니다 |
| 끊을 곳 없는 문자열을 담는다 | `overflow-wrap: anywhere` | 다른 넘침 원인이 없는지 찾습니다 |
| 긴 기록을 일정 높이까지만 보인다 | `max-height`와 `overflow: auto` | 키보드로 스크롤할 수 있는지 봅니다 |

카드를 여러 개 나란히 놓으면 Flex 항목의 기본 최소 크기 때문에 새로운 넘침이 생기기도 합니다.
이 경우는 [Flexbox로 한 축 정렬하기](#/learn/css/wiki-flexbox)에서 항목이 줄어드는 조건과 함께 살펴봅니다.

## 정리

- 일반 흐름에서 block은 새 줄에 놓이고 inline은 글줄 안에서 이어지며 inline-block은 같은 줄에서 크기를 가진 박스가 됩니다.
- `display`는 바깥 흐름과 바로 아래 자식의 배치를 정할 뿐 HTML 의미를 바꾸지 않고 `none`은 박스와 접근성 트리에서 요소를 함께 뺍니다.
- 넘치면 무엇이 박스보다 큰지 먼저 찾고 긴 문자열은 줄바꿈을 허용하며 높이 제한이 필요한 기록은 `max-height`와 `overflow: auto`로 모두 읽게 합니다.

## 핵심 질문 답

일반 흐름에서 새 줄의 박스는 block을 쓰고 글줄 안의 내용은 inline을 쓰며 같은 줄에서 크기를 다뤄야 하면 inline-block을 씁니다.
`display`는 바깥 흐름과 바로 아래 자식의 배치를 정할 뿐 HTML 의미를 바꾸지 않으므로 의미에 맞는 요소를 먼저 고르고 숨길 때는 보조 기술에 미치는 영향도 확인합니다.
내용이 넘치면 고정 크기·긴 문자열·박스 계산·자식의 최소 크기 가운데 무엇이 원인인지 먼저 찾고 긴 문자열에는 `overflow-wrap: anywhere`로 줄바꿈을 허용합니다.
높이를 제한해야 하는 기록은 `max-height`와 `overflow: auto`로 모두 읽게 하고 `hidden`이나 `clip`으로 자를 때는 가려지는 정보와 조작 수단을 확인합니다.
