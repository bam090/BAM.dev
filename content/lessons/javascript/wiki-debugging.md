# 실제 값으로 디버깅하기

## 학습 목표

문제를 재현하고 중단점에서 값과 타입을 비교해 처음 어긋난 단계를 찾을 수 있습니다.

## 한줄 요약

정상인 단계의 증거를 남긴 뒤 다음 경계의 실제 값과 호출을 확인하면 디버깅 범위를 줄일 수 있습니다.

## 먼저 확인할 개념

[입력 검증과 오류 종류](#/learn/javascript/wiki-errors-input) · [폼 입력에서 상태와 화면으로](#/learn/javascript/wiki-forms-state)를 먼저 확인하면 이어지는 흐름을 읽기 쉽습니다.

## 디버깅은 값이 처음 어긋난 지점을 찾는 일이다

디버깅(debugging)은 오류의 원인을 찾고 고치는 과정이다.
보이는 증상에 코드를 무작정 더하기보다 다음 순서로 범위를 줄인다.

1. 같은 입력과 순서로 문제를 다시 만든다.
2. Console에서 오류 이름, 파일, 줄을 확인한다.
3. 오류가 난 값이 어디에서 왔는지 호출 흐름을 거슬러 올라간다.
4. 의심되는 줄 앞에서 실행을 멈춘다.
5. 실제 값과 예상한 값을 비교한다.
6. 한 단계씩 실행해 값이 처음 달라지는 줄을 찾는다.

스택 추적(stack trace)은 `어떤 함수들이 차례로 호출되어 현재 위치에 왔는지` 보여 주는 디버깅 정보다.
표시 형식은 JavaScript 언어가 하나로 정한 것이 아니므로 브라우저마다 다를 수 있다.
맨 위 줄만 보고 끝내지 말고 처음 나타나는 내가 작성한 코드와 그 입력을 함께 본다.

## 브라우저 개발자 도구에서 실행을 멈추고 본다

주요 브라우저의 개발자 도구에는 JavaScript 실행을 멈추고 값을 살펴보는 기능이 있다.
메뉴 이름과 화면 배치는 브라우저마다 다르므로, 여기서는 특정 브라우저의 버튼 위치보다 공통 원리를 배운다.

중단점(breakpoint)은 `이 줄을 실행하기 직전에 잠시 멈추라`고 표시한 자리다.
실행이 멈추면 화면에 찍힌 마지막 결과만 보는 대신 현재 변수와 호출 순서를 직접 볼 수 있다.

```js
function makeLabel(name, count) {
  const total = count + 1;
  return `${name}: ${total}개`;
}

const label = makeLabel("연필", "2");
console.log(label); // "연필: 21개"
```

이 예에서 `count`가 숫자 `2`가 아니라 문자열 `"2"`이므로 `+`가 덧셈 대신 문자열 연결을 한다.
`const total = count + 1` 줄에 중단점을 두면 실행 전에 `count`의 실제 값과 타입을 확인할 수 있다.

개발자 도구에서 주로 확인하는 기능은 다음과 같다.

| 도구 | 확인하는 것 |
| --- | --- |
| Scope | 현재 멈춘 위치에서 사용할 수 있는 변수와 값 |
| Call Stack | 어떤 함수 호출을 거쳐 이곳에 왔는지 |
| Step over | 현재 줄을 실행하되 호출한 함수 안으로 들어가지 않음 |
| Step into | 호출할 함수 안으로 들어가 한 단계씩 봄 |
| Step out | 현재 함수의 나머지를 실행하고 호출한 곳으로 나감 |
| Resume | 다음 중단점까지 실행을 계속함 |

`console.log()`는 흐름을 빠르게 살펴볼 때 유용하다.
그러나 로그를 더 찍을수록 원인이 선명해지는 것은 아니다.
특정 순간의 여러 값과 호출 순서가 필요하면 중단점과 단계 실행이 더 직접적인 증거를 준다.

## 정상임을 확인한 다음 경계 살피기

이벤트가 발생하고 입력값을 올바르게 읽었으며 계산 함수가 기대한 값을 반환했는데 화면만 다르다면, 다음은 출력 함수의 호출과 대상 DOM 요소를 확인한다.
앞 단계가 정상이라는 증거가 있으면 그 부분을 무작정 다시 작성하지 않는다.

```text
이벤트 실행 확인 → 입력값과 타입 확인 → 계산 결과 확인 → render 호출과 출력 요소 확인
```

예를 들어 계산 결과는 5000인데 화면에 이전 3000이 남아 있다면 render에 전달한 값과 textContent를 바꾸는 요소를 살핀다.
반면 계산 결과부터 21처럼 잘못됐다면 `count + 1` 직전의 count가 숫자 2인지 문자열 "2"인지 확인하는 것이 먼저다.
관찰하지 않은 단계를 정상이라고 가정해서도 안 된다.

## 핵심 질문 답

같은 입력으로 재현한 뒤 오류 위치와 호출 흐름을 확인하고 의심되는 연산 직전에 멈춰 실제 값·타입을 비교합니다. 이벤트·입력·계산까지 정상이라는 증거가 있으면 앞을 다시 쓰기보다 출력 함수가 호출되는지와 올바른 DOM 요소를 바꾸는지 확인합니다. 증거가 없는 단계를 건너뛰지 않고 첫 어긋남을 찾습니다.
