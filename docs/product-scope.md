# 제품 목표와 오프라인 개인 학습 MVP

## 제품 목표

`[확정 결정]` BAM.dev는 초보 개발자가 문법을 읽는 데서 멈추지 않고 다음 순환을 스스로 수행하도록 돕는 개인 학습 가이드다.

```text
개념을 자신의 말로 설명한다
→ 문제의 조건과 관찰 지점을 찾는다
→ 접근 방식을 선택하고 이유를 말한다
→ 직접 구현한다
→ 공개된 근거로 결과와 실패를 확인한다
→ 힌트를 줄인 새로운 문제에 다시 적용한다
```

정답을 먼저 보여 주거나 문제 수를 채우는 것은 목표가 아니다. 실행하지 않은 코드 결과를 만들지 않고, 학습자 결과에는 설치본에 포함된 공개 테스트·공개 기준만 사용한다. 접근성과 모바일 사용성은 별도 부가 기능이 아니라 학습 완료 조건이다.

## 첫 학습 서비스 범위

[최신 독립 학습·홈·사용자 편의 결정](roadmap.md#2026-09-12-확정-제품-결정)을 적용한다. 사용자 편의를 제품 판단의 최우선 기준으로 삼아 원하는 서비스·자료·문제를 쉽게 찾고, 상태를 잃지 않고 중단·복귀하며, 불필요한 선택·반복 입력을 줄이는 흐름을 설계한다. 정확성·접근성·비공개 자료 보호는 유지한다.

첫 화면은 BAM.dev 소개와 **학습문서 / 객관식 문제**의 독립 진입을 제공한다. 밤위키는 콘텐츠 제작 재료이고 개인 위키·수업 일정이 서비스 이용의 조건이 아니다. 첫 콘텐츠 목표는 HTML·CSS·JavaScript·Java 문서와 객관식이며 확장 순서는 [로드맵](roadmap.md#학습문서객관식의-우선-완성-순서)에 둔다. 아래 설치형 전체 MVP와 첫 사용 흐름의 완료는 구분한다. 앞선 2026-09-12 설계 작업을 마친 뒤 bam의 구현 시작 요청으로 [R1 첫 사용 범위](designs/lesson-review.md#r1-첫-사용-구현-계약)의 홈·독립 목록·개별 채점·개념/문서 왕복·진행 복구를 구현했다. 현재 검증 증거와 미실행 범위는 [첫 사용 작업 카드](work-items/2026-09-12-independent-review-first-use.md)에서 확인한다. 전부 보기·전체 채점·모름·헷갈림·문제별 전체 이력은 후속 범위다.

## 확정된 제품 방향

- [`DEC-DELIVERY-01`](roadmap.md#2026-08-29-확정-제품-결정)의 MVP 효과: 최종 사용자는 원격 운영 서버가 아닌 **설치형 로컬 프로그램**에서 핵심 교안·진도·코드 작성·공개 평가를 오프라인으로 사용한다.
- [`DEC-DESKTOP-PROTOTYPE-01`](roadmap.md#2026-08-30-확정-제품-결정)의 전환 효과: 첫 설치 후보는 현재 macOS 14.8.3·Apple Silicon 검증 장비에서 Electron·DMG로 capability를 측정하되, 그 장비나 후보를 공식 지원·채택으로 약속하지 않는다.
- [`DEC-QUEST-SEPARATE-01`](roadmap.md#2026-08-29-확정-제품-결정)의 MVP 효과: Code Quest와 코딩테스트는 서로 다른 학습 목적·콘텐츠·화면·진도를 유지한다.
- [`DEC-PUBLIC-EVALUATION-01`](roadmap.md#2026-08-29-확정-제품-결정)의 MVP 효과: 두 기능을 포함한 학습자 평가에는 공개 로컬 사례만 사용하고 원격·비공개·숨김 사례를 실행하지 않는다.
- [`DEC-QUEST-UI-01`](roadmap.md#2026-08-29-확정-제품-결정)의 MVP 효과: Code Quest는 실제 코드 작성 경험과 현재 과정·주제·문제·진도를 한 정보 구조로 보여 준다.
- [`DEC-WEB-ASSIGN-01`](roadmap.md#2026-08-29-확정-제품-결정)의 MVP 효과: BAM.dev는 HTML·CSS·JavaScript·Java Git 실습 폴더의 준비·검증·정답 비교 방법을 안내한다.
- [`DEC-VISUAL-01`](roadmap.md#2026-08-29-확정-제품-결정)의 MVP 효과: BAM.dev 화면은 확정 프로젝트 팔레트와 검증된 semantic token으로 학습 위치·행동·상태를 일관되게 보여 주며 색만으로 의미를 전달하지 않는다.
- [`DEC-CONTENT-01`](roadmap.md#2026-08-30-확정-제품-결정)의 MVP 효과: release 차단 기존 콘텐츠 전체를 깊이별로 지도화하고 학습 완료를 막는 A/E/C/T gap만 보강한다. 감사 자체를 기존 콘텐츠 PASS나 전면 재작성으로 취급하지 않는다.
- [`DEC-JAVA-CODING-TEST-01`](roadmap.md#2026-09-02-확정-제품-결정)의 MVP 효과: 분리된 코딩테스트에 Java를 필수 지원 언어로 포함하고, 설치본의 공개 테스트를 사용자 기기에서 실행한다. Java 정식 교안 과정·Code Quest·웹과제까지 자동 포함하는 결정은 아니다.
- [`DEC-JAVA-RUNTIME-01`](roadmap.md#2026-09-02-확정-제품-결정)의 MVP 효과: Java 코딩테스트는 시스템 JDK 설정에 의존하지 않고 설치 패키지에 고정된 컴파일러 포함 Java 도구체인을 사용한다. LTS 계열과 콘텐츠 기준은 `DEC-JAVA-VERSION-02`, 정확한 배포판·패치와 나머지 runner 계약은 `DEC-JAVA-RUNNER-01`이 담당한다.
- [`DEC-JAVA-VERSION-02`](roadmap.md#2026-09-04-확정-제품-결정)의 MVP 효과: 번들 도구체인과 Java 교안·코딩테스트 소스·표준 API 기준을 정식 Java 25로 통일하고 preview 기능은 허용하지 않는다.
- [`DEC-JAVA-IMPLEMENTATION-01`](roadmap.md#2026-09-04-확정-제품-결정)의 제품 효과: Java를 BAM.dev 실제 제품 구현 언어로 사용하고 최소 제품 구성요소인 Java 코딩테스트 로컬 runner를 Java 25로 작성한다. 구체 runner 계약과 Spring Boot 경계는 별도 결정을 따른다.
- [`DEC-SPRING-BOOT-01`](roadmap.md#2026-09-04-확정-제품-결정)의 제품 효과: Spring Boot 과정은 앞으로 추가하되 교안은 정적 콘텐츠로 제공하고 실제 실행은 외부 Git 웹과제에서 시작한다. 앱 본체·Java 코딩테스트 runner 포함과 MVP 자동 편입을 뜻하지 않는다.
- [`DEC-FRONTEND-01`](roadmap.md#2026-09-04-확정-제품-결정)의 제품 효과: 목표 UI는 HTML·CSS 기반의 React·TypeScript를 사용하고 JavaScript도 유지한다. 현재 검증된 Vanilla JavaScript·Worker·도메인 로직은 폐기하지 않고 작은 화면·경계부터 이관한다. 이 기술 방향만으로 React·TypeScript 학습 과정의 MVP 편입이 확정되지는 않는다.
- [`DEC-DOC-01`](roadmap.md#2026-08-29-확정-제품-결정)의 운영 효과: 변경 가능한 주요 제품 경계는 구현 전에 설계 정본을 갖는다. 상세 범위는 [`docs/README.md`](README.md#설계-문서화-범위)가 담당한다.

이 방향 중 두 기능의 분리와 JavaScript 공개 브라우저 평가는 현재 구현에도 존재한다. 현재 화면은 HTML·CSS·Vanilla JavaScript이며 React·TypeScript와 해당 빌드 의존성은 없다. Java 제품 소스·Maven·Gradle 설정도 없다. Java 코딩테스트 콘텐츠·Java 25 제품 runner·설치 지원, 설치 프로그램, React·TypeScript 이관, 새 Code Quest 탐색 UI와 외부 과제 저장소는 아직 목표 상태다. Java 도구체인의 패키지 포함과 정식 Java 25·preview 금지 기준은 확정됐지만 구현된 사실은 아니며, 공식 지원 OS·shell·설치 형식과 Java runner의 나머지 계약은 prototype 증거 뒤 결정한다. Spring Boot 과정과 과제도 현재 구현이 아닌 향후 목표다.

## MVP가 답해야 하는 질문

`[확정 결정]` 제품 로드맵은 서버·계정·튜터 확장보다 **설치형 오프라인 개인 학습 MVP**의 완결성을 먼저 판단한다. 현재 구현을 전면 재작성하지 않고 검증된 정적 콘텐츠·로컬 저장·공개 평가·Worker·도메인 경계를 단계적으로 설치 shell과 새 정보 구조로 옮기며, 프런트엔드는 승인된 작은 경계부터 React·TypeScript로 이관한다. 세부 과정·OS·과제 범위와 프런트엔드 이관 계약은 [`roadmap.md`](roadmap.md#bam-결정-대기-목록)에서 bam이 확정한다. MVP는 한 명의 학습자가 다음 질문에 모두 “예”라고 답할 수 있어야 한다.

- 무엇을 왜 배우는지 알 수 있는가?
- 개념을 읽은 뒤 작은 구현으로 확인할 수 있는가?
- 정답을 보기 전에 관찰 지점과 단계별 힌트로 다시 시도할 수 있는가?
- 처음 보는 작은 문제에서 적절한 접근을 골라 풀이를 시작할 수 있는가?
- 실패 원인과 다음 행동을 공개된 근거로 이해할 수 있는가?
- 앱을 닫았다 열거나 업데이트해도 자신의 진도와 초안을 이어 갈 수 있는가?
- 별도 서버·계정 없이 설치하고 핵심 학습 흐름을 오프라인에서 완료할 수 있는가?
- 키보드와 좁은 앱 창에서도 같은 핵심 학습 흐름을 완료할 수 있는가?

## MVP 범위

확정된 제품 방향 안에서 과정·OS·외부 과제의 정확한 MVP 차단 범위는 아직 결정되지 않았다. 다음은 현재 구현을 폐기하지 않는 권장 최소 범위다.

### 학습 과정

- `[제안]` 현재 `available`인 JavaScript, 알고리즘, HTML, CSS 과정을 설치본의 오프라인 정식 과정으로 제공한다.
- `[현재 사실]` Java 과정은 언어 독립성 검증용 `sample`이고 Java 교안·객관식 샘플만 있다. Java 코딩테스트 콘텐츠와 runner는 없다.
- `[확정 결정]` Java 코딩테스트는 설치형 MVP 필수 목표이며 설치 패키지의 JDK 25 LTS 계열로 정식 Java 25 소스·표준 API를 preview 없이 컴파일·실행한다. `[확인 필요]` 실제 포함 문제 묶음·수량과 관찰 가능한 핵심 완료 행동은 `DEC-MVP-01`, 정확한 JDK 배포판·재배포 라이선스·패치 버전·보안 업데이트 정책과 컴파일·호출·IPC·격리·OS별 패키징 계약은 `DEC-JAVA-RUNNER-01`에서 정한다.
- `[확정 결정]` Java 학습문서·객관식은 `DEC-INDEPENDENT-LEARNING-01`의 첫 콘텐츠 목표에 포함한다. `[확인 필요]` 정확한 키워드·검증 묶음과 Java Code Quest·외부 과제의 포함 시점은 `DEC-JAVA-01`에서 구분한다.
- `[확정 결정]` Spring Boot 과정은 향후 추가하지만 `[확인 필요]` MVP 포함 시점·정확한 교안 범위·Code Quest 여부는 `DEC-JAVA-01`에서 별도로 결정한다. 교안은 정적 콘텐츠이고 실제 Spring Boot 실행은 승인된 외부 웹과제에서만 시작한다.
- 과정과 콘텐츠의 실제 목록·수량은 `content/curriculum.json`과 컬렉션이 정본이며, 현재 요약은 프로젝트 [`README.md`](../README.md)에서만 관리한다.

### 핵심 학습 경험

- 교안: 학습 목표, 선택 단서, 실행 흐름, 흔한 실수와 확인 방법을 제공한다.
- 객관식: 학습문서와 독립적으로 진입해 키워드의 여러 단일·복합 문항을 선택한다. 두 보기 모드·채점 방식, 선택한 오답의 이유·관련 개념·조건부 문서 복귀·헷갈림·모름·자율 재도전은 [`designs/lesson-review.md`](designs/lesson-review.md)가 정본이다.
- Code Quest: 교안에 연결된 개념·조건을 실제 작성 단위로 연습하고 단계별 힌트와 공개 실패 근거로 다시 시도한다. 정보 구조는 [`designs/code-quest.md`](designs/code-quest.md)가 정본이다.
- 코딩테스트: 별도 목록에서 문제 단서를 읽고 접근·조합·조건을 스스로 선택해 전체 공개 테스트로 로컬 결과를 확인한다. 제품 계약은 [`designs/coding-test.md`](designs/coding-test.md)가 정본이다.
- 웹과제: 실습 저장소의 여러 파일과 순서 있는 요구사항을 로컬 도구에서 구현하고 자신의 commit과 공개 solution을 비교한다. 목표 흐름은 [`designs/web-assignments.md`](designs/web-assignments.md)가 정본이다.
- 학습 콘텐츠의 지원 수준은 교안 관찰에서 힌트 없는 전이까지 점차 줄인다. 세부 기준은 [`learning-content-design.md`](learning-content-design.md)가 정본이다.

### 실행·데이터 경계

- `[현재 사실]` 앱 UI는 HTML·CSS·Vanilla JavaScript 정적 자산으로 동작하고 React·TypeScript와 전용 빌드 도구 의존성은 없다.
- `[확정 결정]` 목표 소스 UI는 HTML·CSS 기반에 React·TypeScript를 사용하고 JavaScript도 유지하며, 설치 shell에는 빌드된 정적 자산을 번들한다. 정확한 도구체인과 첫 이관 경계가 승인되기 전에는 현재 Worker·도메인·라우트·진도를 보존한다. 최종 사용자는 Node·Docker·포트·원격 서버를 운영하지 않는다.
- 사용자 진도는 저장소 인터페이스 뒤에 두며 MVP 구현은 `localStorage`, 차단 시 현재 탭의 메모리 저장소를 사용한다.
- 콘텐츠와 사용자 상태를 분리하고 안정적인 콘텐츠 ID와 리비전으로 연결한다.
- 브라우저에서 실행하는 학습자 코드는 현재 채택된 안전 경계를 지키며, 학습자 결과에 비공개·숨김 테스트나 원격 추가 채점을 사용하지 않는다. 개발 fixture는 콘텐츠 검증에만 쓰고 학습자 결과에 포함하지 않는다.
- Java 코딩테스트는 사용자 기기에서 공개 테스트만 실행하는 목표다. runner는 설치 패키지 내부의 JDK 25 LTS 계열로 정식 Java 25 소스·표준 API를 컴파일·실행하고 preview를 허용하거나 시스템 `JAVA_HOME`·`PATH`에 의존하지 않는다. JavaScript의 one-shot Worker를 Java 실행 방식으로 간주하지 않으며, 정확한 배포판·재배포 라이선스·패치 버전·보안 업데이트 정책과 컴파일·호출·IPC 및 프로세스·파일·네트워크·시간·메모리·출력 제한은 별도 결정·ADR·prototype을 통과해야 한다.
- BAM.dev 앱 본체와 Java 코딩테스트 runner에는 Spring Boot를 포함하지 않는다. Spring Boot 실습은 앱이 임의 실행하지 않는 외부 웹과제 폴더에서만 시작하며 저장소·빌드·의존성·오프라인·공개 검증 계약은 별도 승인을 기다린다.
- 핵심 앱은 설치 뒤 오프라인으로 동작한다. 외부 웹과제는 pinned starter·solution commit을 처음 clone·fetch하는 별도 네트워크 단계를 거치며, 두 commit을 확보한 뒤에는 오프라인으로 수행·비교한다.
- 설치·업데이트·데이터 보존 계약은 [`designs/local-application.md`](designs/local-application.md)가 정본이다.

### MVP 품질 기준

- 콘텐츠 스키마, ID·순서·파일 경로와 교안·개념 연결이 유효하다.
- 변경 유형에 맞는 독립 생성·검증·통합 gate를 통과한다. 역할과 완료 조건의 정본은 [`development-workflow.md`](development-workflow.md)다.
- 제품 변경은 자동 테스트뿐 아니라 영향받는 실제 브라우저 흐름, 키보드, 좁은 화면과 상태 안내를 확인한다.

## 비범위

`[제안]` 다음 항목은 오프라인 개인 학습 MVP의 필수 완료 조건이 아니다. Java 코딩테스트 자체는 `DEC-JAVA-CODING-TEST-01`에 따라 이 목록에 포함되지 않는다.

- Java Code Quest의 설치형 MVP 자동 편입. Java 학습문서·객관식의 첫 목표 포함은 최신 독립 학습 결정으로 확정됐으므로 비범위에서 제외
- Spring Boot 과정·Code Quest·외부 과제의 MVP 편입과 구체 구현
- 회원가입, 로그인, 다중 사용자, 마이페이지와 원격 동기화
- Supabase, 원격 API·DB, 서버 저장과 운영 대시보드
- AI 학습 튜터 또는 외부 모델 호출
- 교사·반·스터디 협업, 순위, 소셜 기능
- 원격 채점, 브라우저에 없는 비밀 테스트, 부정행위 방지 채점
- 서버 기반 학습 분석, 유료 결제와 서비스 운영 인프라
- BAM.dev가 외부 웹과제 폴더의 임의 코드를 자동 실행하거나 중앙 저장소에 자동 push하는 기능
- 승인된 Java 코딩테스트 runner 경계를 벗어난 임의 Java in-app 실행과 로컬 HTTP Java 웹과제

비범위 항목도 이후 단계에서 제안할 수 있지만, MVP 결손을 가리기 위해 먼저 구현하지 않는다. 순서는 [`roadmap.md`](roadmap.md)에서 결정한다.

## 새 기능의 MVP 포함 판정

`[확정 결정]` [`DEC-DOC-01`](roadmap.md#2026-08-29-확정-제품-결정)에 따라 새 기능은 구현 전에 다음 질문에 답하는 **기능 필요성 기록**을 남긴다.

1. 어떤 초보 학습자의 막힘을 해결하는가?
2. 위 학습 순환의 어느 빈칸을 채우는가?
3. 현재 기능이나 콘텐츠만으로 해결할 수 없는 이유는 무엇인가?
4. 오프라인 개인 사용, 데이터 경계, 접근성·모바일에 어떤 영향을 주는가?
5. 사용자가 얻는 새 학습 행동을 무엇으로 관찰할 수 있는가?
6. 자동 검증과 사람 검토를 각각 어떤 증거로 완료할 수 있는가?

답이 없거나 단지 콘텐츠 수·화면 수를 늘리는 기능은 MVP에서 제외한다. 학습 콘텐츠라면 이 기록에 [`learning-content-design.md`](learning-content-design.md)의 경험 카드를 함께 사용한다.

## MVP 완료 조건

다음을 모두 만족하고 bam이 최종 승인할 때 설치형 오프라인 개인 학습 MVP가 완료된다.

- MVP 범위와 비범위가 확정되고 미결정 항목이 완료를 막지 않는다.
- 정식 과정의 핵심 흐름을 새 학습자 관점에서 처음부터 끝까지 완료할 수 있다.
- release 차단 콘텐츠 ID가 깊이별 소급 지도와 증거에 모두 연결되고, 필요한 접근 원자·연결·조건 변화와 무힌트 전이 확인 기회의 차단 gap이 해소된다. 같은 경험만 반복하는 문제를 완료 수로 세지 않고 실제 학습자 관찰이 없으면 전이 성과가 입증됐다고 표현하지 않는다.
- 콘텐츠·제품·문서 변경이 각자의 파이프라인과 Definition of Done을 통과한다.
- `npm run check`와 합의한 OS의 설치·실행·재실행이 통과하고, 실제 패키지의 키보드·좁은 창 확인 증거가 남는다.
- 심각한 콘텐츠 오류, 데이터 손실, 실행 격리·안전, 접근성 차단 문제가 남아 있지 않다.
- Code Quest와 코딩테스트가 각자의 ID·URL·초안·진도를 보존하고 서로 다른 완료율과 학습 목적을 보여 준다.
- 두 기능의 완료에는 설치본에 포함된 공개 사례만 사용하고 전체 결과가 서버 요청 없이 재현된다.
- Java 코딩테스트의 승인된 공개 문제 묶음과 핵심 완료 행동이 확정되고, 설치 패키지의 JDK 25 LTS 계열·정식 Java 25·preview 금지와 runner가 시스템 JDK 없이 격리 계약과 지원 OS에서 검증된다.
- 확정 팔레트가 semantic token으로 적용되고 본문·UI 경계·focus 대비와 비색상 상태 표현이 실제 화면에서 검증된다.
- 핵심 앱은 네트워크 없이 동작하고, Git 웹과제의 최초 다운로드 경계와 오프라인 이후 절차가 명확하다.
- 실제 기능 브랜치·PR·CI·`dev` 통합 이력이 확인된다.

아직 bam의 결정이 필요한 항목은 중복해 적지 않고 [`roadmap.md`의 결정 대기 목록](roadmap.md#bam-결정-대기-목록)에서 관리한다.
