# 제품 목표와 소스 기반 개인 학습 MVP

## 제품 목표

`[확정 결정]` BAM.dev는 초보 개발자가 문법을 읽는 데서 멈추지 않고 다음 순환을 스스로 수행하도록 돕는 개인 학습 가이드다.

```text
개념을 자신의 말로 설명한다
→ 문제의 조건과 관찰 지점을 찾는다
→ 접근 방식을 선택하고 이유를 말한다
→ 직접 구현한다
→ 공개된 근거로 결과와 실패를 확인한다
→ 힌트를 줄인 새로운 문제에 다시 적용한다
```

정답을 먼저 보여 주거나 문제 수를 채우는 것은 목표가 아니다. 실행하지 않은 코드 결과를 만들지 않고, 학습자 결과에는 해당 실행 묶음에 포함된 공개 테스트·공개 기준만 사용한다. 접근성과 모바일 사용성은 별도 부가 기능이 아니라 학습 완료 조건이다.

## 첫 학습 서비스 범위

[최신 독립 학습·홈·사용자 편의 결정](roadmap.md#2026-09-12-확정-제품-결정)을 적용한다. 사용자 편의를 제품 판단의 최우선 기준으로 삼아 원하는 서비스·자료·문제를 쉽게 찾고, 상태를 잃지 않고 중단·복귀하며, 불필요한 선택·반복 입력을 줄이는 흐름을 설계한다. 정확성·접근성·비공개 자료 보호는 유지한다.

첫 화면은 BAM.dev 소개와 **학습문서 / 객관식 문제**의 독립 진입을 제공한다. 밤위키는 콘텐츠 제작 재료이고 개인 위키·수업 일정이 서비스 이용의 조건이 아니다. 첫 콘텐츠 목표는 HTML·CSS·JavaScript·Java 문서와 객관식이며 확장 순서는 [로드맵](roadmap.md#학습문서객관식의-우선-완성-순서)에 둔다. 아래 제품 MVP와 첫 사용 흐름의 완료는 구분한다. 앞선 2026-09-12 설계 작업을 마친 뒤 bam의 구현 시작 요청으로 [R1 첫 사용 범위](designs/lesson-review.md#r1-첫-사용-구현-계약)의 홈·독립 목록·개별 채점·개념/문서 왕복·진행 복구를 구현했다. 현재 검증 증거와 미실행 범위는 [첫 사용 작업 카드](work-items/2026-09-12-independent-review-first-use.md)에서 확인한다. 후속 [보기·채점 확장](work-items/2026-09-14-review-display-and-grading.md)과 [오답 즉시 재도전](designs/lesson-review.md#오답-문항의-즉시-재도전)도 구현·검증됐다. 모름·헷갈림·문제별 전체 이력은 남은 범위다.

## 확정된 제품 방향

- [`DEC-SOURCE-DISTRIBUTION-01`](roadmap.md#2026-09-22-소스-전달-방식-정정)의 MVP 효과: GitHub에서 clone/다운로드한 소스를 기존 실행 명령으로 사용한다. 설치형·설치 후 오프라인·Electron/DMG·공증·OS 선택은 필수 release 조건이 아니다.
- `[대체됨]` 설치 후보를 기본 전환 경로로 삼았던 DEC-DESKTOP-PROTOTYPE-01은 소스 전달 방향으로 대체됐다. 기존 prototype 검증·포장 이력은 유지한다.
- [`DEC-QUEST-SEPARATE-01`](roadmap.md#2026-08-29-확정-제품-결정)의 MVP 효과: Code Quest와 코딩테스트는 서로 다른 학습 목적·콘텐츠·화면·진도를 유지한다.
- [`DEC-PUBLIC-EVALUATION-01`](roadmap.md#2026-08-29-확정-제품-결정)의 MVP 효과: 두 기능을 포함한 학습자 평가에는 공개 로컬 사례만 사용하고 원격·비공개·숨김 사례를 실행하지 않는다.
- [`DEC-QUEST-UI-01`](roadmap.md#2026-08-29-확정-제품-결정)의 MVP 효과: Code Quest는 실제 코드 작성 경험과 현재 과정·주제·문제·진도를 한 정보 구조로 보여 준다.
- [`DEC-WEB-ASSIGN-01`](roadmap.md#2026-08-29-확정-제품-결정)의 MVP 효과: BAM.dev는 HTML·CSS·JavaScript·Java Git 실습 폴더의 준비·검증·정답 비교 방법을 안내한다.
- [`DEC-VISUAL-01`](roadmap.md#2026-08-29-확정-제품-결정)의 MVP 효과: BAM.dev 화면은 확정 프로젝트 팔레트와 검증된 semantic token으로 학습 위치·행동·상태를 일관되게 보여 주며 색만으로 의미를 전달하지 않는다.
- [`DEC-CONTENT-01`](roadmap.md#2026-08-30-확정-제품-결정)의 MVP 효과: release 차단 기존 콘텐츠 전체를 깊이별로 지도화하고 학습 완료를 막는 A/E/C/T gap만 보강한다. 감사 자체를 기존 콘텐츠 PASS나 전면 재작성으로 취급하지 않는다.
- [`DEC-JAVA-CODING-TEST-01`](roadmap.md#2026-09-02-확정-제품-결정)의 MVP 효과: 분리된 코딩테스트에 Java를 필수 지원 언어로 포함하고, 공개 테스트를 사용자 기기에서 실행하는 목표를 유지하되 새 소스 실행 연결은 별도 계약으로 정한다. Java 정식 교안 과정·Code Quest·웹과제까지 자동 포함하는 결정은 아니다.
- [`DEC-JAVA-RUNTIME-01`](roadmap.md#2026-09-02-확정-제품-결정)의 고정 Java 도구체인·시스템 JDK 비의존·격리 경계는 기존 prototype에 유지한다. 소스 전달 환경의 Java 연결·도구체인 제공 방식은 아직 미결정이며 시스템 JDK나 새 HTTP 실행 API를 임의로 허용하지 않는다.
- [`DEC-JAVA-VERSION-02`](roadmap.md#2026-09-04-확정-제품-결정)의 MVP 효과: 번들 도구체인과 Java 교안·코딩테스트 소스·표준 API 기준을 정식 Java 25로 통일하고 preview 기능은 허용하지 않는다.
- [`DEC-JAVA-IMPLEMENTATION-01`](roadmap.md#2026-09-04-확정-제품-결정)의 제품 효과: Java를 BAM.dev 실제 제품 구현 언어로 사용하고 최소 제품 구성요소인 Java 코딩테스트 로컬 runner를 Java 25로 작성한다. 구체 runner 계약과 Spring Boot 경계는 별도 결정을 따른다.
- [`DEC-SPRING-BOOT-01`](roadmap.md#2026-09-04-확정-제품-결정)의 제품 효과: Spring Boot를 포함한 과정의 교안은 정적 콘텐츠로 제공하고 실제 실행은 외부 Git 웹과제에서 시작한다. 이번 정적 입문 묶음은 `DEC-CSS-SPRING-FOUNDATIONS-01`로 착수 범위가 확정됐다. 앱 본체·Java 코딩테스트 runner 포함과 MVP 자동 편입을 뜻하지 않는다.
- [`DEC-FRONTEND-01`](roadmap.md#2026-09-04-확정-제품-결정)의 제품 효과: 목표 UI는 HTML·CSS 기반의 React·TypeScript를 사용하고 JavaScript도 유지한다. 현재 검증된 Vanilla JavaScript·Worker·도메인 로직은 폐기하지 않고 작은 화면·경계부터 이관한다. 이 기술 방향만으로 React·TypeScript 학습 과정의 MVP 편입이 확정되지는 않는다.
- [`DEC-DOC-01`](roadmap.md#2026-08-29-확정-제품-결정)의 운영 효과: 변경 가능한 주요 제품 경계는 구현 전에 설계 정본을 갖는다. 상세 범위는 [`docs/README.md`](README.md#설계-문서화-범위)가 담당한다.

현재 브라우저 앱은 HTML·CSS·Vanilla JavaScript이며 분리된 Code Quest·코딩테스트의 탐색과 JavaScript 공개 평가를 제공한다. Java 정적 교안·객관식, Quest와 코딩테스트의 작성·저장도 구현됐다. 검증 커널에 한정한 로컬 Java Quest·코딩테스트 prototype의 실행·공개 평가를 검증했고 시험용 DMG 포장도 검증했다. 정식 설치·지원 OS·설치 후 오프라인과 기록 보존은 아직 미검증이다. React·TypeScript 점진 이관은 유지하되 설치형 오프라인 MVP는 현재 목표가 아니다. 웹/소스 브라우저에서는 Java 작성·저장만 지원한다. Spring 정적 학습은 [기초](work-items/2026-09-14-css-quiz-spring-foundations.md)와 [Security·JPA 확장](work-items/2026-09-14-spring-security-jpa.md)의 검증 범위를 따른다. 외부 실행 과제는 [밤위키 원본 활용 계약](designs/web-assignments.md)에 따라 후속 연결하며 새 과제의 BAM 제공 완료를 주장하지 않는다.

## MVP가 답해야 하는 질문

`[확정 결정]` 제품 로드맵은 GitHub 소스로 받아 실행하는 개인 학습 흐름을 우선한다. 기존 정적 콘텐츠·로컬 저장·공개 평가·Worker·도메인 경계를 보존하고 승인된 작은 화면부터 React·TypeScript로 이관한다. 새 Java 연결과 브라우저 저장 보호는 별도 설계·검증하며 설치 shell을 선행 조건으로 두지 않는다. MVP는 다음 학습·보존 질문으로 판단한다.

- 무엇을 왜 배우는지 알 수 있는가?
- 개념을 읽은 뒤 작은 구현으로 확인할 수 있는가?
- 정답을 보기 전에 관찰 지점과 단계별 힌트로 다시 시도할 수 있는가?
- 처음 보는 작은 문제에서 적절한 접근을 골라 풀이를 시작할 수 있는가?
- 실패 원인과 다음 행동을 공개된 근거로 이해할 수 있는가?
- 앱을 닫았다 열거나 업데이트해도 자신의 진도와 초안을 이어 갈 수 있는가?
- GitHub 소스를 받아 안내된 명령으로 시작하고 실제 지원되는 핵심 흐름을 사용할 수 있는가?
- 키보드와 좁은 앱 창에서도 같은 핵심 학습 흐름을 완료할 수 있는가?

## MVP 범위

확정된 제품 방향 안에서 과정·OS·외부 과제의 정확한 MVP 차단 범위는 아직 결정되지 않았다. 다음은 현재 구현을 폐기하지 않는 권장 최소 범위다.

### 학습 과정

- `[제안]` 현재 `available`인 JavaScript, 알고리즘, HTML, CSS 과정을 소스에 포함한 정식 과정으로 제공한다.
- `[현재 사실]` Java 과정은 승인된 [JS·Java 개념 전환](work-items/2026-09-14-js-java-concepts-and-review.md)으로 정적 학습문서·객관식을 `available`로 제공한다. Java 코딩테스트 작성용 콘텐츠도 등록됐다. 검증 커널의 로컬 Java Quest·코딩테스트 prototype 실행·공개 평가를 독립 PASS했으며 정식 설치 지원은 미완료다.
- `[확정 결정]` Java 코딩테스트의 로컬 공개 평가는 유지되는 목표이며 기존 prototype은 고정 JDK 25 LTS 계열로 정식 Java 25 소스·표준 API를 preview 없이 컴파일·실행한다. `[확인 필요]` 실제 포함 문제 묶음·수량과 관찰 가능한 핵심 완료 행동은 `DEC-MVP-01`, 정확한 JDK 배포판·재배포 라이선스·패치 버전·보안 업데이트 정책과 컴파일·호출·IPC·격리·OS별 패키징 계약은 `DEC-JAVA-RUNNER-01`에서 정한다.
- `[확정 결정]` Java 학습문서·객관식은 `DEC-INDEPENDENT-LEARNING-01`의 첫 콘텐츠 목표에 포함하며 이번 승인 묶음의 실제 단위·검증은 위 작업 카드에 기록한다. `[확인 필요]` 제품 MVP의 정확한 과정·차단 콘텐츠 범위와 Java Code Quest·외부 과제의 포함 시점은 `DEC-MVP-01`·`DEC-JAVA-01`에서 별도로 구분한다. 현재 정적 제공이 새 실행·실습 범위를 자동 승인하지 않는다.
- `[확정 결정]` Spring 핵심과 Spring Boot를 포함한 정적 문서·객관식의 입문 범위는 [`DEC-CSS-SPRING-FOUNDATIONS-01`](roadmap.md#2026-09-14-확정-제품-결정)에 따라 진행한다. `[확인 필요]` 제품 MVP의 정확한 차단 묶음과 Code Quest·실행 과제 포함 여부는 `DEC-JAVA-01`에서 별도로 결정한다. 실제 Spring Boot 실행은 승인된 외부 웹과제에서만 시작한다.
- 과정과 콘텐츠의 실제 목록·수량은 `content/curriculum.json`과 컬렉션이 정본이며, 현재 요약은 프로젝트 [`README.md`](../README.md)에서만 관리한다.

### 핵심 학습 경험

- 교안: 학습 목표, 선택 단서, 실행 흐름, 흔한 실수와 확인 방법을 제공한다.
- 객관식: 학습문서와 독립적으로 진입해 키워드의 여러 단일·복합 문항을 선택한다. 두 보기 모드·채점 방식, 선택한 오답의 이유·관련 개념·조건부 문서 복귀·헷갈림·모름·자율 재도전은 [`designs/lesson-review.md`](designs/lesson-review.md)가 정본이다.
- Code Quest: 교안에 연결된 개념·조건을 실제 작성 단위로 연습하고 단계별 힌트와 공개 실패 근거로 다시 시도한다. 정보 구조는 [`designs/code-quest.md`](designs/code-quest.md)가 정본이다.
- 코딩테스트: 별도 목록에서 문제 단서를 읽고 접근·조합·조건을 스스로 선택해 전체 공개 테스트로 로컬 결과를 확인한다. 제품 계약은 [`designs/coding-test.md`](designs/coding-test.md)가 정본이다.
- 웹과제: 밤위키 원본의 고정 시작점·요구사항을 로컬 도구에서 구현하고 공개 검증과 승인된 비교 자료로 결과를 설명한다. 목표 흐름은 [`designs/web-assignments.md`](designs/web-assignments.md)가 정본이다.
- 학습 콘텐츠의 지원 수준은 교안 관찰에서 힌트 없는 전이까지 점차 줄인다. 세부 기준은 [`learning-content-design.md`](learning-content-design.md)가 정본이다.

### 실행·데이터 경계

- `[현재 사실]` 앱 UI는 HTML·CSS·Vanilla JavaScript 정적 자산으로 동작하고 React·TypeScript와 전용 빌드 도구 의존성은 없다.
- `[확정 결정]` 목표 소스 UI는 HTML·CSS 기반 React·TypeScript이며 JavaScript도 유지한다. 도구체인·첫 이관 승인 전 기존 Worker·도메인·URL·진도를 보존한다. 현재 소스 사용자는 Node.js 20 이상에서 `npm run dev`로 정적 서버를 시작한다. 이는 Java 실행 API나 원격 운영 서버 도입 승인이 아니다.
- 사용자 진도는 저장소 인터페이스 뒤에 두며 MVP 구현은 `localStorage`, 차단 시 현재 탭의 메모리 저장소를 사용한다.
- 콘텐츠와 사용자 상태를 분리하고 안정적인 콘텐츠 ID와 리비전으로 연결한다.
- 브라우저에서 실행하는 학습자 코드는 현재 채택된 안전 경계를 지키며, 학습자 결과에 비공개·숨김 테스트나 원격 추가 채점을 사용하지 않는다. 개발 fixture는 콘텐츠 검증에만 쓰고 학습자 결과에 포함하지 않는다.
- Java 코딩테스트는 사용자 기기에서 공개 테스트만 실행하는 목표다. 기존 prototype runner는 번들 JDK 25 LTS 계열로 정식 Java 25 소스·표준 API를 컴파일·실행하고 preview를 허용하거나 시스템 `JAVA_HOME`·`PATH`에 의존하지 않는다. JavaScript의 one-shot Worker를 Java 실행 방식으로 간주하지 않으며, 정확한 배포판·재배포 라이선스·패치 버전·보안 업데이트 정책과 컴파일·호출·IPC 및 프로세스·파일·네트워크·시간·메모리·출력 제한은 별도 결정·ADR·prototype을 통과해야 한다.
- BAM.dev 앱 본체와 Java 코딩테스트 runner에는 Spring Boot를 포함하지 않는다. Spring Boot 실습은 앱이 임의 실행하지 않는 외부 웹과제 폴더에서만 시작하며 저장소·빌드·의존성·오프라인·공개 검증 계약은 별도 승인을 기다린다.
- 설치 후 오프라인이라는 gate는 대체하되 오프라인 품질 목표 자체를 폐기하지 않는다. 최초 소스·의존성 다운로드와 이후 실행·외부 링크/과제 도구의 네트워크 요구를 구분해 소스 전달 환경의 범위를 재정의한다. 완전 오프라인 지원은 실제 검증 전 주장하지 않는다.
- 데이터 보호의 유효 원칙과 대체된 설치 prototype 이력은 [`designs/local-application.md`](designs/local-application.md)를 따른다. 브라우저 writer/backup 계약은 재설계가 필요하다.

### MVP 품질 기준

- 콘텐츠 스키마, ID·순서·파일 경로와 교안·개념 연결이 유효하다.
- 변경 유형에 맞는 독립 생성·검증·통합 gate를 통과한다. 역할과 완료 조건의 정본은 [`development-workflow.md`](development-workflow.md)다.
- 제품 변경은 자동 테스트뿐 아니라 영향받는 실제 브라우저 흐름, 키보드, 좁은 화면과 상태 안내를 확인한다.

## 비범위

`[제안]` 다음 항목은 오프라인 개인 학습 MVP의 필수 완료 조건이 아니다. Java 코딩테스트 자체는 `DEC-JAVA-CODING-TEST-01`에 따라 이 목록에 포함되지 않는다.

- Java Code Quest의 설치형 MVP 자동 편입. Java 학습문서·객관식의 첫 목표 포함은 최신 독립 학습 결정으로 확정됐으므로 비범위에서 제외
- Spring·Spring Boot 정적 입문 묶음의 설치형 MVP 자동 편입과 Code Quest·실제 실행 과제 구현
- 회원가입, 로그인, 다중 사용자, 계정형 마이페이지와 원격 동기화
- Supabase, 원격 API·DB, 서버 저장과 운영 대시보드
- AI 학습 튜터 또는 외부 모델 호출
- 교사·반·스터디 협업, 순위, 소셜 기능
- 원격 채점, 브라우저에 없는 비밀 테스트, 부정행위 방지 채점
- 서버 기반 학습 분석, 유료 결제와 서비스 운영 인프라
- BAM.dev가 외부 웹과제 폴더의 임의 코드를 자동 실행하거나 중앙 저장소에 자동 push하는 기능
- 승인된 Java 코딩테스트 runner 경계를 벗어난 임의 Java in-app 실행과 로컬 HTTP Java 웹과제

비범위 항목도 이후 단계에서 제안할 수 있지만, MVP 결손을 가리기 위해 먼저 구현하지 않는다. 순서는 [`roadmap.md`](roadmap.md)에서 결정한다.

## 새 기능의 MVP 포함 판정

`[확정 결정]` [`DEC-DOC-01`](roadmap.md#2026-08-29-확정-제품-결정)에 따라 새 기능은 구현 전에 다음 질문에 답하는 **기능 필요성 기록**을 남긴다.

1. 어떤 초보 학습자의 막힘을 해결하는가?
2. 위 학습 순환의 어느 빈칸을 채우는가?
3. 현재 기능이나 콘텐츠만으로 해결할 수 없는 이유는 무엇인가?
4. 오프라인 개인 사용, 데이터 경계, 접근성·모바일에 어떤 영향을 주는가?
5. 사용자가 얻는 새 학습 행동을 무엇으로 관찰할 수 있는가?
6. 자동 검증과 사람 검토를 각각 어떤 증거로 완료할 수 있는가?

답이 없거나 단지 콘텐츠 수·화면 수를 늘리는 기능은 MVP에서 제외한다. 학습 콘텐츠라면 이 기록에 [`learning-content-design.md`](learning-content-design.md)의 경험 카드를 함께 사용한다.

## 현재 상태와 목표 상태의 차이

현재 기능·수량·실행/작성 구분은 [README의 현재 기능과 남은 범위](../README.md#현재-기능과-남은-범위)를 따른다. 2026-09-15 문서 정리 시점에 브라우저 학습·복습 기본 흐름과 직접 작성 UI는 구현됐으나 Java 실제 실행, 밤위키 웹과제의 BAM 연결, React 이관과 정식 설치는 미완료다. 현재 시각 시스템은 승인된 light/dark와 semantic token을 적용했다. PR·CI·공개 사이트의 범위는 [게시 기록](work-items/2026-09-13-github-publication.md#후속-게시-기록-2026-09-15)과 [CT 전환 기록](work-items/2026-09-15-algorithm-bridge-coding-tests.md#최종-독립-검증과-git-게시-결과)을 따른다. 로컬 `#/my`는 계정 기능이 아닌 학습 기록 화면이다.

## MVP 완료 조건

다음 기준을 소스 전달 범위에서 확인하고 bam이 최종 승인할 때 개인 학습 MVP가 완료된다. 설치·공증·OS 채택은 이 완료 조건에 포함하지 않는다.

- MVP 범위와 비범위가 확정되고 미결정 항목이 완료를 막지 않는다.
- 정식 과정의 핵심 흐름을 새 학습자 관점에서 처음부터 끝까지 완료할 수 있다.
- release 차단 콘텐츠 ID가 깊이별 소급 지도와 증거에 모두 연결되고, 필요한 접근 원자·연결·조건 변화와 무힌트 전이 확인 기회의 차단 gap이 해소된다. 같은 경험만 반복하는 문제를 완료 수로 세지 않고 실제 학습자 관찰이 없으면 전이 성과가 입증됐다고 표현하지 않는다.
- 콘텐츠·제품·문서 변경이 각자의 파이프라인과 Definition of Done을 통과한다.
- 변경 범위에 필요한 검사·기존 증거 재사용과 소스 실행의 실제 브라우저 핵심 흐름·키보드·상태 보존 검증이 완료된다.
- 심각한 콘텐츠 오류, 데이터 손실, 실행 격리·안전, 접근성 차단 문제가 남아 있지 않다.
- Code Quest와 코딩테스트가 각자의 ID·URL·초안·진도를 보존하고 서로 다른 완료율과 학습 목적을 보여 준다.
- 두 기능의 완료에는 해당 실행 묶음의 공개 사례만 사용하고 전체 결과가 서버 요청 없이 재현된다.
- Java 코딩테스트의 승인된 공개 문제 묶음·완료 행동과 새 소스 실행 연결 계약이 확정되고 Java 25/preview 금지·도구체인·격리·공개 평가가 해당 환경에서 검증된다. 기존 Electron IPC prototype PASS만으로 브라우저 Java 지원을 주장하지 않는다.
- 확정 팔레트가 semantic token으로 적용되고 본문·UI 경계·focus 대비와 비색상 상태 표현이 실제 화면에서 검증된다.
- 소스 실행과 외부 과제의 다운로드·도구 준비·네트워크 필요 범위를 실제 지원대로 안내한다.
- 실제 기능 브랜치·PR·CI·`dev` 통합 이력이 확인된다.

아직 bam의 결정이 필요한 항목은 중복해 적지 않고 [`roadmap.md`의 결정 대기 목록](roadmap.md#bam-결정-대기-목록)에서 관리한다.
