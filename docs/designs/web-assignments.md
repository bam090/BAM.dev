# 외부 Git 웹과제 설계

이 문서는 밤위키에서 만든 웹과제를 BAM.dev에 연결하는 원본 활용·시작 상태·공개 검증 계약의 정본이다. [DEC-WEB-SOURCE-01](../roadmap.md#2026-09-15-웹과제-원본-활용-결정)을 적용하며 기존 [외부 Git 학습 방향](../roadmap.md#2026-08-29-확정-제품-결정)과 [Spring 실행 경계](../roadmap.md#2026-09-04-확정-제품-결정)를 유지한다. 현재 인앱 HTML·CSS Web Project는 [작성 계약](../web-project-authoring.md)과 [ADR 0004](../decisions/0004-local-web-project-evaluation.md)을 따른다.

## 결정 적용과 현재 차이

- `[확정 결정]` 밤위키에서 만든 과제를 원본으로 사용한다. 원본 운영의 정본은 밤위키 `schema/자동운영/웹과제-운영.md`이며 BAM은 그 운영·템플릿·예약 설정을 복제하거나 변경하지 않는다. 확인 출처와 범위는 [자료 기록](../reference-audit.md#밤위키-웹과제-원본-확인-2026-09-15)에 남긴다.
- `[현재 사실]` 첫 원본으로 스터디 안내글 고정·고정 해제 v1을 선정하고 고정 Git blob 19파일·선수 연결을 확인했다. 아래는 구현 전 연결 계약이며, 실제 반입·UI·공개 실행 판정은 [첫 과제 작업 카드](../work-items/2026-09-15-web-assignment-study-meetup-pin.md)에 별도로 기록한다.
- `[현재 사실]` BAM은 Spring 핵심·Boot·Security·JPA 정적 문서와 객관식을 제공한다. 실제 Spring 프로젝트 실행은 외부 과제 폴더에서 학습자가 시작·종료하며 앱 본체나 Java 코딩테스트 runner에 포함하지 않는다.
- `[현재 사실]` 기존 인앱 Web Project는 HTML·CSS 두 파일 작성·미리보기·공개 검사·자가평가를 제공한다. 원본 활용 방식의 대체 흐름이 검증될 때까지 ID·주소·초안·제출 기록을 보존한다.

BAM 안내·진도 UI는 [전역 시각 계약](visual-design.md)을 따르되 학습자가 구현하는 과제 결과물에 BAM 팔레트를 강제하지 않는다.

## 학습자 흐름

`[확정 결정]` 첫 과제는 아래 연결 흐름과 [고정 시작 계약](#첫-원본의-고정-시작과-전달)을 구현한다. 설계 확정은 실행 완료가 아니다.

```text
BAM.dev에서 과제 목표·선수 개념 확인
→ 원본 과제의 버전·시작 브랜치·고정 commit·AI 제공 범위 확인
→ 승인된 로컬 과제 또는 별도로 공개된 묶음 확보
→ 개념별 또는 종합 독립 시작점에서 같은 루트 README 읽기
→ 사용자 풀이를 보존하며 목표 TODO 구현·기록
→ 그 버전의 공개 로컬 검증과 수동 확인 수행
→ 자신의 결과 설명·승인된 비교 자료 확인
→ BAM.dev에서 별도 로컬 완료·회고 기록
```

원격 공개·clone은 선택 과제의 전달 방식으로 확정됐을 때 안내한다. 이미 있는 로컬 과제에 원격 저장소 생성을 강제하지 않는다. 비교 자료의 존재·공개 범위도 원본별로 확인하며 미제공 정답이나 solution commit을 생성했다고 가정하지 않는다.

## 권장 최소 저장소 모델

`[대체됨]` 하나의 `bam-dev-assignments` 중앙 저장소에 네 트랙과 일률적인 `starter/<track>/<id>`·`solution/<track>/<id>` 브랜치를 만든다는 과거 제안은 `DEC-WEB-SOURCE-01`의 원본 활용 방식으로 대체한다. 과거 제안대로 새 저장소나 브랜치를 만드는 것은 현재 gate가 아니다.

원본의 한 과제 프로젝트·한 Git 저장소와 개념별/종합 **독립 시작 브랜치**를 유지한다. 브랜치를 바꾸면 같은 루트 README가 해당 목표·TODO·기반 구현과 시작 방법을 설명한다. 시작 버전·commit과 AI가 제공한 범위는 고정하며 이동 가능한 branch 이름만으로 재현성을 주장하지 않는다. 원본과 학습자의 진행 중 풀이·과거 버전을 덮어쓰거나 과거 풀이를 새 starter/정답으로 재구성하지 않는다. 원격 연결·공개는 별도 승인된 범위만 사용한다.

## 과제 메타데이터 계약

`[확정 결정]` 첫 과제의 별도 컬렉션·필수 필드는 [콘텐츠 스키마](../content-schema.md#외부-git-웹과제)를 따른다. 기존 인앱 Web Project JSON에 외부 폴더를 넣지 않는다.

- BAM 안정 ID·revision, 제목·목표와 실제 선수 교안/개념 연결
- 원본 과제 식별자·버전·전달 위치, 선택한 시작 브랜치·고정 commit·루트 README
- 수정할 목표 TODO·기반 구현·허용 파일과 AI 제공 범위
- 필요한 도구·버전·공개 검증 명령·수동 확인·오프라인 준비 조건
- 별도로 승인된 비교 자료·공개 범위와 로컬 완료/회고 연결

원본에 없는 저장소 URL·solution branch·검증 결과를 채워 넣지 않는다. 사용자 풀이·비공개 기록·로컬 절대 경로를 제품의 공개 데이터에 그대로 노출하지 않는다.

## 첫 원본의 고정 시작과 전달

`[확정 결정]` 첫 대상은 `study-meetup-20260910-pin` / `v1`, BAM ID `web-assignment-study-meetup-pin` / revision `1`이다. 시작 기준은 최초 AI starter commit `313b5be982bdc2296326cbed5319733fad5b05fe`의 19개 Git blob이며 현재 작업트리나 이동하는 branch HEAD를 사용하지 않는다. ‘원본 v1 종합 과제’로 표시하고 후대의 개념별 브랜치·선구현 운영 규칙을 소급 적용하지 않는다. 사용자와 AI가 함께 작성한 후속 풀이·dirty 파일은 제외한다.

별도 컬렉션과 함께 `content/web-assignments/assets/study-meetup-pin-v1-313b5be.zip`을 정적으로 제공한다. ZIP의 `study-meetup-pin-v1/` 아래 정확한 19파일 원문과 실행파일 mode를 보존하고 파일별 SHA-256 manifest를 제공한다. `.git`·사용자 풀이·부모 provenance/ERD·개인 위키·빌드/캐시는 포함하지 않는다. README·hints·소스·설정·공개 verify를 고정 blob 그대로 담고 정답·저장소 URL·solution branch를 생성하지 않는다. ZIP에 `.git`이 없으므로 압축해제 폴더의 HEAD가 sourceCommit이라고 안내하지 않는다.

네이티브 ‘고정 시작 자료 받기’ download 링크 → 사용자가 기존 풀이와 다른 새 폴더에 압축해제 → 같은 루트 `README.md` 읽기 순서다. BAM은 사용자 로컬 경로에 접근하거나 명령을 실행하지 않는다. 사용자의 새 `git init`은 선택이며 원격 clone은 필요 없다. 원격 게시 승인을 뜻하지 않는다.

원문 README의 `hints.md`는 포함한다. `../provenance.md`와 `../01-erd/README.md`는 제외되는 선택적 상위 참조이므로 상세 시작 안내에 다음을 명시한다. **“이 묶음은 웹과제 19파일만 제공합니다. README 마지막의 원본 출처·ERD 참조는 포함되지 않으며, 필수 요구사항과 hints.md는 묶음 안에서 읽을 수 있습니다.”** 모든 원문 링크의 정상 작동을 주장하지 않는다. 원문 수정이 필요하면 별도 파생 revision으로 출처·사유를 남긴다.

## 첫 과제의 연결과 기록

기존 `#/web-projects` 목록의 인앱 과제를 보존하고 ‘외부 Git 과제’ 구역에 첫 카드를 추가한다. 별도 상세 `#/web-assignments/web-assignment-study-meetup-pin`은 목표·외부 실행 상태 → 선수 문서 → 고정 자료/README → 환경·공개 검증·오프라인 → 내 진행 기록 순서다. 기존 홈·사이드바 진입을 사용하며 원문 교안을 새로 복제하지 않는다.

선수는 실제 여섯 교안 `java-concept-objects`, `algo-list-conditions`, `spring-boot-start`, `spring-mvc-flow`, `spring-request-mapping`, `spring-request-parameters`다. 대응 concept ID는 스키마에 둔다. Thymeleaf 조건식·`th:text`·반복·Model 연결은 **외부 선행학습 필요**로 표시한다. BAM에 전용 교안이 있다고 가정하거나 이번 연결을 이유로 교안을 자동 작성하지 않는다.

환경은 원본의 JDK 21·Spring Boot 4.1.1·Gradle wrapper 9.7.1·dependency-management 1.1.7·Python 3을 안내한다. 이는 원본값이며 현재 호환·설치 PASS가 아니다. BAM Java 25 runner 계약과 구분한다. ZIP에는 wrapper/의존성 캐시가 없으므로 최초 다운로드 없이 완전 오프라인 시작이 가능하다고 표시하지 않는다. 사전 준비 뒤 오프라인 빌드·시작·검증은 별도 실측한다.

원문 공개 명령은 `python3 verify.py`, 기본 대상은 `http://localhost:8086`이다. 검증은 상태를 변경하고 성공 때 전체 고정을 해제하며 실패 때 일부 상태가 남아 재시작이 필요할 수 있음을 안내한다. 대상 과제 서버임을 확인한 뒤 실행하고 임의 외부 주소·다른 포트 소유자에 요청하지 않는다. BAM의 자동 채점 기능이나 내장 Spring 서버로 제공하지 않는다. 제품에는 ‘이 버전 실행·오프라인 재검증 대기’를 표시하며 개발 호스트의 재시작 시간은 작업 카드에만 둔다.

별도 `bam.dev.web-assignments.v1` 저장소에 ID별 revision·`not-started`/`in-progress`/`self-reported-complete`·회고·갱신 시각을 저장한다. ‘내 진행 기록’·‘직접 완료 표시’는 자가보고이며 공개 검증 PASS·정답률·자동 채점 완료로 바꾸지 않는다. 제품 버전의 검증 대기와 사용자 진행을 별개로 표시한다. 기존 progress/Web Project 기록은 읽기·쓰기·자동이관하지 않는다. 키보드로 링크·펼침·폼에 접근하고 label·focus·저장 오류를 확인하며, 이동·새로고침에서 저장 상태를 알리고 저장 실패 때 회고 입력을 보존한다. 승인 검증 대상은 데스크톱 웹이고 전면 모바일 작업은 추가하지 않는다.

## 트랙별 과제 계약

다음은 선택한 원본의 학습 목표를 검토할 때 참고하는 기존 설계안이다. 네 트랙의 신규 과제를 따로 제작하거나 이미 완료했다고 선언하는 목록이 아니다. 실제 원본의 목표·지원 범위를 임의로 재작성하지 않는다.

### HTML

- `brief/article.md`처럼 한 주제의 내용과 정보 관계를 제공한다.
- 학습자는 내용을 복사해 붙이는 것이 아니라 제목·구역·목록·링크·폼 등 의미에 맞는 HTML 구조를 선택한다.
- CSS와 JavaScript가 없어도 문서 순서와 레이블이 이해되어야 한다.
- 검증은 문법 전체를 보증한다고 과장하지 않고 선언한 의미 구조·접근성 체크와 사람 검토를 분리한다.

### CSS

- 승인된 HTML 뼈대를 고정하고 학습자는 CSS 파일을 작성한다.
- 교안에서 배운 선택자, cascade, box model, Flex, Grid, 반응형, 초점 표시를 실제 화면에 조합한다.
- 특정 픽셀 복제보다 좁은 화면·키보드·내용 증가에서 유지되는 동작을 완료 조건으로 둔다.
- HTML 뼈대를 임의 변경해야만 통과하는 요구는 CSS 과제와 분리한다.

### JavaScript

- 기본 HTML·CSS와 로컬 fixture를 제공하고 외부 API 없이 동작하게 한다.
- 댓글 등록·조회·수정·삭제, 게시물 좋아요처럼 요구사항을 독립 단계로 나눈다.
- 각 단계는 상태 원본, 이벤트, DOM 반영, 빈 값·중복 클릭·새로고침 같은 경계를 명시한다.
- 서버가 없는 과제에서 원격 저장을 약속하지 않는다. 영속성이 필요하면 `localStorage` 또는 메모리 경계를 요구사항에 명시한다.
- 정답은 한 번에 큰 완성 commit이 아니라 요구사항별 작은 commit으로 비교할 수 있게 한다.

### Java

- `[확정 결정]` 원본이 제공하는 시작 상태와 요구사항에서 구현하고 공개된 근거로 결과를 설명한다. 정답 비교 자료는 그 과제의 승인된 범위에 한한다.
- `[확인 필요]` 선정한 첫 Spring 종합 과제와 별개로 순수 Java 콘솔·도메인 실습을 추가할지와 순서는 후속 범위다.
- `[제안]` 댓글·좋아요 도메인을 새로 제작한다는 과거 초안보다 선정한 밤위키 원본의 목표·파일·검증 계약을 먼저 확인한다.
- 원본이 사용하는 JDK·빌드 도구·공개 검증과 오프라인 준비를 과제별로 확인한다. 확인된 외부 후보의 Java 21 안내는 BAM 앱의 Java 25 runner 계약 변경 승인이 아니며, 이 문서 작업에서 원본 버전을 수정하거나 호환 검증하지 않는다.

### Spring Boot

- `[확정 결정]` 교안은 BAM.dev 앱 안의 정적 콘텐츠로 제공하고 실제 Spring Boot 프로젝트 실행은 외부 웹과제 폴더에서 시작한다. 앱 본체나 Java 코딩테스트 runner에 Spring Boot를 포함하지 않는다.
- `[현재 사실]` Spring 정적 교안·객관식은 제공한다. 첫 외부 원본의 BAM ID·고정 버전·연결 계약은 위에 정했고 실제 공개 실행·오프라인 검증은 대기한다.
- `[확인 필요]` 설치형 MVP의 차단 묶음·Code Quest 여부는 `DEC-JAVA-01`, 선정 원본의 BAM ID·시작 버전·전달/공개·빌드/검증 연결은 `DEC-WEB-REPO-01`, 의존성과 오프라인 준비는 `DEC-WEB-OFFLINE-01`에서 정한다.
- 과제에 로컬 HTTP 실행이 필요해도 학습자가 외부 폴더에서 시작·종료하며 BAM.dev 앱의 상시 서버나 Java 코딩테스트 runner로 취급하지 않는다.

## BAM.dev 웹과제 페이지

첫 페이지는 위 [연결·기록 계약](#첫-과제의-연결과-기록)을 따른다. 후속 과제도 선정 원본의 목표·선수·시작 상태·허용 파일·실제 공개 검증·사전 다운로드를 안내하고 승인된 비교 자료만 제공한다. 원본 과제 화면을 새로 제작하거나 사용자 풀이를 자동 읽지 않는다.

BAM.dev는 GitHub API로 브랜치나 사용자 로컬 Git 상태를 자동 판정하지 않는다. 외부 명령을 자동 실행하지 않고 과제별 안내와 실제 검증 상태를 구분한다. 화면·저장 구현과 독립 검증은 [작업 카드](../work-items/2026-09-15-web-assignment-study-meetup-pin.md)의 후속 receipt로 판정한다.

## 검증과 인계

외부 과제 연결은 원본과 BAM 양쪽의 증거가 필요하다.

1. 원본: 선택한 버전·시작 commit·브랜치와 루트 README, 목표 TODO/기반 구현·AI 제공 범위·허용 파일을 확인한다. 공개 검증과 비교 자료가 실제 제공 범위에 일치하는지 독립 확인한다.
2. BAM: 안정 ID·선수 개념·문서·전달 위치·commit·실행/오프라인 안내가 원본과 일치하는지 확인한다. 기존 과제·사용자 기록은 보존한다.

`content_validator`는 교육 목표·지원·정답 누출과 설명을, `test_engineer`는 선정된 시작점에서 실제 공개 검증·오프라인 절차를, `project_integrator`는 원본과 BAM의 고정 참조·연결·독립 증거를 확인한다. 콘텐츠 작성자는 자신의 결과를 최종 승인하지 않는다. 원본을 실제 실행하거나 검증하지 않은 문서 조사 결과를 과제 PASS로 사용하지 않는다.

## 완료 조건

- 선택한 원본 버전·시작 commit에서 README만 따라 해당 목표로 시작할 수 있다.
- 목표 TODO와 AI가 제공한 기반 구현이 구분되며 사용자 풀이·과거 버전이 보존된다.
- 실제 공개 검증과 수동 확인이 관찰 가능한 요구사항에 대응하고 독립 검증을 통과한다.
- 필요한 도구·자산·의존성과 사전 다운로드 이후 오프라인 경계가 확인된다.
- BAM 안정 ID·선수 연결·시작점·안내·별도 완료/회고가 실제 원본과 일치한다.
- 원격 공개·비교 자료는 허용된 범위만 제공하며 기존 인앱 Web Project를 자동 삭제하지 않는다.

## bam의 결정이 필요한 항목

- 첫 과제 이후 추가할 원본·버전과 원격 공개 범위
- 미제공 비교 자료의 작성/공개와 설치형 배포 묶음
- 실제 검증 뒤 남은 도구·의존성 사전 제공 범위
- 검증된 대체 흐름 이후 기존 인앱 Web Project의 병행·이관·종료 여부

첫 원본 선정·연결 계약은 위에 확정했다. 실제 반입·제품 연결·공개 검증 receipt 전에 제공 완료를 선언하지 않는다. SQL/ERD·Excalidraw/PNG·사용자 풀이 반입과 밤위키 자동운영 설정 변경은 이번 범위 밖이다.

결정 ID와 구현 순서는 [`../roadmap.md`](../roadmap.md)가 담당한다.
