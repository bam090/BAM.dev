# 전체 화면 서비스 사이드바 통일

## 범위와 기준선

- 유형: 일반 제품 기능·코드. bam의 2026-09-14 전체 적용 요청에 따라 학습문서·객관식의 236px 사이드바를 모든 앱 route에 재사용한다. 학습 콘텐츠·평가·진도 계약 변경은 없다.
- 정본: [전체 화면의 서비스 사이드바 통일](../designs/visual-design.md#전체-화면의-서비스-사이드바-통일). 브랜드·검색·서비스 이동·단일 서비스 현재 표시·최근 문서·하단 theme을 일관되게 제공하며 제품 본문과 유효한 기존 링크를 보존한다.
- 기존 dirty 변경과 직전 Quest 완료 상태를 기준선으로 보존한다. 문서 원문과 SHA-256은 `/tmp/bam-global-sidebar-docs-baseline/`에 보관했다. 제품 기준선과 route 조사 근거는 해당 담당 receipt에서 인계한다. root `README.md`는 수정하지 않는다.
- 모바일 추가 구현/검사, 콘텐츠·SQL·Java·설치 앱·React·서버·DB·계정·의존성·외부 전송·Git 게시·merge·배포는 제외한다.

## 소유권과 순서

| 역할 | 소유 경로·완료 인계 |
| --- | --- |
| 제품·설계 문서 담당 (Astra) | 이 카드, `docs/designs/visual-design.md` 사이드바 계약, `docs/architecture.md` 최소 상태, `docs/README.md`·`docs/roadmap.md` 관련 안내만. 선행 계약과 receipt 기반 상태 반영 |
| 읽기 전용 조사 담당 | 모든 route·legacy 유효 링크·최소 코드 영향 receipt |
| 제품 구현자 (Sol xhigh) | 총괄이 조사 후 지정한 앱·UI·스타일. 구현과 기존 focused 검사, 테스트 작성 금지 |
| 별도 테스트 작성자 | 총괄이 지정한 영향 테스트. 독립 기대값과 focused 검사 |
| 독립 test_engineer | 쓰기 없이 focused·대표 데스크톱·상태/링크 보존 판정 |
| 독립 문서 검토자 | 쓰기 없이 정본·카드 diff·링크·상태·범위 충돌 판정 |
| 독립 project_integrator | 쓰기 없이 PASS receipt·전체 diff·기준선 보존·경로 소유권·미검증 연결 판정 |

총괄은 파일을 수정하지 않는다. 같은 경로는 선행 인계 후 순차 소유하며 상세 파일·hash·실행 조건은 담당 receipt에 둔다.

## 완료 조건과 검사 경계

조사 receipt의 기준선은 홈·학습문서·객관식·Quest 목록·내 학습 기록이 서비스 shell을 사용하고 Quest 상세·코딩테스트 목록/상세·Web Project 목록/상세는 legacy shell을 사용한다. 이번에 후자의 shell을 통일하며 기존 로딩·빈 결과·오류 및 fallback 화면도 같은 탐색에서 벗어나지 않게 한다. 서비스 현재 값은 `home`·`learn`·`review`·`quest`·`coding-test`·`web-project`·`my-page`이며 내 학습 기록은 하단 현재 표시로 구분한다. 상세 breadcrumb·이전/다음·목록·관련 문서 등 본문 문맥 링크는 유지한다.

- 모든 앱 route에서 같은 236px 서비스 shell과 단일 현재 서비스 표시. 각 제품 본문·편집기·학습 문맥·기존 유효 링크 유지.
- 대표 데스크톱 밝게/어둡게·키보드 focus·검색·최근 문서·서비스 왕복과 가로 넘침 없음. 검색/theme만 조작하면 본문 DOM·풀이·편집·실행 상태가 유지된다.
- 기존 객관식 복귀와 Quest·코딩테스트·Web Project 초안/실행/내역·내 학습 기록 및 URL·ID·저장 키를 보존한다. 실제 서비스 이동에는 기존 실행 정리 계약을 적용한다.
- route 분류/현재 표시·메뉴 링크·검색/theme 무재렌더와 직접 영향 대표 흐름의 focused 및 데스크톱 증거를 선정한다. 이전 유효 PASS는 변경되지 않은 대상·의존 근거와 함께 재사용한다. 전체 검사·빌드를 자동 반복하지 않는다.
- 실행·재사용·미실행, 최초 실패·수정·재검증을 구분한다. 문서 결과만 갱신한 뒤에는 문서 diff·링크·정합성만 재검한다.

## 상태와 인계

`[현재 사실]` 제품 구현과 독립 `test_engineer` 검증은 PASS다. 최종 독립 문서 검토·`project_integrator` 통합도 PASS이며 사용자 재결정이 필요한 새 제품 정책은 없다.

| 증거 구분 | 실제 범위와 결과 |
| --- | --- |
| 독립 데스크톱 실행 | Chrome 1440×1000, 12개 route의 236px 공통 shell·서비스 메뉴 6개·정확한 현재 표시·가로 넘침 없음 PASS. 키보드·사이드바 스크롤과 console 오류 0 확인 |
| 상태 보존 실행 | Quest·코딩테스트·Web Project의 초안, 검색/theme 조작과 서비스 왕복 복원 PASS. Web Project 결과와 객관식 선택 보존 PASS |
| 독립 신규 focused | 새 테스트 3개 파일의 12/12 PASS. route·서비스 현재 상태·로딩/오류 shell 및 비동기 준비 후 문맥 보존의 변경 영향 확인 |
| 유효 증거 재사용 | 기존 review 32개·my 9개·theme 5개·Quest/코딩테스트/Web Project 45개 PASS. 담당 최종 receipt에서 제품 4개·테스트 3개 SHA가 최종 검증 상태와 일치함을 확인한 근거를 재사용 |
| 최초 실패와 반환 | 비동기 목록 준비 후 서비스 문맥이 잘못되는 FAIL을 제품 담당에게 반환. 문맥 보존 수정 뒤 영향 focused와 데스크톱 재검증 PASS. 최초 실패를 지우거나 초기 구현을 최종 PASS로 쓰지 않음 |
| 미실행 | 모바일, 전체 `npm run check`, 전체 테스트·빌드, 새 콘텐츠 재감사, 설치형 오프라인·SQL·Java 실행·React·서버/DB/계정·Git 게시·merge·배포. 이번 PASS의 범위가 아님 |

문서 상태 갱신은 위 총괄 인계와 담당 receipt를 근거로 했으며 제품 실행을 다시 수행하지 않았다. 최종 통합에서 제품 4개·테스트 3개·문서 5개 경로의 diff·소유권·기준선 보존을 확인했고 직전 Quest와 기존 dirty 13개 경로의 불변 근거 및 독립 실행·문서 PASS를 재사용했다. 추가 결함 없이 통합 PASS를 받았으며 이번 결과 기록 뒤에는 문서 상태 diff·링크만 확인한다.
